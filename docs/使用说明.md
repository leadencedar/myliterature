# 文墨 · 使用说明

> 一个 AI 小说创作工作台。从一句话点子长出可续写的知识库，再按章把小说写下去。
>
> **手机和电脑是同一个应用、同一个地址**：窄屏是底部 Tab 的移动端形态，宽屏自动换成左侧边栏的桌面形态。本文的操作说明两端通用，涉及差异的地方会标出来，桌面端专有内容集中在[第 4.1 节](#41-电脑上用)。
>
> 应用显示名为**文墨**，`MyLiterature` 是项目代号。
>
> 配套文档：[产品文档.md](./产品文档.md) · [设计方案.md](./设计方案.md) · [开发计划.md](./开发计划.md)

## 1. 开始之前

### 1.1 你需要准备什么

一个模型服务商的 API Key。应用不代理任何请求，**你的 Key 只保存在这台设备上，直接与服务商通信**。

推荐 DeepSeek：中文写作性价比高，低峰时段（北京时间 00:30–08:30）价格减半。也支持 OpenAI，以及任何 OpenAI 兼容的端点。

### 1.2 配置模型

打开「设置」（手机在底部 Tab 栏，电脑在左侧边栏）：

1. **服务商**：选 DeepSeek（接口地址与模型名会自动填好）
2. **API Key**：粘贴你的 Key。旁边有「去申请 Key」直达服务商控制台
3. **常规模型**：用于正文写作、摘要、设定提取等大部分任务
4. **重点任务模型**：立项与大纲决定整本书的地基，会优先用这个。留空则与常规模型相同
5. 点 **「测试连接」**——会发一条极短的请求，费用可忽略。成功时能看到文字逐字出现，并汇报 token 用量与缓存命中情况

「模型分工」区列出了每个任务实际会用哪个模型、是否开思维链、温度多少。这些参数已按任务预设，不需要手动调。

下面的 **「写作辅助」** 控制标记完成后的自动化：

- **完成后自动生成本章摘要与设定**（默认开）：后台生成章节摘要、全书进展与知识库更新（都是待确认提案，不自动落库），不弹窗、可以继续写
- **同时提取知识库条目**（默认开）：关掉后只生成摘要与进展，不产生人物/设定条目提案
- 每章大约一次结构化调用；摘要与进展必须生成，条目可以关

### 1.3 安装到桌面或主屏

**手机**：浏览器菜单里选「添加到主屏幕」。之后以独立窗口全屏打开，图标名为「文墨」。

**电脑**：Chrome / Edge 地址栏右侧会出现安装图标（或在菜单里找「安装文墨」）。装好后是一个独立窗口，没有浏览器地址栏，和原生应用一样可以放进 Dock / 任务栏。

> 当前版本**没有注册 Service Worker**，所以离线状态下打不开。这一项留给后续版本。

### 1.4 关于你的数据

- 所有作品数据存在**这台设备的浏览器**里（IndexedDB），不上传任何服务器
- 清除浏览器数据、换手机、隐私模式清理，都会一次性带走它们
- **所以请定期备份**（见 [第 8 节](#8-导出与备份)）。攒够一定字数后，书架顶部会主动提醒你
- 备份文件**不含 API Key**，可以安心丢进网盘

> 共用设备时，用完建议点设置页的「清除密钥」。

## 2. 五分钟上手：从一句话到第一章

### 第 1 步 · 新建作品

「书架」Tab → 右上角 **+**。只有书名是必填的。

顶部先选从哪里开始：

- **从一句话** —— 还没动笔。下面接着走
- **导入已有稿件** —— 已经写了一些，跳到[第 3 节](#3-已经写了很多导入旧稿)

「我想讲一个什么故事」这一栏会作为后续生成的锚点，写具体一点效果明显更好：

- ❌ 一个关于成长的故事
- ✅ 一个失忆的剑客发现自己就是三年前灭门案的凶手

创建后自动成为「当前作品」，其余 Tab 都针对它。

### 第 2 步 · 一句话立项

「知识库」Tab。知识库为空时，「从一句话开始」会直接展开：

1. 确认或修改「我想讲一个什么故事」
2. 选 **篇幅**：短篇（1–3 万字）/ 中篇（10–30 万字）/ 长篇（50 万字以上）——它决定大纲的颗粒度
3. 可填「额外要求」，比如「主角不要金手指」「结局要留白」
4. 点 **「生成世界观与大纲」**

稍等之后会得到一批**待确认项**：世界观设定若干条、主要人物若干位、一份全书大纲。

> 篇幅选「长篇」时，AI 只会细化前两卷的章节，后续各卷只给卷级梗概——长篇的后段应当随剧情生长，过早细化只会被推翻。

### 第 3 步 · 确认与修改

每条待确认项可以展开，逐字段查看和**直接编辑**。操作有三种：

- **采用这条** — 单条写入
- **忽略这条** — 本次不要（可以点「恢复」撤回）
- 底部 **「全部采用（N）」** — 把没被忽略的全部写入

大纲是一条特殊的待确认项：内容是一段缩进文本（`#` 表示卷，`##` 表示章，标题下一行写梗概），可以像改 Markdown 列表一样直接调整层级和顺序。

### 第 4 步 · 设定风格档案

还在「知识库」Tab，找到「风格档案」，点「调整」。三个维度：

- **文体取向**：网络文学 / 严肃文学 / 类型文学，选定后可再选子类（仙侠、悬疑、推理…）
- **创作方法论**：网文节奏结构 / 三幕式 / 雪花法 / 英雄之旅 / 起承转合·章回体。它决定大纲怎么组织
- **名家风格参考**：可多选并分别调强度（略带一点 / 适度借鉴 / 明显偏向 / 强烈贴近）。收录鲁迅、张爱玲、老舍、沈从文、曹雪芹、金庸、古龙、海明威、契诃夫、卡夫卡、马尔克斯

也可以在「示例文本」里贴一段自己或喜欢的文字，让 AI 提炼成自定义文风档案（同样要确认才生效）。

> 从旧稿导入的作品有条更省事的路：导入流程会自动从你的稿子里归纳文风与文体取向，交给你确认。见 [第 3 节 步骤六 · 确认](#步骤六--确认)。

> 档案里存的是「句式节奏 / 意象偏好 / 叙述距离 / 对话风格 / 修辞习惯 / 词汇色彩 / 需要避免」这些特征描述，不是原文片段。AI 被要求据此把握语感，而不是模仿任何具体作品的文句。

### 第 5 步 · 写第一章

「写作」Tab → 在大纲树里点一个**章级节点**（没有子节点的叶子）→ 抽屉里点 **「写这一章」**。

进入全屏编辑器。你可以直接开始写，也可以点底部 **「生成本章」**：

1. 先看 **「本次注入」** 清单——这一次会把哪些设定、哪几章摘要、上一章的结尾原文交给模型，每项都标了 token 数，顶部给出总量。超出预算被丢掉的项也会明确列出
2. **「参与写作的设定」** 已经自动勾好了，点标签可以增减。标了「核心设定」的始终注入、不能在这里取消（要改就去知识库改标记）
3. **「带上前几章摘要」** 选带几章；**「本章额外要求」** 填这一次的具体要求
4. 点 **「开始生成」**，正文会流式出现
5. 结果可以直接在「生成结果」框里改
6. 满意后 **「采用」** 或 **「追加到正文末尾」**

选中正文里的一段，点底部 **「加工这一段」**，可以做 **续写 / 改写 / 扩写**，还能临时指定一次性的文风要求。改错了点标题栏的「撤销 AI 改动」。

### 第 6 步 · 标记完成，生成章节摘要与设定

写完点标题栏右侧的 **「草稿」** 切成 **「已完成」**。后台会自动生成本章摘要与设定，编辑器里只出现一条状态行：

- 「正在生成本章摘要与设定…（后台运行，可继续编辑）」——不弹窗，可以继续写或退出
- 完成后变成「本章摘要与设定已生成：摘要 + N 条知识库更新待确认」+「查看」；点「查看」在一个收件箱里统一确认
- 摘要包含本章摘要、关键事件、出场人物、**截至本章仍未收束的伏笔**、更新后的全书进展

知识库条目会按 3–5 章一个批次归组，每章最多 3 条实质变化，新登场人物单独即时提案；同一章重复标记完成不会重复出提案。**不会自动落库，也不会自动改大纲状态**——都要你确认。

收件箱里对**已有知识条目的合并/替换**默认标为「已标记为忽略」，不会被「采用本批」写入（摘要与进展仍默认选中）；要改旧条目，展开那条点「恢复」再采用。收件箱顶部还会按章显示本章伏笔的「新埋 / 收束 / 现存」，如果发现伏笔被误收束，在摘要的「未收束伏笔」里加回即可。

如果关掉了设置里的「完成后自动生成」，或者模型没配置，状态行会提示手动点标题栏的「摘要 / 补摘要」。已完成但没有摘要的章节，编辑器入口会高亮成「补摘要」。

> 这一步很重要——摘要是后续所有章节的上下文来源。跳过它，写到后面就会出现「AI 越写越不记得前面的事」。

### 第 7 步 · 写下一章

回到「写作」Tab，点下一个大纲节点。这次生成时，前几章的摘要、关键事件、未收束伏笔、全书进展、上一章的结尾原文都会自动带上——你可以在「本次注入」清单里确认它们真的在。

## 3. 已经写了很多？导入旧稿

如果你手上已经有几万到几十万字，这条路是给你的 —— 不需要先编一句「我想讲一个什么故事」。

**两个入口，任选一个：**

- **新建作品时**：书架 → **+**（或空书架上的「导入已有稿件」）→ 顶部选 **「导入已有稿件」** → 填个书名 → **「创建并导入稿件」**。作品建好后会直接落在导入面板上
- **已有作品补导入**：「知识库」→ 滚到底部「管理」区 → **「导入旧稿」**

> 导入模式下不会问「我想讲一个什么故事」。那句话应该从你的稿子里反推出来，而不是让你现编一个。
>
> **外文稿也可以**：分章后会多出一个「翻译」步骤，把外文章节译成中文再继续。见[步骤三](#步骤三--翻译只有外文稿才会出现)。
>
> **不只是正文**：同一条路也能导入外传（番外、前传）和世界观设定（设定集、人物小传），在「导入到」里选。见[步骤四](#步骤四--导入到)。

### 步骤一 · 上传或粘贴

**推荐上传文件**：点「选择稿件文件」，或在电脑上直接把文件拖进虚线框。

| 项目       | 说明                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 支持格式   | `.txt` `.md` `.rtf`（以及 `.text` `.markdown`）                                                      |
| 编码       | 自动识别 **UTF-8** 与 **GB18030**（Windows 记事本的「ANSI」就是它），也认 UTF-16。识别结果会显示出来 |
| RTF        | Word 的富文本格式，读入时自动提取纯文本（新式 `\uN` 与老式 GBK 转义都能解）                          |
| 单文件上限 | 20 MB（约一千万字）                                                                                  |
| Word / PDF | 不支持。请在原软件里「另存为」纯文本（.txt）或 RTF 后再上传                                          |

**一章一个文件的话，按顺序一个个选**，每次会接在后面，界面上会列出已读入的文件与顺序。刻意不按文件名自动排序 —— 中文文件名的字典序会把「第十章」排到「第二章」前面，与其悄悄把一本书打乱，不如让顺序由你掌握。

也可以直接在下面的文本框里粘贴，两种方式可以混用。点「清空重来」可以全部倒掉。

> 如果提示「少量字符无法识别，已用 � 占位」，说明原文件里确实有坏字节。不影响导入，可以在下一步或写作页里改掉。

下一步才会写入作品，这一步只是暂存。

### 步骤二 · 分章

三种方式：

- **自动识别章节标题**（默认）：认「第一章」「第十回」「楔子」「序章」「尾声」「番外」「Chapter 3」这类独立成行的标题
- **整篇作为一章**：单章短篇，或想先粗略跑一遍看看效果
- **自定义正则**：标题格式特殊时用，按行匹配（例如 `^◇.+◇$`）

切分结果会逐章列出，你可以：

- 改章节标题
- **并入上一章**（切多了）
- **删除**（目录页、版权页之类的杂项）

如果切出大量极短章节，会出现提示——这通常意味着规则不对，比如把目录的每一行都切成了一章。

外文章节如果超过 6000 字，旁边会提示「这一章较长，翻译时会自动分段进行」。只是提示，不拦你；翻译时会按段落自动切段逐段译（见下一步），所以长章不需要手动切小 —— 想按剧情节奏切小才需要在这里调整。

确认无误后：

- **纯中文稿**：列表下面直接就是「导入到」（见[步骤四](#步骤四--导入到)），选好后点底部主按钮 —— 文案会随选择变成 **「写入主线 N 章」**、**「写入外传 N 章」** 或 **「提取为世界观设定」**
- **有外文章节**：主按钮是 **「下一步：翻译（M 章）」**，「导入到」要等译完再选

到这一步为止，什么都还没写进作品。

### 步骤三 · 翻译（只有外文稿才会出现）

如果分章后检测到**外文章节**，会多出这一步；纯中文稿完全看不到它，流程一步不多。

语种是**按章判定**的，所以「三章英文 + 一章中文」这种稿子，只有那三章会被勾上，中文那章标为「不译」。你可以自己取消勾选不想译的章节。

| 要点           | 说明                                                                                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 不会自动开始   | 翻译是整个流程里最贵的一步，必须你自己按「开始翻译」                                                                                                                                                                  |
| 长章自动分段   | 超过约 3000 字的章节按段落边界切成几段逐段翻译，全部成功再拼成整章。段落与段落之间的空行原样保留                                                                                                                      |
| 段段都落地     | 每段译完立刻存盘：刷新、关面板、切后台都不丢已译好的段落，重开接着译                                                                                                                                                  |
| 失败只重试一段 | 某段失败会停下来，重试只重跑失败的那一段，已经成功的段落不重跑、不重复计费                                                                                                                                            |
| 原文留底       | 译文替换正文，原文自动存一份，随时可以回头核对原句                                                                                                                                                                    |
| 译名一致       | 同一个名字全书只用一个译法。第一章把 Ashford 译成「阿什福德」，后面章节会沿用，不会变成「艾许佛」；**同一章内分段翻译也一致**——前段定下的译名后段强制沿用。译名存在**作品**上，所以**以后再导入别的外文素材也会沿用** |
| 可暂停续跑     | 和提取一样，关掉面板也不丢进度，重开会回到这一步                                                                                                                                                                      |
| 失败可重试     | 某章失败会停下来，修好问题后单章重试                                                                                                                                                                                  |
| 截断不算译完   | 译文撞上模型的单次输出上限时，这一段（或这一章）会标为失败，正文仍是原文。半截译文不会被当成已译                                                                                                                      |

界面上会边译边显示译出的文字，以及累计的译名对照表。

> **成本提醒**：翻译按字数计费，大致相当于让 AI 重写一遍同样长度的文字 —— 这是导入流程里唯一一次大规模输出。译三章比译三十章便宜十倍，先拿一章试试效果再决定要不要全译。

译完后点 **「下一步：选择导入方式」**。还有没译或译失败的章节时，按钮是 **「跳过剩下的，选择导入方式」**：跳过的章节按原文进入下一步（写成章节后还能到编辑器里逐章「译成中文」），但如果拿去提取，知识库里会混英文原词。翻译进行中要先「暂停」，等当前这一段落盘后才能跳过。

失败的那一章（或那一段）直接点「重试」即可 —— 已经译好的段落不会再重跑。真正需要重新切小的场景已经很少了：只有某一段反复撞上输出上限时才需要考虑回分章页调整。

### 步骤四 · 导入到

这一步决定整批稿件去哪里。纯中文稿它就在分章页上；外文稿在译完之后单独出现，步骤条上显示为「导入到」。

| 选项                 | 结果                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| **主线章节**         | 接在主线之后编号，生成章节摘要与全书进展                                                                       |
| **外传**             | 归入一部外传，有自己的编号与摘要链，不计入主线进度。在「哪一部外传」里选已有的，或选「＋ 新建外传…」当场填名称 |
| **仅作为世界观设定** | 只提取人物与设定条目，不写成章节、不占编号、不出摘要与文风                                                     |

下面会告诉你编号从哪接：「主线已有 N 章，这一批从第 M 章接着编号，不会覆盖已有内容。」外传会写「外传·X 已有 k 章，从第 k+1 章接着编号」，新建外传从第 1 章开始。

> **为什么翻译之后才选**：世界观设定也可能是以故事的形式写的 —— 一段前史、一篇人物小传，看着和正文没两样。外文稿在翻译之前很难判断它该进主线、进外传还是只当设定参考，所以先译成中文，再看着译文决定。世界观设定因此也能翻译，译名同样记进作品的译名表。

几条要知道的：

- **整批只能选一个目的地**。正文和番外混在一个文件里时，导两次：第一次在分章页删掉番外章节，第二次只留番外
- **「顺便归纳这部作品的文风」在这里勾**。主线默认勾上，外传默认不勾（番外常换语气、样本也少，容易判错），世界观设定不提供。你手动改过之后，再切换目的地不会覆盖你的选择。它要多花一次调用，写入之后界面上不再提供开关
- **外传名称**：必填，最多 40 字，不能和已有外传重名（「外传·青冥旧事」和「青冥旧事」算同一个名字）
- **世界观设定需要先配置模型**，否则主按钮不可用
- 外文稿在这一步可以点 **「返回翻译」** 补译刚才跳过的章节，已译的不会重新付费

点主按钮后，章节和导入进度一次写进去，自动进入提取。写入失败（比如选中的外传刚在别处被删）时一章都不会写，改选后再点即可。

### 步骤五 · 逐章提取

写入后自动开始。界面显示「已提取 X / N 章」和每章状态。世界观设定按段提取：几个短章合成一段，超长章按段落再切，段名里带着章节标题。

- 可以随时 **「暂停」**（会停在当前这一章结束处）
- **可以直接关掉面板**。进度已经存盘，下次打开「导入旧稿」会直接回到这一步继续
- 某一章失败会停下来，不会把同一个错误重复几十遍。修好问题后点该章的 **「重试」**，或点 **「继续提取」**
- 实在跑不过的章节可以选 **「跳过失败章节，直接整理提案」**

每一章都会立刻生成一条章节摘要待确认项（外传章节的标签是「外传·X 第 N 章摘要」；世界观设定不出摘要）。设定条目不会逐章生成——它们会先在后台按名称累计合并。

### 步骤六 · 确认

全部跑完后进入「确认」步骤，这时才一次性生成条目待确认项：

- 库里没有的人物／设定 → **新建**
- 库里已有同名（或别名匹配上）的条目 → **合并**，展开能看到**字段级改动**：哪些是新增、哪些是被改写、原值是什么

合并规则是「只补不删」：列表字段取并集，模型没提到的字段保留原值，两边都有值且不同的会标成改动交给你裁决。

导入主线时还有一条全书进展摘要；导入外传时换成这部外传的「外传进展摘要」，主线的全书进展不会被动到。

如果在「导入到」里勾了「顺便归纳文风」，同一个收件箱里还会多出一条 **「文风与文体」**：

| 字段                                                                       | 说明                                                   |
| -------------------------------------------------------------------------- | ------------------------------------------------------ |
| 文体取向                                                                   | 下拉选择，网络文学 / 严肃文学 / 类型文学。判错了直接改 |
| 子类                                                                       | 如「都市」「推理」。判不出来会留空                     |
| 句式节奏 · 意象偏好 · 叙述距离 · 对话风格 · 修辞习惯 · 词汇色彩 · 需要避免 | 七段文字，就是「自定义文风」的七个维度，可以逐字改     |

采用后它们直接写进风格档案，之后每次生成都会带上。**创作方法论与名家风格参考不在里面** —— 前者是「接下来怎么规划大纲」的选择，不是稿子的属性；后者是「我想像谁」，不该由机器替你宣称。这两项要用的话去「知识库 → 风格档案 → 调整」自己选。

> 归纳依据是从稿件里自动挑的几段代表性片段：跳过过短的章（目录、卷标题那类），章数够时让出开篇（楔子的语感往往不代表全书），每段取中段而不是章首。
>
> 稿件篇幅太短、没配模型、或这次调用失败时会跳过，并在确认步骤里说明原因 —— 其余内容不受影响。

> 长列表默认全部折叠，方便扫读。逐条处理或直接「全部写入知识库」。

### 步骤七 · 继续导入下一批（可选）

确认步骤底部有 **「继续导入下一批素材」**。点它回到第一步，不用关掉面板再从「管理 → 导入旧稿」重新进一次 —— 一章一个文件、正文与番外分开存、或者先拿一章试水再导全书，这些情况一次导入都不够。

跨轮会沿用的东西：

- **译名表**。第一批把 Ashford 译成「阿什福德」，第二批照旧
- **已有设定条目**。第二批提到同一个人物会走「合并」而不是新建，不会出现两个同名条目
- **分章方式与自定义正则**。同一批素材的标题格式通常一致，不用每轮重选
- **上一批的目的地**。「导入到」会预选上一批选的那一项；上一批是新建的外传，这次预选的就是这部外传，不用再填名字。它要是中途被删了，就回到「新建外传」
- **「顺便归纳文风」的勾选状态**。它就在「导入到」里，每轮都看得见，想关随时关

提示会写明上一批去了哪里，比如「上一批 3 章外传·青冥旧事 已经处理完」；「导入到」里也会照常告诉你这一批从第几章接着编号。

> 上一批还没处理的待确认项**不会丢**。它们已经落库，会留在「知识库」页顶部的待确认区，什么时候处理都行。

### 步骤八 · 接着写

确认完成后，知识库有了设定、摘要链有了前情，直接去「写作」Tab 写下一章即可。

> 导入的作品没有大纲。「写作」Tab 会正常显示章节列表；大纲区可以点「按已有章节生成大纲」把已写的章 1:1 变成节点，也可以「添加第一个大纲节点」手动开始规划。
>
> 导入的字数**不会**算进当天的写作产出。

**想放弃这次导入**：翻译、导入到、提取这三步右上角都有垃圾桶图标。

- 还没选目的地时放弃：分章结果和已经译好的章节会被清空，需要重新粘贴；译名表存在作品上，不受影响。这时还没有写入任何章节
- 进入提取之后放弃：只清空提取进度，**已写入的章节正文会保留**（主线和外传都一样）

## 5. 知识库

### 5.1 条目

点右上角 **+** 新建，点条目进入编辑。每个条目有：

- **名称**
- **别名**（每行一个）：反向提取时靠它识别同一对象，写全能避免重复条目
- **一句话摘要**：注入 prompt 时优先用它，省 token
- **分类字段**：跟随所属分类的字段模板
- **核心设定**：勾上后每次生成都强制注入。通常只有真正的底层规则需要，1–2 条足够

顶部搜索框覆盖名称、别名、摘要与所有字段值。

删除是软删除，进「回收站」（管理区），可以恢复或彻底删除。某个推演的主角在推演还在时不能彻底删除，回收站里会标出「推演《X》的主角」。

**互动推演设置**（条目编辑里默认折叠，只对互动推演有影响，见 [6.7](#67-互动推演)）：

- **作用范围**：「通用」（默认）或「仅限推演」。仅限推演的条目只在勾选的推演里出现，可以给每个推演写一句登场条件（比如「主角进入青冥宗后才会遇到」），AI 会把它当成「可能登场」而不是一开始就在场。它在知识库里照常显示，带「限定 · 推演《X》」，但**不会进入正文写作、摘要、提取等任何其他任务**。想让它成为全书条目，改成「通用」即可
- **每个字段在世界线上**：跟随分类（显示默认是锁定还是可变）/ 锁定 / 可变。锁定的字段推演里永远不会被改写

### 5.2 分类

管理区 → **「分类管理」**。

内置两类：**世界观设定**（定义 / 运作规则 / 限制与代价 / 对剧情的影响）和 **人物**（身份 / 外貌 / 性格 / 目标与动机 / 软肋与恐惧 / 关系网 / 说话方式 / 成长弧线）。内置分类不能删除，但可以改名、增删字段。

可以新建自定义分类并自定义字段，也可以一键套用预置模板：**势力 / 地点 / 道具 / 伏笔 / 时间线**。

每个字段有一个 **「世界线可改写」** 开关，决定互动推演里这一栏能不能随剧情变。内置默认：世界观设定的定义、运作规则、限制与代价锁定；人物的性格、软肋与恐惧、说话方式锁定，身份、外貌、目标与动机、关系网、成长弧线可变；自定义字段默认可变。单个条目还可以逐字段覆盖（见上一节）。

> 字段的「给 AI 的提示」会进入 prompt，直接影响生成质量。它不是占位文案，而是「告诉模型这一栏该写什么」的指令。
>
> 分类下还有条目时不能删除，需要先移走或删掉条目。

### 5.3 译名表

管理区 → **「译名表」**。只有导入过外文素材的作品会用到它。

翻译外文章节时会**强制沿用**这里的译法，所以它决定了「同一个名字全书只有一个译名」。表存在作品上，跨章节、跨导入批次、单章补译都用同一份。

能做三件事：

- **改译名** —— 可以一次改多条，改完点「保存 N 处改动」。作者的决定会覆盖模型先前定下的译法
- **删译名** —— 删掉之后，下次翻译时模型会重新挑一个
- **提前添加** —— 在翻译之前就把关键人名定好。这样第一章就会照着译，不用等模型自己挑一个再沿用

> 改译名只影响**之后**翻译的章节。已经译好的正文不会自动跟着变 —— 需要的话去那一章点「重译」。

**译名不一致提示**

改了译名之后，之前译好的章节就落后了。译名表顶部会把这件事列出来：

```
1 条译名与已有译文不一致
下面这些章节的原文出现过对应专名，译文里却找不到现在登记的译法 ——
通常是改了译名之后没有重译。点章节名过去处理。

Ashford → 艾许佛   1 章未采用
[ 第 1 章 雪夜 ]
```

点章节名直接跳到那一章的编辑器，在那里点「重译」即可。表里对不上的那一行也会标上「译文不一致」，几百条译名时靠它定位。

三条边界要知道：

- 判断依据是**原文与译文对照** —— 某一章的原文出现过 `Ashford`，而译文里找不到「艾许佛」。这也能顺带发现模型当初压根没照译名表译的情况
- **只看翻译过的章节**。中文原创章节没有留底原文，即便里面写着旧译名也无从判定是不是同一个人
- **只提示，不替换**。同一个词可能出现在对话、称谓、复合地名里，机械地全文替换会出事；改不改、怎么改由你决定

### 5.4 重新立项

知识库已有内容时，「从一句话开始」会折叠成「重新立项」入口，用于换个方向重来。结果同样是待确认项，不会直接覆盖现有内容。

### 5.5 写作规范

知识库「风格档案」下面的 **「写作规范」** 区块。放的是你给这本书定下的规矩：时间截面（故事从原作哪个阶段开始、之后的人物与装备一律冻结）、与原作的差异及后续影响、谁知道什么、命名与合并规则、哪些事不能写。设定条目回答「这个世界能发生什么」，规范回答「这本书选择发生什么」，两者冲突时以规范为准。

**新建**

- **「新建」**：填标题，把整理好的规范粘贴进正文。保存时原样存下，一个字都不改
- **「从文件新建」**：选一个 `.txt` / `.md` / `.rtf` 文件，编码自动识别（RTF 自动提取纯文本），标题预填为文件名。读入后先打开编辑面板，**点「保存」才写进知识库**
- 编辑面板里的 **「上传文件追加」**：把另一个文件接在正文末尾（中间空一行）
- **「插入差异说明模板」**：给同人、改编准备的提示结构（原作版本、本作开场时期、分叉事件、明确改动的事实……）。正文为空时直接填入并把标题设为「本作差异说明」，否则接在末尾。模板里的字段都可以删改

单份规范最多 60000 字，超过的文件会被拒绝，可以拆成几份。

**作用范围**

每份规范可以选进入哪些任务，默认全开：

| 作用范围 | 覆盖                                                     |
| -------- | -------------------------------------------------------- |
| 写正文   | 整章生成、段落续写 / 改写 / 扩写                         |
| 规划     | 一句话立项、细化大纲                                     |
| 章节摘要 | 标记完成后的摘要与伏笔                                   |
| 提取设定 | 导入旧稿与世界观设定时的反向提取                         |
| 检查     | 章节编辑器里的「按规范检查」（见 [6.6](#66-按规范检查)） |
| 互动推演 | 推演每一步的情节与选项、收尾（见 [6.7](#67-互动推演)）   |

「互动推演」是后来加的。之前已有的规范，如果原来五项全开，会自动加上它；你收窄过作用范围的不会动。

翻译不带规范：翻译要忠实于原文，带上规范会让模型去「修正」原文。

一项都不选也可以，这份规范就不会进入任何提示词，列表里会写明。

**启用、排序、删除**

- 列表每行右侧的 **「启用」** 开关：停用的规范保留在列表里，但不会进入任何任务
- 上移 / 下移按钮决定多份规范在提示词里的先后
- 点标题打开编辑，面板底部 **「删除这份规范」**，确认后删除，不影响已经写好的章节

**token 提示**

规范每次都整份带上，所以列表和编辑面板会显示每份约多少 tokens：

- 单份超过约 2000 tokens 时标「较长」
- 启用中、作用于写正文的规范合计超过约 6000 tokens 时，区块顶部会提示
- 正文里链接超过 5 个时提示：来源表通常不必进提示词

**AI 精简**

打开一份已保存的规范，点 **「AI 精简」**，模型会把长文压成约束条目，去掉来源链接、核对说明这类不需要进提示词的内容。结果先显示为可编辑的预览，并对比原文与精简后的 token 数：

- **「另存为新规范（原文自动停用）」**：新建一份「标题（精简）」，排在原文之后、作用范围相同；原文停用但内容不变，随时可以切回去
- **「放弃」**：什么都不写

精简前要先保存手头的修改（有未保存修改时按钮不可用）。精简过程中关掉面板会取消，不写任何东西。

> **想让旧稿导入时的反向提取也遵守规范**（比如「阶段性称号不新增成人物」「组织不因名字相近合并」），先建好规范、勾上「提取设定」，再去导入。提取每章都会读取最新的规范。

## 6. 写作

### 6.1 大纲树

点节点打开抽屉，可编辑**标题 / 梗概 / 目标字数 / 状态**，并**关联知识条目**（写这一节点时默认注入这些设定）。

**AI 细化为子节点**：把一个卷或幕拆成若干章。可指定拆几个、加额外要求。额外要求**只影响这一次、不会保存**——要让它影响后续章节，请写进梗概。结果是待确认项。

细化会读知识库：面板下方列出「本次注入」，包括核心设定、手工关联的条目，以及从标题 / 梗概 / 额外要求里认出来的人物与设定；清单显示标题、来源（核心 / 手工关联 / 名字提到）与合计 token，完整字段会送进模型。认错的「名字提到」项可以点 × 临时移除（只影响这一次，不写库）。细化出的子节点是可直接开写的**场景卡**：谁要什么、什么在阻碍、转折点、结尾局面或认知变化，并要求至少一处选择由人物软肋或规则代价驱动。

节点已有子节点时，点「细化这一节点」会先告诉你：将替换 N 个子节点（含孙节点）、约 M 个已挂章节（W 个已有正文）会解除大纲关联；正文保留，之后可重新关联。旧细目会从大纲树删除；采用前可以在提案里对照原细目。取消就不发请求。细化前会先保存当前修改，避免拿旧梗概生成。

采用细化结果后，如果新子节点提到了知识库里已有的条目（或父节点本身有关联条目，会继承给新子节点），会弹出「确认自动关联」面板：默认全选，可以逐条取消；标签上会写「名字提到」或「继承」，命中别名时显示别名。两个按钮的后果：

- **确认关联（N 条）**：只写入勾选的条目（默认全选时即写入全部）；
- **全部跳过 / 关闭面板**：什么都不写。

写入的是节点的「关联设定」，不改父节点。取消过的条目，在**本次打开这个节点抽屉期间**不再建议；关掉抽屉再开或换会话会重新建议。

**自动大纲（两条不写正文的捷径）**：

- **导入作品 1:1 回溯**：大纲区还是空的时候，点 **「按已有章节生成大纲」**。每章生成一个顶层节点（标题=章节标题、梗概=该章摘要），预览里能看到章号、标题与「本章现有 N 字（仅参考，不设为目标）」。确认后一次性建节点并回填章节关联；**不改正文、编号与标题**，可以之后再手动分卷。重复点不会重复建；已关联大纲的章节会跳过。
- **前沿规划 3–5 章**：大纲区右上点 **「规划后续 3–5 章大纲」**。只生成大纲提案、不写正文。生成前可以看到「本次依据」（大纲尾部、全书进展、最近 3 章摘要、未收束伏笔），生成后先看「续写细目」——每章的标题、主冲突、章末钩子、将收束/将新埋伏笔，再决定是否采用；提案里的文本可以直接改。采用后才追加到大纲树（末卷下；没有分卷则顶层）。它不替你决定人物生死、感情或凶手，也不会自动收束伏笔。

**调整层级与顺序**：点节点右侧的把手，用按钮上移 / 下移 / 升级 / 降级。

> 用按钮而不是拖拽是有意的：移动端嵌套树拖拽很难瞄准，而且读屏用户完全用不了。

删除节点会级联删除整棵子树，但**章节正文不受影响**，只是解除与节点的关联。

### 6.2 章节编辑器

- **自动保存**：防抖落盘，标题栏实时显示「有改动 / 保存中 / 已保存」。返回时会立刻冲刷未落盘的改动，不等防抖
- **字数**：实时显示（不含空白字符，与国内平台计数惯例一致）
- **撤销 AI 改动**：只在有 AI 改动后出现。程序化修改会清掉浏览器原生撤销历史，所以这个撤销栈是单独维护的
- **草稿 / 已完成**：切到「已完成」会把这一章计入当日产出，并在后台生成摘要与知识库更新（非阻塞，见 [6.4](#64-摘要)）
- **删除本章**：需要二次确认，并会告诉你要删掉多少字

### 6.3 生成与加工

| 功能     | 入口                           | 说明                                                                                                                           |
| -------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 整章生成 | 底部「生成本章」               | 先看注入清单与目标字数，再生成；结果可编辑后「采用」或「追加到正文末尾」；截断/中断会标「生成未完成」                          |
| 译成中文 | 标题栏「译成中文」             | 只在这一章确实是外文时出现。译文可编辑后采用，原文自动留底，「撤销 AI 改动」可退回原稿。用的是作品级译名表，与批量翻译共用一份 |
| 段落续写 | 选中一段 →「加工这一段」→ 续写 | 在选区之后接着写                                                                                                               |
| 段落改写 | 同上 → 改写                    | 替换选中内容                                                                                                                   |
| 段落扩写 | 同上 → 扩写                    | 把选中内容写得更充分                                                                                                           |

「加工这一段」里还有两样东西**只影响这一次**，不会改动作品的风格档案：

- **临时换个笔法**：从名家列表里挑一位试试笔法，默认是「沿用当前文风」
- **额外要求**：比如「更冷一点，少用形容词」

没有选中任何内容时，「续写」会从正文末尾接着写。

**整章生成的目标字数**：来自大纲节点的「目标字数」，节点没填时按 3000 字。生成面板会显示这个值及来源（「大纲节点」或「默认 3000」），以及具体场景数参考（如「约 3–5 场」），要改请到「写作 → 大纲节点」里改。生成以梗概节拍为准：节拍不足时把一场写深，不会为了凑字数复述心理活动或堆景物。结果会同时显示「已生成 N 字 / 目标 M 字」；如果输出撞上模型上限被截断、或你中途点了停止，结果会明确标「生成未完成」，采用不完整内容前还会再确认一次。

采用不完整内容后，编辑器正文上方会保留一条会话内提示「本章由未完成生成稿采用，可能缺少结尾；补写后再标「已完成」」，点「知道了」可关闭；如果这一章原本是「已完成」，会自动退回「草稿」。补写完成后再手动标完成。

**写作规范可以临时取消**。作品里有作用于「写正文」的规范时，「生成本章」的注入清单会列出「写作规范 · 标题」和它的 token 数，清单下面还有一行「写作规范（本次带上 X / N 份）」，每份一个按钮；「加工这一段」里也有同样一行。点一下就是这次不带它，**只影响这一次**，不改知识库里的启用状态，下次打开面板又会全部带上。想长期不带，去知识库停用它或改作用范围。

> 写作规范不会因为预算紧张被自动挤掉 —— 那是你定下的约束。规范很长时，被挤掉的是后面勾选的设定，它们会出现在「因超出预算未注入」的提示里。

在外传章节里「生成本章」时，注入清单里会多一条「外传·X 说明」（外传名与简介，必定带上），前情只取同一部外传的摘要和上一章结尾。主线的全书进展默认**不**带：作品已有全书进展时，面板里会出现开关 **「参考主线进展」**，默认关闭 —— 外传发生在主线之后、需要知道主线走到哪时再打开；前传打开它，人物容易提前知道后来的事。这个开关每次打开面板都重新从关闭开始。

### 6.4 摘要与章节设定

标记完成后，后台会自动生成本章摘要与设定（摘要、全书进展、可选的知识库条目更新）。这些结果都是**待确认项**，编辑器状态行会提示「N 条待确认」+「查看」，不会自动落库，也不会自动改大纲状态。

- **查看**：点状态行里的「查看」，在一个收件箱里逐条或整批采用本批摘要与设定；关掉不写。对已有条目的合并/替换默认跳过，需要时点「恢复」；顶部按章列出伏笔「新埋/收束/现存」
- **批次**：知识库条目按 3–5 章归组，同名条目合并，每章最多 3 条实质变化；新登场人物单独即时提案
- **手动补摘要**：仍可点标题栏的「摘要 / 补摘要」重新提炼；如果本章已有待确认摘要，会提示「本章摘要与设定待确认」并替换旧的待确认摘要
- **继续补写**：生成结果偏短或截断时，结果区会提示「还有场景没落地？」；点「继续补写」只补本章尚未落地的场景，不自动循环，也不是凑字数

摘要产出两条待确认项：本章摘要、全书进展摘要。可以只采用其中一条。

> **全书进展摘要是整体替换，不是追加。** 它每次都会被写成完整独立的一段。

外传章节的摘要同样产出两条：本章摘要，以及这部外传的「外传进展摘要」（不是全书进展）。未收束伏笔只在同一部外传里承接，不会和主线的混在一起。

### 6.5 外传

主线之外的番外、前传、后传。在「写作」Tab 的 **「外传」** 区块里管理（没有外传时也会显示这个区块，写着「还没有外传」）。

| 操作          | 怎么做                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------- |
| 新建          | 区块右上角 **「新建外传」**，填「名称」（必填，最多 40 字，本书内不能重名）和「简介」（可选） |
| 写一章        | 外传卡片上的 **「写新一章」**，在这部外传里续一章并打开编辑器                                 |
| 继续写        | 点卡片下面的章节列表                                                                          |
| 改名 / 改简介 | 卡片右侧的「编辑外传《X》」图标。外传进展摘要在这里只读展示，要改只能走摘要的待确认项         |
| 删除          | 编辑抽屉里的 **「删除这部外传」**，二次确认后连同它的章节和摘要一起永久删除，无法恢复         |

**简介值得写清楚**：讲什么、发生在主线的什么时候（之前、同期还是之后）。写外传时它会交给模型，也用来推断默认勾选哪些设定。

每部外传各自从第 1 章编号，编辑器标题显示成「外传·青冥旧事 第 2 章」。外传章节和主线章节功能一样（生成、加工、译成中文、标记完成自动摘要），只是不关联大纲节点。

**计入与不计入**：

- 不计入：主线编号、主线摘要链与全书进展、写作页的「全书进度」；生成主线章节时也不会带上外传的任何内容
- 计入：书架的总字数（卡片上另显示「外传 K 章」）、备份提醒、写作计划的每日产出

旧稿里的番外也可以直接导成外传，见[第 3 节步骤四](#步骤四--导入到)。互动推演里不在主线上的线也可以沉淀成外传，见 [6.7](#67-互动推演)。

### 6.6 按规范检查

章节编辑器标题栏「摘要」前的 **「按规范检查」**，用作用范围含「检查」的写作规范（见 [5.5](#55-写作规范)）审读这一章，列出可能违反的地方。**只提示，不改正文**。主线和外传章节都能用。

入口在三种情况下不可用，点一下会显示原因：还没有作用范围含「检查」的规范、还没配置模型、本章还没有正文。

**开始检查**

1. 面板顶部「参与检查的规范」列出全部可用的规范，可以临时取消某几份（只影响这一次），至少要留一份
2. 下面一行写着本章字数和预计输入 token。超过 8000 字符的长章会分段检查，这里会写明「将分 K 段检查（K 次调用）」
3. 点 **「开始检查」**。进行中显示「正在检查第 i/K 段…」，可以点「停止」放弃这一次

检查会带上核心设定、本章提到的设定条目和同一条线上此前最近一份章节摘要，减少「人物早就见过面」这类误报。检查用的是编辑器里当前的正文，不必等自动保存。

任何一段失败（包括模型输出被截断），整次检查都算失败，面板会说明是第几段，不会只给你一半结果。被截断时可以减少作用范围含「检查」的规范，或先用 AI 精简把规范压短，再点「重新检查」。

**看结果**

每条结果是一张卡片：

- 严重程度：**明确违反** / **可能违反**（取决于前文没写明的信息）/ **需作者判断**（规范本身留有余地）
- 违反的是哪份规范（模型写的规范名对不上时标「规范名未对应」）、规范里的哪一条
- 正文原句、问题说明、修改建议

卡片上的三个按钮：

| 按钮       | 作用                                                                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定位       | 关闭面板，在正文里选中那段原句。接着点「加工这一段」就是处理这一段                                                                                                    |
| 按建议改写 | 选中原句并打开「加工这一段」，操作预选「改写」，额外要求预填「按写作规范《X》修改：建议」。之后和普通改写一样：先看预览，点「替换原文」才写入，「撤销 AI 改动」能退回 |
| 忽略       | 这一条不看了。标题栏的入口会变成「检查结果 N」，N 是还没忽略的条数                                                                                                    |

原句在正文里找不到时（模型改了字，或者你检查后改掉了那句），卡片会说明，「定位」和「按建议改写」不会动正文或选区。

一条都没有时显示「没有发现明显违反规范之处。这是模型的判断，仅供参考。」

**结果只保留在这次编辑里**：关掉面板再打开还在，离开编辑器或换一章就没了。检查后改过正文，面板顶部会提示「正文在检查后改过，结果可能已过期」。点结果下方的「重新检查」会先回到「开始检查」那一步：可以重新选参与检查的规范，也能看到按当前正文算出的分段数和预计输入 token，确认后再点「开始检查」。这时没开始就关掉面板，再打开仍是上一次的结果。

### 6.7 互动推演

把一个主角放进这本书的世界里，AI 写出他面对的处境和挑战，你替他做决定，AI 接着写后果和下一个挑战，直到走到结局。随时可以回到之前任何一步换个选择，开出另一条世界线，原来那条保留。玩出来的线可以沉淀成大纲或外传，再一章章写成正文。

入口在「写作」Tab 顶部的 **「互动推演」** 卡片：有推演时显示「继续《X》第 k 步」和「全部推演」，没有时显示「开始一局」。需要先在设置里配置模型。

**开始一局**

点「开始一局」，填：

| 项             | 说明                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 推演名称       | 必填，最多 40 字                                                                                                               |
| 主角           | 从「人物」里选一条已有条目，或当场新建（名称必填，身份 / 性格 / 目标与动机选填）。新建的主角会存成一条只属于这个推演的人物条目 |
| 起点           | 处境必填（最多 500 字），时间、地点选填                                                                                        |
| 结局目标       | 至少 1 个、最多 6 个，每个选好 / 坏 / 中性结局并写一句描述                                                                     |
| 里程碑         | 选填，最多 8 个，按顺序排（上移 / 下移按钮）                                                                                   |
| 基调、预计步数 | 选填。预计步数 5–200，默认 30，只是节奏参考                                                                                    |

保存后直接进推演页并开始写开局。开局之后，名称、目标、里程碑、基调和预计步数还能在「更多 → 开局设定」里改，只影响之后的步骤；**主角和起点不能改**，想换就新建一个推演。

**怎么选**

每一步上面是情节（边生成边显示），下面是挑战和 2–4 个选项。每个选项标着倾向（谨慎、果断、迂回……）和风险（按主角此刻看得见的危险标，不剧透结果）。点一个选项，AI 写下一步；生成中可以点「停止」，什么都不存，回到选择前。失败时会说明原因，点「重试」用同一个选择再来，不用重选。

选项都不合心意，就在下面的 **「或者，写下主角要做的事」** 里自己写（最多 200 字），点「这样做」（电脑上 `⌘/Ctrl + Enter`）。

**自由输入会被当成尝试**：AI 会判断这件事在这个世界里能不能做成。可行就写出成败与代价；违背底层设定（凭空获得能力、无视代价）就写主角试了、失败了、付出了什么，而不会让它成真。所以想让主角「突然会飞」，得到的多半是一次失败和它的后果。

**选过的不能再选**

回到某一步时，已经选过的选项标「已走过」、不能再点，旁边的「去这条线」会带你去那条线的最新一步。写下和这一步已走过的行动一样的话（忽略空白和句末标点），按钮不可用，提示「这个行动在这一步已经走过了」。只是很像时会提醒一句，按钮变成「仍然这样做」，你仍然可以继续。这一步走过的自由输入列在选项下面「这一步走过的其他行动」里。

选项都走过了可以点 **「再给几个选项」**，追加一批新的（每一步最多 8 个）。

**回退与世界线导航**

- **面包屑**（标题下的「开局 › 第 2 步 › … › 第 7 步」）：点任何一步就回到那里
- **底部「世界线」**：当前路径上每一步，以及从每一步分出去的其他线（「另一条线：选『…』· 已走 4 步 · 坏结局『…』」），可以「看分叉处」或「去这条线的最新一步」；下面还列出这个推演已到达的所有结局

回退、跳转、切换线都**不花钱**：只是换一步来看，不调用模型。从回到的那一步选一个没走过的选项，就开出一条新的世界线。

**主线是什么**

主线是你**最近一次推进**的那条线。只是回去看看旧线，主线不变；在旧线上走出新的一步，主线就切到那里。标题下的徽标会写「主线 · 第 k 步」，或「外传线 · 不在主线上」并给「回到主线最新一步」。沉淀时，主线上的步骤进主线大纲，其他线进外传。

**坏结局**

可以走到坏结局。结局会写明类型、标题和「起因」（哪个选择或哪种状态导致了它）。结局之后这条线不能再推进，但点「回到上一个挑战」或「从路径里选一步回去」就能重新选择。

**收尾**

不一定要等 AI 写出结局。在任何还没结束的一步点底部 **「收尾」**，可以选一个想要的结局目标（也可以不指定）、写一句说明，AI 会在这一步从当前状态自然地写出结局。走到预计步数之后，选项下面会提示「可以收尾了」，但什么时候结束由你决定。写出的结局和你选的目标不一致时会写明「你要的是 G1，这条线写出的是：…」。同一步只能收尾一次，之后按钮变成「查看已写的结局」。

**本线状态与编辑**

AI 每写一步，会顺带记下这条线上发生的变化：谁的身份变了、新出现了谁、谁死了或失踪了、主角受了什么伤拿到了什么、发生了哪些事。这些只记在这条世界线上，不会改知识库，另一条线也看不到。

底部 **「本线状态」** 分几块：

- **本线变化**：按步骤列出的变化，可以编辑或删除。新增一条改写时，字段下拉里只有可以被世界线改写的字段
- **有效设定**：这一步时各个条目的样子，改写过的字段同时显示本线的新值和世界观原值
- **主角状态**、**事件与标记**
- **前情摘要**：每 5 步一份，AI 整理，可以改

有些变化 AI 报告了却没记下（比如想改人物的性格），这一步正文下面会出现「这一步有 N 处变化没有记下」，点开看原因。改了前面某一步的变化后，后面的步骤会提示「生成时依据的是旧事实」，它们不会自动重写。

正文下方折叠的 **「本步依据 · 约 X tokens」** 列出下一步会带给 AI 的内容。其中标「（推断）」的相关设定可以取消勾选，之后几步就不带它；离开推演页后恢复全选。其余项是这条线的事实依据，不能取消。

**提升为世界观**

推演里的变化默认只属于这条线。想让某个变化成为全书设定，在「本线状态 → 有效设定」里点「提升为世界观」：

- 某个可变字段的改写 → 生成一条只改这一栏的条目修改
- 这条线上新出现的人物或事物 → 生成一条新建条目；知识库里已有同名条目时改为合并进它

生成的是待确认项，去知识库顶部确认后才写入。人物的死亡、失踪等处境，主角状态，事件和标记不能提升：某人在这条线上死了是这条线的剧情，要写进全书请沉淀成章节。

**沉淀成大纲 / 外传**

在想沉淀的那一步点 **「更多 → 沉淀这条线」**：

- 这一步**在主线上** → 沉淀为本书主线大纲，新的卷追加在大纲最后
- 这一步**不在主线上** → 沉淀为一部新外传（从和主线分叉的地方之后算起）；接着玩同一条外传线后再沉淀，默认追加到那部外传

面板先显示范围（第 a–b 步）和预估输入 tokens，点 **「生成大纲」** 才调用模型（用重点任务模型）。结果是一份可编辑的大纲：每章写着梗概、关键事件、出场人物和「对应步骤」。可以改标题、改梗概、合并或拆分章，「对应步骤」要首尾相接地覆盖整个范围，不然采用会失败并告诉你哪一章不对。确认前大纲树和外传列表都不会变。

再沉淀同一个推演时，只会沉淀还没沉淀过的那一段。主线换到别的线之后，原来沉淀进主线大纲的章节会标「来自旧主线」，推演页顶部也会提示，删不删、怎么改由你决定，正文不受影响。

**接着写这一章**

沉淀出来的章节和普通章节一样「生成本章」。注入清单里会多出几项：推演专属设定（主角档案等）、互动推演第 a–b 步原文、世界线状态，外传章节还有「分叉之前的经过」。它们都是本章的写作材料，必定带上。外传章节的细纲在编辑器的「本章细纲」里只读显示。段落加工不会带推演材料。

**删除推演**

「更多 → 删除」。全部步骤和分支会被永久删除；已沉淀的大纲、外传与章节保留，只是不再关联这个推演。复选框「同时把只属于这个推演的条目（含主角）移进回收站」默认勾上，回收站里可以恢复。

## 7. 计划

「计划」Tab → **「设定写作计划」**。

**三种模式**

| 模式      | 适合                                                   |
| --------- | ------------------------------------------------------ |
| 每日 N 章 | 最常见的连载节奏，章数比字数更能体现「今天推进了剧情」 |
| 每日 N 字 | 长章节或不按章推进的写法                               |
| 每周 N 章 | 按周结算，某天没写可以在周内补回来，压力更小           |

**其他设置**

- **写作日**（每日模式）：没选中的日子不计入进度，**也不会产生欠账**
- **开始日期**：之前的不统计，也不倒算欠账
- **启用计划**：暂时不想被催时关掉，历史记录会保留

**看板**

- **今日目标 / 本周目标**：完成量、还差多少、进度条
- **连续打卡 / 连续达成**：今天还没写**不会**让它归零——周期还没过完
- **累计欠账**：只回看最近一段时间。更早的追不回来，盯着一个一直变大的数字也没用
- **最近 7 天**：迷你柱状图，非写作日显示为半透明

**产出怎么记的**

在章节编辑器里保存时自动记录，不需要手动汇报。

- 只记**正向增量**：删字不会倒扣当天的产出
- 标记「已完成」记一章，来回切换不会重复计数
- 只改标题不会产生记录
- **导入的旧稿不计入**

## 8. 导出与备份

### 8.1 导出正文

「写作」Tab → 章节区右上角 **「导出」**。先用 **「范围」** 选导出方式：**「打包」** 在最前面，是每章一个文件、整本压成 zip；**单章 / 外传 / 全书** 是单文件导出，把一章或整本书导成一个文件。

**单文件导出**

- **范围**：全书 / 单章 / 外传（有外传时才出现，在「选择外传」里挑一部单独导出）
- **全书默认不含外传**。打开 **「附带外传」** 后，外传排在主线之后，每部一个「外传·X」标题
- **单章**：下拉框先列主线，再列各部外传的章节。外传单章的文件名形如 `书名 - 外传·X 第 N 章 标题.md`，不会和主线同号章节撞名
- **格式**：Markdown（书名与章节标题带 `#` 层级）/ 纯文本（无标记符号，适合直接贴进平台编辑器）
- **只导出已完成的章节**（全书与外传范围）：跳过草稿
- 面板里有预览和文件名，确认后 **「复制」** 到剪贴板或 **「下载文件」**

空章节会被跳过。单文件导出只有 Markdown 与纯文本两种格式；RTF 和 PDF 是文件型格式，只跟着「打包」走。

**打包导出：每章一个文件**

范围选 **「打包」**，再：

1. 按需要勾 **「只导出已完成的章节」** 与 **「附带外传」**（有外传时才出现）
2. **默认格式**：Markdown / 纯文本 / RTF / PDF 四选一，默认 **纯文本**。没单独改过的章都用它
3. **逐章改格式**：文件列表里每一行右边都有格式下拉框，改哪一行只影响那一章。改过任意一章后，会出现 **「全部改用默认格式」**，点一下清掉所有单独设置
4. 统计行是 **「共 N 个文件 · 约 M 字」**；有章被跳过时，同一行后面会加 **「另有 K 章未包含（草稿或空章节）」**
5. 点 **「下载压缩包」**，得到 **`<书名>.zip`**。打包中按钮显示「正在打包…」，成功后提示「已导出 `<书名>.zip`」

打包模式没有「复制」按钮 —— zip 没法复制到剪贴板。

**四种格式怎么选**

| 格式         | 适合什么                                                            |
| ------------ | ------------------------------------------------------------------- |
| **纯文本**   | 默认。没有标记符号，直接贴进平台编辑器或再存一份，最不容易出问题    |
| **Markdown** | 带 `#` 层级的书名与章节标题，适合投稿、排版工具，或以后还要再处理   |
| **RTF**      | 用 Word / WPS 直接打开，标题加粗居中、正文 1.5 倍行距，改批注也方便 |
| **PDF**      | 定稿存档、打印、发给编辑看。版式固定、有页码，但文字不能直接改      |

**zip 里长什么样**

```
归墟纪/
  第001章 离乡.txt
  第002章 山雨.md
  第003章 入城.pdf
  外传·青冥旧事/
    第001章 拜师.rtf
    第002章 故人.pdf
```

- 最外层是**书名文件夹**；主线章节直接放在里面，每部外传一个 **`外传·X`** 子文件夹。没填书名时叫「未命名作品」
- 文件名是 **`第001章 标题.扩展名`**。章号按这次导出的最大章号补零（至少三位，超过 999 章自动多一位），按文件名排序就是章序
- 标题为空时文件名只剩章号；标题里不能进文件名的字符（`\ / : * ? " < > |` 与换行）会被去掉
- **书名和章标题都有长度上限**：书名超过 40 个字符时会截断（zip 根文件夹名和下载文件名都用它，太长会超过解压器的名字上限）；章标题同样最多 40 字
- 扩展名跟着该章选的格式走，所以一个 zip 里可以四种格式混着放
- **会跳过什么**：空章节一律不导出；勾了「只导出已完成的章节」时草稿也跳过。两类都算进统计行的「另有 N 章未包含」
- 一章都导不出来时，面板显示「没有可导出的章节。」，按钮是灰的

**PDF 的限制**

PDF 用阅读器自带的字体，我们不把字体塞进文件里 —— 这样一章只有十几 KB。代价是超出 GBK 的生僻字（扩展区汉字）和 emoji 会显示成 **□**。列表里只要有 PDF 文件，面板就会提示：

> PDF 使用阅读器自带字体，超出 GBK 的生僻字与 emoji 会显示为 □；要原样保留请选 TXT/MD/RTF。

要一个字都不丢，就给这些章换成 **纯文本 / Markdown / RTF**。PDF 里显示成宋体还是黑体，也由你的阅读器决定。

### 8.2 全量备份

「设置」Tab → **「备份与恢复」** → **「导出备份文件」**。

得到一个 JSON 文件，带走**所有作品**的全部数据：作品信息、分类与字段模板、设定条目（含回收站里的）、大纲、章节正文（含翻译前的原文）、外传、互动推演（含全部分支）、章节摘要、风格档案、写作规范、译名表、待确认项、写作计划与每日产出。

旧版本导出的备份照常能恢复，里面的章节全部算作主线。

**文件不含 API Key**，可以安心存网盘。

导出后「上次备份」时间会更新，书架上的提醒横幅随之消失。

### 8.3 恢复

先选 **恢复方式**，再点「选择备份文件…」：

| 方式         | 行为                                                                                        | 用在什么时候                 |
| ------------ | ------------------------------------------------------------------------------------------- | ---------------------------- |
| **覆盖恢复** | 先清空这台设备上的全部作品，再写入备份内容                                                  | 换设备、清过浏览器数据后恢复 |
| **合并导入** | 保留现有作品，把备份内容并进来；id 相同的记录以备份为准；同一个互动推演整棵分支树以备份为准 | 把另一台设备的作品并过来     |

覆盖恢复会二次确认。**如果现有数据还没备份，请先导出一份。**

选错文件或文件损坏时会给出明确提示，不会写进库里。

## 9. 确认机制：AI 不会替你做决定

这是整个应用的第一原则：**所有 AI 产出必须经你确认才会写入**。

**待确认项出现在哪里**

- 在生成它的面板里（立项、摘要、大纲细化、导入收件箱）
- 关掉面板后，未处理的会出现在所属页面顶部的「待确认 N 项」区

同一批内容不会同时出现两个确认入口。

**你能做什么**

| 操作       | 说明                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| 展开       | 看全部字段。**新增**、**改动**会分别标记；合并类会显示原值                                                             |
| 直接编辑   | 任何字段都能改，写入的是你确认过的版本                                                                                 |
| 还原       | 把某个字段退回原值（合并类）                                                                                           |
| 采用这条   | 单条写入                                                                                                               |
| 忽略这条   | 本次不要，点「恢复」可撤回                                                                                             |
| 全部忽略   | 整批不要                                                                                                               |
| 底部主按钮 | 把没被忽略的全部写入。文案随场景变化（「全部采用（5）」「保存摘要（2）」「全部写入知识库（12）」），括号里是待写入条数 |

**例外有三类**：正文散文、AI 精简后的写作规范，以及互动推演里每一步的情节和记下的变化。三千字的整章做字段级 diff 不提供任何信息，所以正文走「可编辑预览 → 采用 / 追加 / 放弃」；精简结果走「可编辑预览 → 另存为新规范 / 放弃」，原文不被覆盖。你自己写、粘贴、上传的写作规范不是 AI 产出，直接保存。「按规范检查」只给提示、不写任何数据。推演每一步都是你自己做的选择，不满意就回退换一条；推演内容只留在推演里，要进入作品只有两条路，都要确认：「提升为世界观」生成条目待确认项，「沉淀这条线」生成大纲待确认项，之后写出的正文仍走可编辑预览。结构化数据一律走确认管道。

**如果某条写入失败**（比如要合并的条目已被删除），只有那一条会失败并留在待确认列表里，其余正常写入，界面会告诉你失败原因。

## 10. 省钱与提速

你用的是自己的 Key，所以这几条值得知道：

1. **低峰时段更便宜**。DeepSeek 在北京时间 00:30–08:30 价格减半。
2. **别把注入量开太大**。「本次注入」清单里勾的设定越多、带的摘要章数越多，每次生成越贵。而且上下文过长会稀释模型注意力，不一定写得更好。
3. **保持稳定前缀不变**。命中服务商的 prompt 缓存时，输入价格可能相差 50 倍。应用已经把稳定内容（系统提示 + 风格档案 + 写作规范 + 核心设定）严格放在前缀，但**频繁修改风格档案、写作规范或核心设定会让缓存失效**——改完第一次生成会贵一些，之后恢复。
4. **核心设定别标太多**。它们每次都强制注入。通常 1–2 条真正的底层规则就够。
5. **给条目写好「一句话摘要」**。注入时优先用摘要而不是全部字段。
6. **重点任务模型只用在该用的地方**。立项与大纲用它，其余任务自动走常规模型。想省钱可以把它留空（与常规模型相同）。
7. **导入旧稿是一次性的大开销**，按章计费。可以先用「整篇作为一章」或只导入前几章试跑，确认效果再全量导入。
8. **长规范先精简，作用范围按需收窄**。写作规范每次都整份带上，几千 tokens 的来源表会让之后每次生成、每章摘要、每章提取都多付一份钱。用「AI 精简」把它压成约束条目（原文保留并停用），或者把只适合事后审读的规范只勾「检查」，见 [5.5](#55-写作规范)。
9. **互动推演回退不花钱**。回到之前的步骤、切换世界线、打开本线状态都不调用模型，没选的分支也不会预先生成。「本步依据」里能看到下一步要带多少 tokens，推断出来的相关设定可以临时取消。

## 11. 常见问题

**Q：数据存在哪？会上传吗？**
存在这台设备的浏览器里，不上传任何服务器。只有模型请求会直接发给你配置的服务商。

**Q：换手机怎么迁移？**
旧设备「设置 → 导出备份文件」，新设备配置好 Key 后「选择备份文件…」+「覆盖恢复」。

**Q：API Key 安全吗？**
Key 只存在本地，出站连接被限制在已登记的服务商域名内，应用不引入任何第三方脚本。但纯前端应用无处安全保管密钥——同一网站的脚本理论上都能读取本地存储。这是「无后端」的代价，后续版本会转为服务端代理。共用设备请用完「清除密钥」。

**Q：可以不联网用吗？**
不能。当前版本没有注册 Service Worker，离线状态下应用打不开。数据本身存在本地，联网后照常可见。

**Q：手机和电脑是两个不同的应用吗？**
同一个。同一份代码、同一个地址，只是在宽屏上换了布局。所以功能完全一致，不存在「桌面版才有的功能」。

**Q：手机上写的内容，电脑上看不到。**
数据存在各自设备的浏览器里，不会自动同步。跨设备请用「设置 → 导出备份文件」，在另一台设备上「选择备份文件…」恢复。账号与云同步是后续版本的事。

**Q：电脑上窗口拖窄了界面变样了。**
是预期行为。窗口窄到一定宽度会切回移动端形态（底部 Tab、单列），拖宽会自动切回来，不需要刷新。

**Q：AI 写的不像我的风格。**
先检查风格档案：文体取向、名家风格参考的强度、「额外写作要求」。也可以在「示例文本」里贴一段你自己的文字让 AI 提炼。单次生成还可以在「本章额外要求」或「加工这一段」的额外要求里临时指定。

**Q：我已经写了很多，能不能让它照着我自己的文风写？**
能。用「导入旧稿」进来时，「导入到」里勾着「顺便归纳这部作品的文风」（导入主线时默认就是勾上的），跑完会给你一条「文风与文体」待确认项 —— 七个维度的描述加文体取向，都是从你自己的稿子里读出来的，确认后写进风格档案。已经导入过、当时没勾的，也可以去「风格档案 → 调整 → 示例文本」贴一段自己的正文让它提炼，效果是一样的。

**Q：AI 忘了前面的剧情。**
大概率是摘要链断了。检查已完成的章节是否都有摘要——编辑器上的入口会把缺摘要的高亮成「补摘要」。补齐后再生成。

**Q：AI 把设定改错了。**
它改不了。所有设定变更都要经你确认。如果是你误采用了，去知识库直接编辑该条目。

**Q：为什么大纲只细化了前两卷？**
选「长篇」时有意如此。长篇后段应当随剧情生长，过早细化只会被推翻。写到那里时用「AI 细化为子节点」逐卷展开。

**Q：上传后整篇是乱码。**
正常情况下不会 —— 应用会自动识别 UTF-8 / GB18030 / UTF-16 并把识别结果显示出来。如果真的乱了，说明文件编码更冷僻，可以用记事本 / VS Code 打开后「另存为 UTF-8」再上传。

**Q：只能上传 txt 吗？我的稿子在 Word 里。**
可以上传 `.txt` / `.md` / `.rtf`。Word 里「另存为 → RTF」即可直接上传（应用会自动提取成纯文本），或「另存为 → 纯文本（.txt）」。不直接支持 .docx 是因为它本质是个压缩包，解析要额外依赖，而「另存为」是一步操作。

**Q：我的稿子是一章一个文件，几十个。**
按顺序一个个选，每次会接在后面。刻意不自动排序：中文文件名的字典序会把「第十章」排到「第二章」前面，悄悄打乱一本书比多点几下糟糕得多。

**Q：我的稿子是英文的，能翻译成中文吗？**
能。导入时分章后会多出一个「翻译」步骤（纯中文稿看不到）。语种按章判定，所以「部分章节是英文」这种情况只会翻那几章。译完后正文是中文、原文留底，之后的知识库提取与续写都基于中文。已经导入完了才想翻译的话，在章节编辑器标题栏点「译成中文」。

**Q：翻译贵吗？**
这是整个应用里最贵的操作 —— 大致相当于让 AI 重写一遍同样长度的文字（输出 token 比输入贵得多）。所以翻译步骤不会自动开始，你可以先取消勾选不需要的章节，或者先译一章看看效果。

**Q：译名会前后不一致吗？**
不会。同一个名字全书只用一个译法：先定下的译名会传给后面的章节，且**不允许被后面的翻译推翻**。译名表存在作品上（不是存在某次导入里），所以跨章节、跨批次、单章补译都用同一份。

**Q：分几次导入多份英文素材，人名会不会各译一套？**
不会。译名表是**作品级**的：第一批导入定下「Ashford → 阿什福德」之后，半年后再导入另一份素材，翻译时仍会带着这条约束。单章点「译成中文」也一样。

**Q：怎么改某个译名？**
「知识库 → 管理 → 译名表」。在那里改译名、删条目，或者**在翻译之前**先把关键人名定好 —— 定好了第一章就会照着译，不用等模型自己挑一个。注意：改译名只影响之后翻译的章节，已经译好的正文不会自动变，需要的话去那一章点「重译」。

**Q：改了译名，之前译好的章节怎么知道哪些要重译？**
译名表会替你找。改完之后表的顶部会列出「N 条译名与已有译文不一致」，写清是哪条译名、有几章没采用，点章节名直接跳到那一章。它比对的是原文与译文：原文里出现过 `Ashford`、译文里找不到「艾许佛」的章节就会被列出来。应用不会替你改字 —— 同一个词可能出现在对话、称谓、复合地名里，机械替换会出事。

**Q：翻译完想看原文怎么办？**
原文一直留着。单章翻译刚采用后，点「撤销 AI 改动」可以立刻退回原稿；之后原文仍存在这一章里，不参与字数统计。

**Q：英文章节的字数显示不对。**
已经修了。之前英文按字符数算，六个词会显示成 30 字，让写作计划的「每日 3000 字」失真约五倍。现在东方文字按字符、拉丁文字按词，中英混排两者相加。**纯中文作品的字数没有变化。**

**Q：支持翻译成英文吗？**
不支持。这不是一个通用翻译器，只做「把外文来稿并入一部中文作品」这一个方向。

**Q：导入时分章切错了怎么办？**
在分章预览里合并、删除、改名，或换一种分章方式重新切。选定「导入到」之前不会动到你的作品。

**Q：稿子里的番外、设定集不想进主线。**
在「导入到」里选「外传」或「仅作为世界观设定」。一批只能选一个目的地，混在一个文件里的话分两次导，每次在分章页删掉不属于这一批的章节。

**Q：导入跑了一半关掉了页面。**
进度已存盘。重新打开「导入旧稿」会直接回到提取步骤，点「继续提取」。

**Q：同一个人物在旧稿里被提取成了两条。**
给其中一条补上另一个称呼作为**别名**，然后重新提取会合并。别名是重名识别的关键。

**Q：待确认项太多看不完。**
可以只处理关心的几条，其余「全部忽略」——它们只是提案，忽略不会影响已有数据。也可以先关掉，未处理的会留在页面顶部的「待确认」区。

**Q：能一键生成整本小说吗？**
不能，这不是产品目标。每一步都要你确认与修改——它假定作者是你。

**互动推演**

**Q：情节里明明写了某个变化，「本线状态」里却没记下。**
推演只记得住「对得上号」的变化：改写的是锁定（底层）字段、找不到对应的条目、字段不在分类模板里、要给世界规则记「死亡 / 被毁」、新人物和已有条目重名，这些都会被丢弃。被丢弃的会列在那一步的「这一步有 N 处变化没有记下」里。确实需要的话，在「本线状态 → 本线变化」里手动补一条（只能改可变字段），或者到知识库把那个字段改成可变。

**Q：为什么不能改某个字段？**
它是锁定字段（底层设定），比如人物的性格、说话方式，世界规则的运作规则、限制与代价。锁定的意思是任何一条世界线都不能改它，所以手动编辑的下拉里也不会出现它。要改有两种办法：直接在知识库编辑这个条目（改的是世界观本身，所有线都会变），或者在条目的「互动推演设置」/ 分类管理里把这个字段设成可变。字段改成锁定之前已经存下的本线改写会显示「已改为底层设定，本线改写不再生效」，也不能提升为世界观。

**Q：为什么有的选项不能再选？**
这一步你已经选过它，标着「已走过」。同一步的同一个选择只对应一条线，点旁边的「去这条线」就能回到当时那条线继续。想走别的路，选另一个选项、自己写一个行动，或者点「再给几个选项」。

**Q：为什么推演主角不能在回收站里彻底删除？**
推演还在用他。彻底删除后推演就没有主角了，备份也会因此恢复不了。先删除那个推演（「更多 → 删除」，可以顺便把只属于它的条目移进回收站），再回来彻底删除；或者在回收站里恢复他，推演就能继续推进。

**Q：沉淀出来的章节，摘要里为什么没记下主角出场？**
主角是「仅限推演」的条目时，章节摘要看不到他：仅限推演的条目不进摘要、提取这些全书链路，免得推演人物混进全书的出场记录。写这一章不受影响，主角档案会作为「推演专属设定」必定带上。想让他像普通人物一样被摘要记下，把他的作用范围改成「通用」，或者把他提升为世界观。

**Q：合并导入备份之后，有些大纲为什么不再关联推演了？**
合并导入时，同一个推演的整棵分支树以备份为准。本地有、备份里没有的那几步会被备份版本取代；沉淀自这几步的大纲节点、外传章节保留，只是解除和推演的关联（大纲和正文都还在），设成「只从这几步起出现」的限定条目会去掉这一项限定，因此不再属于任何推演的会进回收站。这样合并之后再导出的备份仍然能正常恢复。

## 13. 本地运行与开发

### 环境要求

- Node.js（建议 22.22+；22.18 可用但安装依赖时会有 EBADENGINE 警告）
- npm

### 命令

```bash
npm install        # 安装依赖（首次较慢）
npm run dev        # 开发服务器，默认 http://localhost:5173
npm run typecheck  # 类型检查
npm run test:run   # 跑一遍全部测试
npm run build      # 生产构建
npm run format     # 用 Prettier 格式化代码
```

### 双击启动（免敲命令）

项目根目录有 `启动文墨服务器.command`：**双击**即可启动开发服务器并自动打开浏览器，无需进终端。首次运行会自动装依赖；服务器已在运行时双击，会询问打开浏览器还是停止。想放在顺手的地方，把它拖到桌面或 Dock 即可（拖 Dock 用「在访达中显示 → 拖到 Dock 右侧」）。

### 用手机 / 平板访问开发服务器

`npm run dev` 启动后终端会打印局域网地址（形如 `http://192.168.x.x:5173`），手机连同一个 Wi-Fi 直接打开即可。

> 局域网 IP 走的是纯 HTTP，属于**非安全上下文**，部分浏览器 API 在这里不存在（`crypto.randomUUID`、`navigator.clipboard`）。应用已针对这两处做了降级，功能不受影响，但「复制到剪贴板」走的是兜底路径，个别浏览器上可能失败 —— 那时改用「下载文件」。
>
> 新增浏览器 API 时请先确认它不是 secure-context only，否则只在 `localhost` 上验证会漏掉真机问题。

### 添加新的模型端点

自建或第三方中转端点除了在设置页填写，还需要登记到 `vite.config.ts` 的 `LLM_ENDPOINT_ALLOWLIST`——内容安全策略会拦下未登记的域名。这是防密钥外传的一层，不建议放开。

### 技术栈

React 19 + Vite 8 + TypeScript 7 + Tailwind 4 + Dexie（IndexedDB）+ Zod + zustand，测试用 Vitest + Testing Library。详见 [设计方案.md](./设计方案.md)。

移动端与桌面端是**同一套组件**，靠 Tailwind 断点切换形态（`md` 起多列与对话框，`lg` 起侧边栏外壳），没有按屏幕宽度分叉的渲染逻辑。改布局时请保持这个约定：分叉渲染会让同一份内容出现两棵 DOM，读屏读两遍，测试也会同时查到两份控件。
