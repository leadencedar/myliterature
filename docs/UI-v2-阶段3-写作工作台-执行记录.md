关键取舍：

- **先做「打开章节后的工作台」**，不重写整个 `/write` 信息架构：没有章节打开时，大纲/外传/推演/提案/导出仍按原页面工作，避免一次性推翻已验收链路。
- **右栏默认关闭**（Q5=A 上下文检查器）：不长期挤占正文；打开时覆盖在编辑器右侧，正文宽度仍是 680。
- **`Chapter.note` 与 UI 同 PR**：schema、DB v8、备份 v5、迁移测试一起改，避免旧库/旧备份在中间态读取失败。
- **工单式对账保留**：章节栏、页头、右栏已经就位；旧大纲/外传/推演入口尚未搬进工作台页头，关闭编辑器仍可访问，列入下一阶段 IA 工作。

## 5. 当前边界

- 未打开章节时仍是旧写作页：工作台不是 `/write` 的永久外壳，信息架构重排在后续阶段。
- 右栏是覆盖式抽屉，不记忆开关状态，也不能固定/拖宽。
- 浏览器后退、代码内 `navigate()` 仍未拦截（延续阶段 2 的已知项）；关闭/刷新由 `beforeunload` 兜底，站内链接由点击守卫兜底。
- 真机移动键盘/安全区未验证；390 只做了视口冒烟。
- `Chapter.note` 已从 AI/摘要/检索/导出链路排除（当前代码没有读取该字段）；后续增加提示词/导出字段时需补回归测试守住。
- 备份 v5：旧版应用不能读新备份（会明确提示版本过新），这是有意的。
