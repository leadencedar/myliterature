# 文墨 · 世界观设定写作指南

> 读者：要为文墨准备设定文本的 AI，以及作者本人。
>
> 目的：让设定文本经过「导入 → 仅作为世界观设定」后，尽可能完整、准确地变成知识库条目。本文每条规则都对应应用里的实际行为，背景与取舍见 [产品文档.md](./产品文档.md) 6.2、6.5。要用互动推演的作品另见第 9 节。

---

## 1. 网页怎么处理一份设定文本

上传 `.txt` / `.md`（或粘贴）→ **分章**（按标题行切成若干节）→ 检测到外文的节**可选翻译**成中文 → 选「仅作为世界观设定」→ 各节**按章打包成不超过 6000 字符的段**（几个短节合成一段；单节超长才按空行再切）→ **逐段调用模型提取**条目 → 各段结果**按条目名称累计合并** → 全部跑完后生成**待确认提案**：库里已有同名条目的走「合并」，否则走「新建」。

几个直接影响写法的事实：

- 每段是**独立的一次调用**。模型看得到知识库里**已入库**的条目，但看不到本次导入前几段刚提出、尚未确认的条目。
- 模型被要求「只写正文里真有依据的内容，不允许发挥想象补全」。没写的字段就是空的。
- 世界观导入**只收条目**。模型顺带产出的章节摘要、关键事件、伏笔清单、全书进展一律丢弃。

## 2. 能识别的分类与字段

模型只能从当前作品**已有的分类**里选分类名，并且只能用该分类字段模板里的键。分类名对不上，**整条丢弃**；字段不在模板里，**该字段丢弃**；字段内容为空也丢弃。

内置两类（每部作品都有）：

| 分类名     | 字段（文本里写中文名，括号内是内部键）                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 世界观设定 | 定义（definition）、运作规则（rules）、限制与代价（cost）、对剧情的影响（impact）                                                                          |
| 人物       | 身份（identity）、外貌（appearance）、性格（personality）、目标与动机（goal）、软肋与恐惧（flaw）、关系网（relations）、说话方式（voice）、成长弧线（arc） |

预置模板（作者需先在知识库里「一键添加」，否则不存在）：

| 分类名 | 字段                                                                                 |
| ------ | ------------------------------------------------------------------------------------ |
| 势力   | 简介（definition）、诉求（goal）、实力与手段（power）、弱点（weakness）              |
| 地点   | 简介（definition）、氛围（atmosphere）、叙事作用（function）                         |
| 道具   | 简介（definition）、能力与规则（rules）、代价（cost）                                |
| 伏笔   | 埋设内容（definition）、预期收束（payoff）、状态（status，填「未收束」或「已收束」） |
| 时间线 | 时间（when）、事件（what）、后果（impact）                                           |

每个条目另有三个通用项：**名称**、**别名**（可多个）、**一句话摘要**（模型被要求 30 字内）。

要点：

- 分类名与字段名**逐字照抄上表**。提示词里给模型看的是「键（中文名）：说明」，文本里用中文名，模型能对上键。
- 作品里没有「势力」「地点」等分类时，这些内容要么被模型塞进「世界观设定」（字段错位），要么被丢弃。**导入前先让作者在知识库里建好需要的分类**。
- 作者若改过分类名或字段，以作品里的实际分类为准；自定义分类同理，必须先建好。

## 3. 写作规则

**格式与切分**

1. **一个实体一个小节，每节以一行标题开头。** 有标题时分章会把每节切成独立单元，打包时节与节之间不会被切开；没有标题则整篇算一章，超过 6000 字符就按空行硬切，一个实体可能被拦腰截断。
2. **标题行用分章能自动识别的格式**：独占一行、不超过 50 字，形如 `第1节 灵潮`（`第` + 数字 + `章/回/节/话` + 可选的标题，标题部分不超过 40 字）。也认 `楔子` `序章` `序言` `引子` `尾声` `终章` `后记` `番外…` `Chapter 3: Title`。**不认** Markdown 的 `## 标题`，也不认 `第一卷`。
   - 坚持用 `## 标题` 也可以：分章页改选「自定义正则」，填 `^##\s+\S`。
   - 反过来，正文里不要有以「第N章 / 第N节」开头的短行（如单独一行「第三章埋下」），会被误切成新的一节。字段行以「字段名：」开头，不受影响。
3. **第一个标题之前不要放正文。** 开头无标题的部分不足约 200 字会被当成书名、简介丢掉。总述也放进一个带标题的小节。
4. **单个小节（标题行 + 正文）控制在 6000 字符以内，最好 3000 以内。** 超长节按空行切成几段，**切出的段不带标题行**，后面几段的模型看不到这一节在讲谁。
5. **段落之间用空行分隔。** 超长时只在空行处切；整节没有空行时按 6000 字符硬切，可能断在句子中间。

**命名**

6. **标题里的名称 = 条目名称 = 全文最常用的称呼。** 提示词要求 title 用「最常用的称呼」，标题与正文称呼一致，模型才不会自己挑一个。
7. **同一实体在全文只用一个正式名称。** 跨段合并只按名称匹配（忽略首尾空白与英文大小写，其他差异都算不同）：「沈砚」和「沈公子」会变成两条，「沈 砚」和「沈砚」也是两条。别名**不参与**本次导入内部的合并。
8. **在小节开头列出全部别名**（绰号、尊称、曾用名、外文原名）。别名会存进条目，之后再导入或写作时，正文里出现任一别名都能命中这个条目；第二次导入时，若新名称恰好等于已有条目的某个别名，会合并而不是新建。
9. **引用其他实体时写对方的正式名称。** 关系网字段的说明就是「注明对方姓名以便交叉引用」；写「他师父」模型无从对应。

**内容**

10. **字段写成「字段中文名：内容」，一行一个字段。** 和提示词里列给模型的字段名一致，最容易被原样归位。
11. **在小节第二行写「分类：人物」这样的分类声明。** 模型的 categoryName 必须从分类清单里原样抄，明说比让它猜可靠。
12. **一个实体的全部信息写在它自己的小节里，不要分散。** 同名条目跨段合并时，后一段的非空字段会**整段覆盖**前一段的同名字段，不是拼接；前一段写了「运作规则」，后一段再提一句，前面那句就没了。
13. **别的小节里提到某实体，只写名字和关系，不写它的设定细节。** 否则模型会为它再输出一条只有片段信息的条目，按上一条规则覆盖掉主小节的内容（主小节在前时）。
14. **写具体、可验证的事实，不写形容词堆砌。** 模型只录有依据的内容；「神秘而强大」提取出来几乎是空的。
15. **给每个实体一行「摘要：」，30 字内。** 它是条目列表里快速辨认用的。

**伏笔与时间线**

16. **伏笔写成「伏笔」分类的条目，一条伏笔一节。** 世界观导入会丢弃模型产出的伏笔清单，只有落成条目才能留下。标题写伏笔本身（如「玉佩上的缺口」），状态写「未收束」或「已收束」。
17. **时间线一事件一节**，标题带上事件名（如「第二次灵潮」），字段写 时间 / 事件 / 后果。时间线模板每条只有一个时间和一个事件，多个事件塞一节会被压成一条。

### 哪些内容写成写作规范，而不是世界观条目

文墨的知识库「写作规范」区块收的是作者给本作定下的约束。它原文保存、不被提取、不拆分合并，按作用范围整份进入写正文、规划、摘要、提取、检查这些任务，和设定冲突时以规范为准。区别在于：**条目描述「这个世界能发生什么」，规范规定「这本书选择发生什么、现在进行到哪里、按什么规矩写和整理」**。

下面这些内容写成规范，不要写进设定小节：

- **时间截面与冻结信息**：故事从原作的哪个阶段开始，这之后才出现的人物、组织、装备、信息一律冻结，角色不能提前使用或认识
- **与原作的差异及其因果**：基线是哪个版本，从哪件事开始分叉，改了哪些事实，每处改动影响哪些后续事件、人物和势力
- **信息分层**：哪些是作者全知的事实、公开常识、阵营内部的秘密、角色亲历的信息，主角知道什么、从哪里知道
- **命名与合并规则**：比如「阶段性称号不新增成人物」「组织不因名字相近合并」「保留『原作未明确』的限定」。这类规则写进规范并勾选「提取设定」，反向提取就会遵守
- **生成边界**：明确不能写的内容、不推算的数据、需要留白的问题
- **创作方向说明**：本作想侧重什么、刻意回避什么

为什么不写进设定：设定小节会被拆成一条条条目，按名称合并、被预选勾选。「开场之后的人物一律冻结」这种话塞进某条世界观设定，它只在那条条目被选中时才进提示词，还可能在合并时被后段覆盖；提取模型也会把规范里描述的分叉事实当成设定条目提出来。

**来源表、参考链接、「能核对的内容」这类核对说明，两边都不必放**：它们不约束创作，只占 token。实在要留，放进规范后可以用「AI 精简」去掉。

写规范时不需要遵守第 2–4 节的格式（分类、字段、标题行），用 `## 小节` 和列表组织即可；同人与改编可以先在编辑面板点「插入差异说明模板」再填。

## 5. 设定是故事体怎么办

小说片段、人物小传、前史故事同样可以选「仅作为世界观设定」，提取照常进行。但会损失：

- **只能拿到明写的事实。** 模型不推断、不补全，性格、动机这类靠情节暗示的内容常常空着。
- **名称由模型挑。** 条目名取「正文里最常用的称呼」，片段里一直叫「少年」「他」，名称就可能落成别的。
- **伏笔与时间顺序不会成为条目。** 模型的伏笔清单与关键事件在世界观导入中被丢弃。
- **长章被切后丢失上下文。** 超过 6000 字符的章被切开，后半段不带标题行，可能认不出主角。

补救：在每个故事片段**之后**加一节结构化的「设定附录」（按第 4 节模板），用正式名称把关键实体写全，伏笔与时间线单独成节。附录排在故事之后，同名字段以附录为准（后段覆盖前段），所以附录里每个字段都要写完整。

## 6. 外文设定

- **按节判定语种。** 一节里汉字占比低于一半（且字母数足够判断）就会默认勾选翻译；作者可以取消勾选。中文设定里少放大段外文，外文原名只在首次出现时括注，例如「阿什福德（Ashford）」，避免整节被判成中外混排。
- **翻译要作者手动开始**，按节逐个翻，保留原文的分段与空行。单节超过 6000 字符会提示「单次翻译可能被截断」，被截断的节标为失败；外文设定的每节也控制在 6000 字符以内。
- **译名先到先得。** 每节译完，模型附带的专名对照会并入作品的译名表；同一原文名已有译法时不会被后来的翻译改掉，后续各节翻译必须沿用。想指定译法，最可靠的办法是在翻译前由作者在「知识库 → 管理 → 译名表」里先填好（作者填写的会覆盖模型的）。
- 写外文设定的 AI 可以另附一份「原文名 => 期望译名」清单交给作者录入译名表；把这份清单写进正文本身没有特殊作用，它只会被当作普通文字翻译。
- 提取看到的是译文。模型被要求把外文原名放进别名，所以译文里保留原名括注（或译名表里有对应）有助于溯源。

## 7. 常见失败与原因

| 现象                       | 原因                                                   | 对策                                                                       |
| -------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| 某类条目一条都没有         | 分类名不在作品现有分类中，整条丢弃                     | 先在知识库建好分类；文本里分类名逐字照抄                                   |
| 条目有了，某些字段空着     | 字段名不在模板里被丢弃，或文本里没有明确依据           | 用第 2 节的字段中文名；写具体事实                                          |
| 同一人物出现两三条         | 不同小节用了不同称呼，跨段合并只认名称                 | 全文统一正式名称，其他叫法写进别名                                         |
| 某字段内容只剩一句         | 其他小节顺带提到该实体，后段的片段覆盖了前段           | 一个实体的信息只写在一个小节；别处只提名字                                 |
| 开头的总述没被提取         | 第一个标题前的内容不足约 200 字被当成简介丢弃          | 总述也放在带标题的小节里                                                   |
| 整篇只切出一章             | 标题行格式不被识别（如 `## 标题`、标题超过 50 字）     | 用 `第N节 名称`，或改用自定义正则                                          |
| 长小节后半部分归错实体     | 单节超过 6000 字符被切开，后续段不带标题行             | 拆短小节；段落里写出实体全名                                               |
| 伏笔、时间线没进知识库     | 世界观导入丢弃伏笔清单；作品没有「伏笔」「时间线」分类 | 添加预置分类，一条伏笔 / 一个事件一节                                      |
| 中文设定被要求翻译         | 外文占比过高，被判成中外混排                           | 原名只括注一次；或在翻译步骤取消勾选                                       |
| 第二批导入没合并到已有条目 | 新名称既不等于已有条目名称，也不等于它的任何别名       | 沿用已有名称，或在第一批就写全别名                                         |
| 文件被拒                   | 只收 `.txt` `.text` `.md` `.markdown`，上限 20 MB      | `.docx` / `.pdf` 先另存为 `.txt`；编码 UTF-8、GB18030、UTF-16 均可自动识别 |

另外：导入生成的条目不会自动标为「核心设定」，世界观底层规则确认入库后需要作者手动标记。

## 8. 给其他 AI 的提示词

把下面这段连同你的设定需求一起交给其他 AI：

```text
请把世界观设定整理成纯文本，供「文墨」导入为知识库条目。严格遵守以下格式：

1. 每个实体单独一节。每节第一行是标题，格式为「第N节 名称」（N 为阿拉伯数字，从 1 起连续编号，整行不超过 50 字），不要用 Markdown 的 # 标题，不要写「第一卷」这类卷标题。第一节之前不要有任何正文。
2. 标题之后逐行写：
   分类：{只能是下列之一：世界观设定 / 人物 / 势力 / 地点 / 道具 / 伏笔 / 时间线}
   别名：{其他称呼、绰号、外文原名，用「、」分隔；没有则省略此行}
   摘要：{一句话，30 字以内}
   然后是该分类的字段，每行「字段名：内容」，字段名必须逐字使用：
   - 世界观设定：定义、运作规则、限制与代价、对剧情的影响
   - 人物：身份、外貌、性格、目标与动机、软肋与恐惧、关系网、说话方式、成长弧线
   - 势力：简介、诉求、实力与手段、弱点
   - 地点：简介、氛围、叙事作用
   - 道具：简介、能力与规则、代价
   - 伏笔：埋设内容、预期收束、状态（只填「未收束」或「已收束」）
   - 时间线：时间、事件、后果
   没有内容的字段整行省略。
3. 每个实体只用一个正式名称，标题、正文、其他小节的引用都用这个名称，其他叫法只写在别名里。
4. 一个实体的全部信息只写在它自己的小节里。其他小节提到它时只写名称与关系，不补充它的设定细节。
5. 关系网里写对方的正式名称，例如「裴照——师兄，护着他也瞧不起他」。
6. 每节（含标题）不超过 3000 字；节与节之间、段落之间空一行。
7. 只写具体、可验证的事实与规则，不写空泛的形容词。
8. 一条伏笔一节，一个时间线事件一节。
9. 设定正文写完后，在正文之外另起一段说明（不要混进设定正文），告诉作者用到了哪些非内置分类，需要先在知识库里添加（世界观设定、人物为内置）。
10. 约束性内容（时间截面、与原作的差异、提取与写作规则、边界说明）不要写进设定正文，另起一份『写作规范』文档单独输出，供作者在知识库『写作规范』里粘贴。
11. 规则类设定（世界观设定的运作规则与限制与代价、道具的能力与规则与代价）写清三件事：能做什么、不能做什么、代价是什么。写成可以判断对错的具体规则，不要写「威力巨大」「代价惨重」这类无法判定的形容。
```

## 9. 为互动推演准备设定

互动推演（[产品文档.md](./产品文档.md) 6.8）把一个主角放进世界观里一步步选择。推演会拿知识库里的设定判定主角的尝试能不能成功，所以设定写得好不好，直接决定推演里的成败有没有说服力。

**世界观是底层，世界线记变化，分层写**

- 知识库条目写的是**开局时**、**所有世界线共有**的事实。推演里发生的变化（谁叛变了、谁死了、哪座城被占了）记在那条世界线上，不改条目，另一条线也看不到。
- 不要把「某人后来叛变」「第三卷宗门覆灭」写进条目：那是某一条线上的事。写进条目，它在每一条线上都成了既成事实，推演就失去了「选择改变结局」的意义。确实是原作既定走向、又想让推演参考的，写成伏笔或时间线条目，或者写进写作规范。

**可变性：哪些字段推演能改**

每个字段要么**锁定**（底层，任何世界线都不能改写），要么**可变**（可以随剧情变）。默认值：

| 分类       | 锁定                       | 可变                                     |
| ---------- | -------------------------- | ---------------------------------------- |
| 世界观设定 | 定义、运作规则、限制与代价 | 对剧情的影响                             |
| 人物       | 性格、软肋与恐惧、说话方式 | 身份、外貌、目标与动机、关系网、成长弧线 |
| 势力       | 简介                       | 诉求、实力与手段、弱点                   |
| 地点       | 简介                       | 氛围、叙事作用                           |
| 道具       | 简介、能力与规则、代价     | —                                        |
| 伏笔       | 埋设内容                   | 预期收束、状态                           |
| 时间线     | 时间、事件                 | 后果                                     |
| 自定义字段 | —                          | 全部                                     |

作者可以在分类管理里改整个分类的默认（「世界线可改写」开关），或在单个条目的「互动推演设置」里逐字段覆盖。预置分类改过名后，按「不知道语义」处理，全部默认可变。

写法上的要求：

- **锁定字段写成可验证的规则。** 推演提示词里锁定字段会标「（底层，不可改变）」，主角的尝试违背它时，模型要写出尝试失败及其后果。「逆潮强行吸纳会损伤经脉，三次以上必留暗伤」可以判定；「灵潮之力深不可测」判定不了，模型只能随意发挥。
- **「限制与代价」写得越具体，推演里的失败越有说服力。** 失败的情节就是从代价里长出来的：代价写成「左手失去知觉一天」，失败就有具体的后果可写；只写「代价很大」，失败就只剩一句空话。
- **性格、说话方式锁定，是为了让同一个人在每条线上都认得出。** 人物的成长与转变写进「成长弧线」（可变），不要指望改「性格」一栏来体现。
- **可变字段写开局时的状态。** 「身份：青冥宗外门弟子」会随推演变成别的；不要在可变字段里预写后来的变化。

**作用范围：隐藏人物和分支专属的事物**

只在某个推演里出现的人物、道具、地点（隐藏人物、某条路线才会遇到的角色），照常按第 4 节模板写进设定、导入知识库，然后由作者在条目编辑的「互动推演设置」里：

- 把作用范围改成「仅限推演」，勾选对应的推演；
- 需要满足条件才登场的，写一句**登场条件**（最多 200 字，比如「主角进入归墟之后」）。推演会把它当作「可能登场的预设」交给模型，而不是一开始就让他在场；
- 在推演页「本线状态」里还可以设成「只从这一步起出现」，只在那一步之后的分支里可见。

不要把隐藏人物写进其他条目的正文里藏起来：那样他没有自己的条目，推演无法把他记为登场，也无法注入他的档案。仅限推演的条目不会进入正文写作、摘要、提取等其他任务，不用担心他提前出现在主线里。
