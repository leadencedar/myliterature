# M3.1 打磨范围

来源：M3 文学顾问复核 P2/P3 + M2.1 顾问/QA 记录。只做影响「判断/信任」的小改动，不扩散到 M2 用户测试的大项 P1。

## 做

1. **续写提案两套采用按钮去重**：ProposalReview 只有一条提案时，不再渲染逐条「采用这条」（底部按钮同义），避免 m3-04 两个采用入口。
2. **安全提示动态化**：归档收件箱「本批 N 条对已有条目的合并/替换默认不选」随「恢复」变化：仍有跳过 → 显示「当前还有 X 条跳过」；全部恢复 → 显示「已全部纳入」。需要 ProposalReview 把忽略数回传给 ProposalInbox。
3. **计数口径解释**：安全提示里写清「本批共 M 项，其中 N 条合并/替换默认不选」；底部按钮数只算将写入项，差异可见。
4. **伏笔流水去重**：无历史伏笔时（open 与 opened 完全相同、resolved=0），明细只写「新埋」，不再重复「现存」；计数行加「（现存均为本章新埋）」。
5. **「恢复」措辞**：`恢复` → `纳入本批`（P3，更直白）。
6. **三个大纲入口关系**：写作页大纲区块 description 加一句：细化=拆当前节点；自动大纲=按已有章节补结构/往后规划；互动推演沉淀=先把玩出来的线变成大纲。

## 不做（留后续）

- M2 用户测试的大项 P1：注入清单人物字段可见、继续补写选场、全局收件箱分组、未完成标记持久化。
- 回溯上百章的批量分卷/虚拟滚动；续写提案的关联回写。
- 视觉重设计（只改文案与一处按钮显隐）。

## 验收

- 单提案的 ProposalInbox 只有底部一个采用按钮；多提案仍可逐条采用。
- 归档批次恢复全部合并后，安全提示变「已全部纳入」；部分恢复显示剩余条数。
- 无历史伏笔批次明细不重复「现存」；有历史伏笔仍显示三类。
- 「纳入本批」标签生效；大纲区块说明三入口关系。
- 既有测试同步，新增断言；全量门禁 + 沙盒截图。
