# M1 修复后复核（literary-advisor）

> 依据 `after-01…11`、`walkthrough.md §8`、`after-verification.md`（未重跑）。假模型只评信息与流程，不评演示文笔；658/6000 为演示截断，不代表真实字数体验。

## ① P0 留痕：安心
`after-07` 里，采用后回到编辑器，第一屏就是琥珀提示「本章由未完成生成稿采用，可能缺少结尾；补写后再标「已完成」」+「知道了」；位置在正文前、不挡写作，文案说人话且给了下一步。`after-09` 的边界更关键：已完成章被截断稿替换后状态退回「草稿」+同一提示，半章不再冒充定稿，我认可；可关掉、不吸顶都不算问题。唯一保留：提示是内存态，刷新/换设备后消失，只剩「草稿」标签，而草稿是常态，跨天回来可能忘；建议 M2 持久化，或章节列表给小标记。

## ② 关联面板：犹豫消除
`after-03` 干净多了：三按钮减为「全部跳过 / 确认关联（6 条）」，默认全选下没有同义按钮；「关闭面板不会写入任何关联；取消的条目在本次打开节点抽屉期间不再建议」正好回答「会不会偷偷写、取消了还回来」；chip「裴照 名字提到」不再重复名字。无新歧义，两处可顺：「名字提到」略生硬，可改「按名字命中」；说明四句连排偏长。

## ③ 结构承诺：兑现
`after-04`「场景数参考：约 3–5 场」+ `after-05`「658 字 / 目标 6000 字」：目标、场景、进度三处口径一致，能对账，也不会让人以为必须凑满。

## ④ 剩余 P2 / 真机
提示跨会话不持久（见①）；已完成章退回草稿后旧摘要是否仍进后续章上下文——沙盒未覆盖，建议补反向验证；桌面/长文/真实模型质量待真机；「采用后回树高亮」仍未做（可接受，M2）。

结论：P0/P1 闭环，可进 M2；上述均为打磨或真机项。
