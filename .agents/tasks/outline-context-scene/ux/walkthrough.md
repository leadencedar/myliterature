# M1 体验沙盒 · 走查记录（假模型 + 真浏览器）

> 执行者：qa-verifier（QA）
> 目的：让文学顾问在真实浏览器里「作为用户」走一遍 M1 新流程，只评**信息与流程**。
> **重要免责声明：本沙盒的模型输出全部是脚本里的演示用假数据（写死的 JSON / SSE），不代表真实文风质量，也不代表真实模型对设定的理解能力。** 真实模型质量需配真实 API Key 的真机验证（见 `../verification-report.md` §10 待人工项）。
> 数据都种在浏览器 IndexedDB 里，截图与记录可重复生成；不依赖真实网络与 API Key。

## 2. 预置数据（脚本种入作品《归墟纪》）

- 小说：**《归墟纪》**，仙侠，第三人称限知；一句话：失忆剑客追查灭门案，在渡口被迫与旧敌同船。
- 人物：
  - **沈砚**（别名「小舟」）：流亡贵族；说话方式「短句、爱用反问」；软肋「妹妹下落不明」；关系「与裴照有旧怨」。
  - **裴照**：六扇门捕头，冷硬寡言；与沈砚有旧怨，当年在渡口见过他妹妹。
- 世界观核心设定（**pinned**）：**渡口的规矩** —— 无官凭不得渡河、夜渡双倍船资、贿赂船夫会连坐同船之人。
- 大纲：
  - `第一卷 渡口`（目标 3 万字）—— 梗概「沈砚在渡口与裴照相遇，被迫接下去北方的差事。」（用于细化演示；开始时没有子节点）
  - `第二卷 夜渡` → 子节点 `第1章 夜渡`（**targetWords 6000**）
- 章节：`第 1 章 夜渡`（正文为空，挂在 `第1章 夜渡` 上，用于「生成本章」演示）

## 5. 异常 / 卡住点

- **页面异常：0**（`pageerror` 为空；无 console error）。
- **模型请求：2 次，均被假模型正常应答**（1 次结构化 + 1 次流式），无重试、无 400 回退触发。
- **脚本健壮性（已修）**：早期版本点击「开始生成」偶发 30s 超时（元素在移动端抽屉底部、滚动状态不稳定），已在脚本里显式 `scrollIntoViewIfNeeded()` 后点击并改为幂等滚动；本次连续两次完整运行均通过。这是**沙盒脚本**的问题，不是应用 bug。
- **截图取景（已修）**：抽屉较长（注入清单 → 细化 → 提案 → 保存），脚本现在会先滚到目标区块再截图，保证每张截图聚焦对应体验点。
- **演示局限**：假正文只有 658 字（就为演示截断），与「目标 6000 字」的落差是假数据造成的，**不要据此判断字数体验**。

## 6. 给文学顾问的体验观察提示（只列现象，不下结论）

以下是走查中值得注意的界面现象，请以作者视角判断「是否看得懂/被打断/信息过载」：

1. **单个抽屉很长**：在 390×844 上，从「关联设定」→「本次参考设定」→「细化」→「提案」→「保存」需要多次滚动；注入清单与提案不在同一屏。截图 `02`/`03` 是不同滚动位置。
2. **「写这一章」出现在卷节点上**：细化前 `第一卷 渡口` 没有子节点，抽屉里出现「写这一章」按钮（截图 02）。它是否符合「卷不该直接写一章」的直觉？
3. **注入清单文案**：`核心设定 1 条（始终注入）：渡口的规矩`、`相关设定：显式 0 条 + 提到 2 条，共约 146 tokens`、chips 带 `提到 · 沈砚 ×`。作者能否一眼相信「设定被用上了」？token 数是否有意义？
4. **关联确认默认全选 6 条**：三个场景卡各自动关联沈砚+裴照（`04`）。默认全选是否让作者放心？「全部跳过」= 一条不写，这个后果是否够清楚？
5. **移动端底部三按钮换行**：`全部保留 / 全部跳过 / 确认关联（6 条）` 在 390px 下第三个按钮文案换成两行（截图 04 可见）。是否拥挤、是否担心误触？
6. **目标来源与场景数**：`目标字数：6000 字（来源：大纲节点）` + 「场景数参考按这个目标推算」+「要修改请到『写作 → 大纲节点』里改」（截图 05）。信息是否足够、是否制造凑字数压力？
7. **截断体验**：结果标题「生成未完成」+ 红框说明 + 658 字，点采用先弹「仍要采用不完整内容？」（截图 06/07）。作者是否会误以为这是失败？二次确认是否必要？
8. **细化提案的呈现**：提案是一整段可编辑「大纲内容」文本（带 `# 标题（约 N 字）` 格式，截图 03），不是逐条卡片。作者是否觉得可读、可改？
9. **桌面形态**：右侧抽屉 + 保存按钮吸底（截图 09），与移动端底部抽屉差异是否合理。

> 再次提醒：第 6/7 条的「658 字」是假数据；第 3/8 条的细纲文本也是 QA 写死的演示内容。**只评价信息组织、文案与流程**，不要评价这篇演示稿的文学质量。
