## 6. 补充发现 · 390px 大纲区块版式回归（P1，由顾问复核发现）

**现象**：M3.1 给大纲 Section 的 description 追加「三种规划入口…」后，390px 下 description 加长，`Section` header 的 `flex items-end justify-between` 把右侧 action 按钮「规划后续 3–5 章大纲」挤成 1–2 字/行（约 5 行竖排），按钮文字甚至溢出 header 边界压到下方大纲树；桌面 1280px 正常。受影响截图：`01-writing-page-mobile.png`、`m3-01`（空大纲不含按钮，不加长时正常）、`m3-02`、`m3-05`，以及任何 390px 写作页（大纲 Section 含续写入口时）。

**根因（file:line）**：
- `src/ui/Page.tsx:73-84` `Section` header：`<div class="mb-2.5 flex items-end justify-between gap-3 px-1">`，左侧文字 div 无 `min-w-0`、右侧 action 无 `shrink-0`；description 变长后 flex 优先压 action。
- `src/features/writing/WritingPage.tsx:348-362`：大纲 Section 的 description 拼接 `OUTLINE_ENTRY_NOTE`（长句），action 为「规划后续 3–5 章大纲」按钮（`size="sm"`）。

**建议修法（dev 定夺，二选一或组合）**：
1. 通用最小修：`Section` header 给右侧 action 包一层 `shrink-0`，左侧文字 `min-w-0`；按钮保持一行，description 正常折行（对其它带 action 的 Section 也更稳）。
2. 移动端堆叠：header 改 `flex-col items-start gap-2 lg:flex-row lg:items-end lg:justify-between`（description 与按钮各占一行，390px 观感最好）；或仅大纲区块把说明放到 Section 内容区顶部而非 description。
3. 若选缩短文案（顾问建议「三种规划入口：细化 / 自动大纲 / 推演沉淀」），QA 需同步 `m3-s4` 对整句的断言。

**QA 复验计划（修复后）**：同步文案断言（若改文案）→ 重跑默认/串行全量 + typecheck/build → 重跑沙盒重拍 `m3-02/03/05` 等受影响截图 → 请顾问 1 分钟确认 → 再给「可提交」。
