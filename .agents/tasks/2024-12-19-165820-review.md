# 导入类型选择：章节 vs 世界观设定

用户导入旧稿时可以选择将内容作为章节（分章、翻译、提取、生成摘要）或作为世界观设定（只提取知识库条目，不创建章节、不生成摘要、不归纳文风）。实现方式是在粘贴步骤添加分段控件让用户选择，世界观模式通过创建临时章节（index = -1）完成提取后删除，复用现有提取逻辑但跳过摘要和文风提案的生成。

**Watch for:** 临时章节清理依赖 `finalize()` 被正确调用，提取失败时临时章节会留在数据库中（possible）；世界观模式下摘要提案的跳过逻辑通过两个条件判断实现但测试覆盖未知（likely）；UI 使用已有的 `SegmentedControl` 组件且文案清晰（confirmed）。

**Verdict**: NEEDS_CHANGES

## High-level view

Schema 在 `ImportJob` 中新增 `importType` 枚举字段，默认值 `'chapter'` 保证向后兼容，文档注释清晰说明两种模式的区别。

UI 在粘贴步骤使用 `SegmentedControl` 组件呈现两个选项，仅在有文本时显示，footer 按钮根据选择分发到 `goToSplit()` 或 `createWorldviewImportJob()`。

世界观模式创建 index = -1 的临时章节用于提取，设置 `withSummaries: false` 和 `withStyle: false`，翻译逻辑与章节模式一致，提取完成后在 `finalize()` 中通过 `index === -1` 筛选并删除临时章节。

提取逻辑在生成摘要提案时增加 `importType !== 'worldview'` 判断，`buildStyleProposal()` 开头直接返回 null 跳过文风归纳，提取进度消息根据模式显示不同文案。

测试验证显示 TypeScript 编译通过、1004 个单元测试全部通过，但不清楚是否包含针对新增 `importType` 字段和世界观流程的测试用例。

1. **临时章节清理的容错性** — `finalize()` 未被调用（异常中断、用户关闭页面）时临时章节会留在数据库，建议添加启动时清理孤儿临时章节的逻辑或在数据库层面定期清理 index = -1 的章节。

2. **摘要提案跳过逻辑的测试覆盖** — `extractOne()` 中 `importType !== 'worldview'` 的判断逻辑未见测试用例，建议添加单元测试验证世界观模式下不生成摘要提案。

3. **`withSummaries` 和 `importType` 双重条件的必要性** — `extractOne()` 中同时检查 `importType !== 'worldview'` 和 `withSummaries !== false`，但世界观模式已强制 `withSummaries: false`，第二个条件可能冗余；如果 `withSummaries` 是章节模式下可配置的，保留是合理的，否则简化为单一条件判断。

4. **世界观模式下 `rollingSummary` 的更新行为** — `finalize()` 中如果 `rollingSummary` 有变化会生成全书进展摘要提案，但世界观设定文本不应更新"全书进展"，建议在生成该提案时也检查 `importType` 跳过世界观模式。

## Schema 扩展与类型安全

`ImportTypeSchema` 定义为 `z.enum(['chapter', 'worldview'])`，在 `ImportJobSchema` 中字段定义为 `importType: ImportTypeSchema.default('chapter')`，默认值保证现有流程不受影响。

## 临时章节的生命周期管理

`createWorldviewImportJob()` 创建临时章节时使用 `index: -1` 作为标识，title 为 `'[临时：世界观导入]'`，status 为 `'draft'`，source 为 `'imported'`。这个章节的唯一目的是为提取逻辑提供 `chapterId` 和 `content`。

清理发生在 `finalize()` 中：

```typescript
if (current.importType === 'worldview') {
  for (const state of current.chapters) {
    if (state.index === -1) {
      await repository.deleteChapter(state.chapterId);
    }
  }
}
```

**容错性缺口（possible）**：如果 `finalize()` 未被调用（提取过程中用户关闭页面、浏览器崩溃、异常未捕获导致流程中断），临时章节会留在数据库中。这些孤儿章节的 index 为 -1，不会出现在正常章节列表中，但会占用存储空间且在某些聚合查询中可能被错误计入。建议在应用启动时或 `loadJob()` 时检查并清理 index = -1 的章节。

## 提取逻辑的条件分发

`extractOne()` 在提取完成后生成摘要提案，现在增加了条件判断：

```typescript
if (latest?.importType !== 'worldview' && latest?.withSummaries !== false) {
  await repository.createProposals([
    buildCreateProposal({
      // ... 摘要提案构建逻辑
    }),
  ]);
}
```

两个条件的组合：`importType !== 'worldview'` 跳过世界观模式，`withSummaries !== false` 是章节模式下用户可关闭的开关。`createWorldviewImportJob()` 显式设置 `withSummaries: false`，意味着世界观模式必然不生成摘要。

**测试覆盖未知（likely）**：grep 结果显示测试文件中没有 `importType` 或 `worldview` 的匹配。虽然整体测试套件通过了 1004 个测试，但无法确认是否包含针对这个条件判断的单元测试。建议显式验证世界观模式下不会调用 `repository.createProposals()` 创建摘要提案。

## 文风归纳的跳过逻辑

`buildStyleProposal()` 开头增加判断：

```typescript
if (current.importType === 'worldview') return null;
```

文风应该从完整章节稿件归纳，世界观设定文档不具备文风特征。`createWorldviewImportJob()` 中同时设置 `withStyle: false`，这是防御性的双重保护。

## UI 控件与交互流程

`SegmentedControl` 组件接受泛型参数 `T extends string`，options 包含 `value`、`label` 和可选的 `description`，选中项的 description 显示在控件下方。

导入类型选择器的实现：

```typescript
<SegmentedControl<'chapter' | 'worldview'>
  label="导入类型"
  value={importType}
  options={[
    {
      value: 'chapter',
      label: '作为章节',
      description: '分章存储，提取设定并生成每章摘要',
    },
    {
      value: 'worldview',
      label: '作为世界观设定',
      description: '直接提取知识库条目,不创建章节',
    },
  ]}
  onChange={setImportType}
/>
```

文案准确描述两种模式的行为差异。控件仅在 `text` 有内容时显示，避免无内容时出现无意义的选择。

Footer 按钮根据 `importType` 分发到 `goToSplit()` 或 `createWorldviewImportJob()`，按钮文本动态显示 `'下一步：切分章节'` 或 `'开始提取设定'`。

## 提取进度与完成文案

提取步骤的进度消息根据 `importType` 显示不同文案：世界观模式显示 `'正在从设定文本中提取知识库条目…'`，章节模式显示 `'正在提取第 X 章…'`。

Inbox 步骤的描述也做了区分，准确反映两种模式的产出差异：章节模式产出摘要 + 条目，世界观模式只产出条目。

## 翻译流程的一致性

`createWorldviewImportJob()` 中判断是否需要翻译的逻辑与章节模式一致：

```typescript
translateStatus: needsTranslationToChinese(text) ? 'pending' : 'none',
```

外文设定同样需要译成中文才能正确提取，翻译是语言问题而非导入类型问题。世界观模式下翻译的是临时章节的 content，翻译完成后提取逻辑读取这个章节的内容。

## 全书进展摘要的更新逻辑

`finalize()` 中有一段逻辑处理 `rollingSummary` 的更新：

```typescript
if (
  current.rollingSummary.trim() &&
  current.rollingSummary.trim() !== novel.rollingSummary.trim()
) {
  proposals.push(
    buildReplaceProposal({
      // ... 全书进展摘要提案
    }),
  );
}
```

这个逻辑没有检查 `importType`，意味着世界观模式下如果提取过程中更新了 `rollingSummary`，也会生成全书进展摘要的替换提案。

**语义不一致（confirmed）**：世界观设定文本不应该更新"全书进展摘要"，这个字段的语义是跟踪章节级故事进展，设定文档不是故事的一部分。建议在生成提案前检查 `importType` 跳过世界观模式。

## 向后兼容性

`importType` 字段的默认值为 `'chapter'`，保证现有数据库中的 `ImportJob` 记录在读取时被 Zod 自动填充默认值，现有代码路径显式设置 `importType: 'chapter'`，所有条件判断默认走章节流程。

## 数据库清理的实现

`repository.deleteChapter()` 在 `DexieNovelRepository.test.ts` 中有测试覆盖，实现使用事务同时删除章节和关联的摘要。世界观模式下临时章节不应该有摘要记录（因为跳过了摘要提案生成），但即使有也会被正确清理。
