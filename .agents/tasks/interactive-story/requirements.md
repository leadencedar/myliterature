> 唯一需求来源：`brief.md`（2026-10-21 与用户的讨论）。本文把它整理成可验收的需求，**不做设计决定**。凡标「决策点 D*」的，留给技术设计给出推荐与理由；凡标「假设 A*」的，是本文为消除歧义做的推断，设计评审可以推翻，但推翻要说明理由。

## 1. 概述

参考《底特律：变人》式分支叙事：作者把一个 OC 放进已建好的世界观，AI 生成 OC 面对的挑战与 2–4 个选项；作者选择或自由输入行动后，AI 写出后果与下一个挑战，循环到预设结局或作者认为可以收尾的节点。任意时刻可以回退到之前的挑战、走另一条世界线，原来的线完整保留。

**为什么要做、和酒馆类应用差在哪**：互动本身是目的，但每条世界线都能**沉淀为大纲与细纲，再润色成正式章节**，接入现有大纲树、整章生成、摘要链、外传、导出。推演产出的是结构化叙事资产，不是一次性聊天记录。所有需求都要服务于这个差异化，验收时不能只验「能玩」，还要验「能沉淀」。

### 1.1 已确认的用户决策（不可在设计中改动）

| #   | 决策                                                                                                                                                                                               | 为什么重要                         |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| U1  | 互动是目的；一条世界线可以生成大纲与细纲，最终润色成小说                                                                                                                                           | 决定了数据必须结构化、可回溯到路径 |
| U2  | 每步像游戏：几百字情节 + 一个挑战 + 2–4 个选项                                                                                                                                                     | 决定步长、输出上限与节奏           |
| U3  | 允许坏结局（含 OC 死亡、任务失败），坏结局结束该线，但必须能回退                                                                                                                                   | 失败不是错误状态，是正常结局       |
| U4  | 分支树是唯一真实存储；主线与外传都是树上的路径；外传只存分叉点之后并记录分叉节点；主线跟随「最新」世界线；同一节点选过的选项不能再选，但可以随时切到那条旧线查看或继续；回退时原线完整保留为外传线 | 数据模型的根                       |
| U5  | 新事实只记在所属世界线上，不写回全局知识库；知识库新增「世界线」层                                                                                                                                 | 兄弟分支互不污染                   |
| U6  | 决策方式：AI 选项与自由输入都支持                                                                                                                                                                  | 两条输入路径都要验收               |

### 1.2 术语

- **推演**：一本书下的一次互动故事，一本书可以有多个。拥有一棵分支树、一套开局设定。
- **节点**：树上的一步。包含情节、挑战、选项、世界线差异、进度、结局标记等。
- **路径 / 世界线**：从根到某个节点的一条路线。
- **主线路径**：按主线规则（D1）当前被标为主线的那条路径。
- **外传线**：树上非主线的路径；它与主线（或其他线）的公共前缀之后的部分属于它自己。
- **世界线差异（diff）**：某节点因选择产生的知识变化，沿树向下继承。
- **有效知识**：节点 N 处计算出的知识视图，不存储。

### 1.3 本文的假设

- **A1**：「外传线」在树上只是路径属性；只有作者执行「沉淀为外传」时才创建 `SideStory` 记录。否则每次回退都会在外传列表里多出一部空外传。
- **A2**：一本书已有的主线大纲与章节不受推演影响，直到作者对某条推演路径执行「沉淀」。一本书有多个推演时，哪个推演的主线能沉淀进书的主线、能否追加到已有主线之后，归入 D7。
- **A3**：推演的知识层只在推演内部生效。没有推演时、或写作链路未显式引入推演上下文时，现有写作链路看到的知识库与改动前完全一致。
- **A4**：OC 引用一条已有人物条目时，人物原始设定属于世界观层；OC 在推演中的状态（伤势、持有物、关系、已知秘密等）属于世界线层。
- **A5**：自由输入行动是作者文本，不是 AI 产出；AI 据此写出的情节与差异才是 AI 产出。
- **A6**：现有「外传不挂大纲树、简介即轻量大纲」（产品文档 6.3）是已确定的设计。外传路径的「大纲 / 细纲」落在哪里与这条冲突，归入 D7、D8，不在本文决定。

## 2. 功能需求

### F1 入口与推演管理

- F1.1 新增「互动推演」入口，位置由设计决定（主导航或写作页），并同步修改产品文档第 7 节信息架构。**为什么**：五个主导航是已有的信息架构，加第六项会影响底部 Tab 在窄屏上的可用宽度，需要设计权衡。
- F1.2 推演针对当前作品；没有选定作品时与其他页一样引导去书架。
- F1.3 每本书可以有多个推演：新建、重命名、删除（删除需确认，说明会连带删除整棵树）、列表展示（名称、OC、节点数、主线步数、是否已到结局、最后推进时间）。
- F1.4 删除作品时连带删除其推演数据。

### F2 开局设定（导演层输入）

- F2.1 OC：引用一条已有人物条目，或新建 OC（新建形式由 D4 决定：是否同时创建人物条目、是否走提案）。
- F2.2 起点：时间、地点、处境。
- F2.3 结局目标：至少一个，可多个（例如一个真结局 + 若干坏结局），每个带类型（好 / 坏 / 中性）。
- F2.4 可选里程碑（有序）。
- F2.5 基调与节奏：预计步数。
- F2.6 开局设定可在推演开始后查看；可否修改、修改后对已有节点的影响由 D4 决定。
- F2.7 数据模型不能把 OC 写死成单个（为第二期多 OC 留口）。

### F3 推演循环

- F3.1 每一步产出（schema 细节见 D3）：情节正文（几百字）、挑战描述、2–4 个选项（可带风险提示或倾向标签，**不能剧透结果**）、世界线差异、向结局或里程碑的进展、是否触发结局（好 / 坏 / 中性）。
- F3.2 情节流式显示。
- F3.3 结构化输出走现有 Zod 校验 + 修复重试；截断检测复用 `finishReason === 'length'`。截断或解析最终失败时，**不落一个半截节点**，提示失败原因，可重试。
- F3.4 两种决策方式：点选 AI 选项；自由输入行动。
- F3.5 自由输入不合理时（凭空获得能力、违反底层规则），处理方式由 D3 决定；无论哪种方式，**锁定字段都不能因此被改**。
- F3.6 每个节点保存 AI 生成的原始选项，回退或切换回来时不重新生成。
- F3.7 不预生成未选的分支。
- F3.8 写作规范新增「互动推演」作用范围，推演每一步注入作用范围含它的规范（见 F10）。

### F4 世界线差异（知识层）

- F4.1 差异类型至少包括：条目字段被覆盖、仅在本线存在的新条目、条目状态变化（死亡 / 失踪 / 被毁等）、OC 状态（伤势、能力、持有物、关系、已知秘密）、事件记录与标记。
- F4.2 差异挂在产生它的节点上，**沿树向下继承到所有后代，兄弟分支及其后代不可见**。
- F4.3 差异只在推演沙盒层，**不修改世界观层的任何条目**。
- F4.4 AI 产出的差异若试图覆盖锁定字段，必须被拒绝或丢弃（宁可少记，5.2），并在该节点上向作者提示被丢弃的内容。
- F4.5 差异引用不存在的条目、不存在的字段时按 5.2 丢弃（具体规则由设计定，但不能静默造出不存在的引用）。
- F4.6 作者可以在任意节点查看、编辑、删除该节点的差异。编辑祖先节点的差异后，后代的有效知识随之变化（是否提示「后代基于旧事实生成」由设计决定）。
- F4.7 有效知识视图：在任意节点展示该处的有效知识（世界观条目 + 适用于本线的限定条目 + 沿路叠加的差异），并能看出每一项来自世界观层还是哪个节点的差异。
- F4.8 差异确认流程见 D6；设计必须论证不违反 5.1，并写进产品文档 5.1。

### F5 世界观条目新属性

- F5.1 作用范围：`通用`（默认）/ `限定世界线`（只在指定推演或世界线存在）。
- F5.2 可变性：`底层（锁定）` / `可变`。粒度（按条目还是按字段）由 D2.2（见 §5）决定；分类模板要给默认值。
- F5.3 已有条目升级后行为与现在完全一致（默认通用；可变性默认值由设计给出，但不能改变任何现有写作链路的 prompt）。
- F5.4 现有导入（含「仅作为世界观设定」）、反向提取、写作规范、风格档案、核心设定继续作用于世界观层，行为不变。
- F5.5 原作同人的「时间截面」：本期不做原作事件表，但数据模型不能阻碍以后加。

### F6 提升为世界观

- F6.1 任意节点上的一条差异或本线新条目，作者可以「提升为世界观」。_（设计阶段补充：可提升的是「条目字段覆盖」与「本线新条目」；条目状态、OC 状态、事件与标记不可提升 —— 世界观条目没有对应的栏位，它们是这条线的剧情，要进全书应走「沉淀」。界面对不可提升的项说明原因。见 design.md §7.1。）_
- F6.2 提升走现有提案管道：新条目走 create（知识库里已有同名通用条目时改为 merge，合并进那个条目而不新建）；字段覆盖走 replace 提案（payload 是只换这一栏的完整条目），显示字段级 diff；作者确认后才写入世界观层。_（设计阶段修订：原文写「字段覆盖走 merge」。merge 对 list 字段取新旧并集，而世界线覆盖的语义是替换，提升后应是新值而不是新旧拼在一起，所以改用 replace。见 design.md §7.1。）_
- F6.3 试图提升对锁定字段的修改时，按 D6 给出的规则处理（不能绕过锁定）。

### F7 回退、分叉与切换

- F7.1 可以回退到当前路径上任意祖先节点，并从那里选择另一个选项或自由输入。
- F7.2 回退本身**不发任何模型请求**。
- F7.3 回退后原路径完整保留（节点、差异、选项状态都不变）。
- F7.4 在同一节点已走过的选项显示为「已走过」，不可再点。
- F7.5 可以切换到任一旧世界线的任意节点，查看或从它继续推进；切换本身不发请求。
- F7.6 自由输入与已走过选项本质相同时如何判定（D2.1）；一个节点所有选项都走过后能否「再生成一批」（D2.3）。
- F7.7 坏结局节点不能继续推进，但能回退到任意祖先。

### F8 主线

- F8.1 主线跟随「最新」世界线，「最新」的定义由 D1 决定。
- F8.2 UI 上随时明确标出当前主线，以及当前所在节点是否在主线上。
- F8.3 主线变化时，已沉淀的大纲与章节的处理方式由 D7.4 决定，但至少不能静默删除作者已采用的正文。

### F9 世界线导航

- F9.1 列表或面包屑形式的导航（本期不做图形化树）：能看到当前路径、每个祖先节点、每个节点的分支（已走过的选项、各分支的深度或结局状态），能跳到任意节点。
- F9.2 移动端与桌面端都认真做（5.4）：单套 DOM + CSS 断点；移动端用按钮而不是拖拽或手势导航；触控目标足够大；桌面端情节正文限宽阅读列；键盘可达、焦点可见；Esc 受 `isComposing` 守卫。

### F10 结局与收尾

- F10.1 AI 判定结局触发（好 / 坏 / 中性）后，该节点标为结局，不再给选项。
- F10.2 坏结局后明确提示可以回退，并给出回退入口（至少能回到上一个挑战）。
- F10.3 「收尾」按钮：根据当前状态写出结局节点（对应 task profile 见 §3）。

### F11 沉淀为小说

- F11.1 从一条路径生成大纲（卷 / 章两层）与细纲（每章梗概、关键事件、出场人物、关联条目）。**结果走现有提案管道**，确认后写入。
- F11.2 再通过现有「写这一章」整章生成润色成正文：推演原文与世界线状态作为额外上下文注入，并出现在「本次注入」清单里；正文仍走可编辑预览 → 采用。_（设计第 2 轮补充：还要注入「推演专属设定」，即主角及本章涉及的、作用范围限定到该推演的条目原文。限定条目不在现有写作链路的条目列表里，不注入的话整章生成就拿不到主角档案。段落加工不注入推演材料。见 design.md D7.3。）_
- F11.3 主线路径沉淀到主线大纲与章节；外传路径沉淀为 `SideStory`，并记录推演与分叉节点。
- F11.4 生成外传章节时自动接上分叉点之前共用路径的摘要；导出外传时不重复导出共用的前半段。
- F11.5 已沉淀的大纲 / 章节能追溯到来源推演与节点（为 D7.4 的过期判断提供依据）。

### F12 写作规范作用范围

- F12.1 `WritingNormScope` 新增「互动推演」，编辑面板与列表的作用范围选项里出现它。
- F12.2 已有规范升级后**是否默认勾上**「互动推演」由设计决定并说明理由（默认全开是现有约定，但给老规范自动加新范围会改变作者已做的选择）。
- F12.3 规范在推演 prompt 中的位置遵循第 9 节：稳定前缀、排在核心设定之前。

### F13 持久化与断点续玩

- F13.1 推演全部状态存 IndexedDB；刷新或关闭页面后回到同一推演、同一节点，可以继续。
- F13.2 生成中途刷新：不留下半截节点；已完成的节点不丢。
- F13.3 Dexie 升级到 v7（当前 v6）；旧库升级后所有现有数据可用。
- F13.4 备份快照升级到 v4（当前 v3），包含推演数据与条目新属性；v1–v3 备份照常能恢复（缺推演数据视为空、条目新属性取默认值）；旧版应用读 v4 时明确报「来自更新版本」，而不是悄悄丢数据。
- F13.5 备份入口的 Zod 校验覆盖推演数据的引用完整性（例如节点父子关系、外传引用的推演与分叉节点存在且属于同一作品），具体规则由设计列出。**为什么**：备份是唯一能绕过仓储写入的入口。
- F13.6 合并导入（并入另一台设备的作品）时推演数据随作品一起导入。

## 3. 非功能需求

- N1 **5.1 确认原则**：除 D6 论证并写进产品文档的例外外，所有结构化 AI 产出走提案；正文走可编辑预览。
- N2 **5.2 宁可少记**：对不上的分类、字段、条目引用、锁定字段覆盖一律丢弃并可见地提示。
- N3 **成本与缓存（第 9 节）**：推演 prompt 拆成稳定前缀（作品信息、风格、写作规范、锁定世界规则、OC 原始设定）与易变尾部（有效世界线状态、最近若干步原文、更早步骤摘要、导演提示）；同一推演连续推进时前缀逐字节可复现。回退和切换不重新生成；不预生成分支。长路径的早期步骤压缩方案（按路径滚动摘要，按节点存放、沿路继承）由 D5 决定。
- N4 **零回归**：没有任何推演时，现有写作链路（立项、细化大纲、整章、段落加工、摘要、提取、翻译、文风、规范精简、按规范检查）的 prompt 与改动前**逐字节一致**，参照 `src/context/noNormsInputs.test.ts` 的做法。
- N5 **task profile**：新增至少 `interactive-step`、`interactive-ending`、`path-to-outline`（命名可调）。推演属于创作但输出结构化，思维链开关、温度、是否用重点任务模型由设计在 `src/llm/taskProfiles.ts` 的既有原则下给出取舍。
- N6 **两端第一等公民**：单套响应式 DOM；不引入新依赖。
- N7 **中文注释，写明「为什么」**。
- N8 **范围外文件不动**：不需要改的现有功能不改。
- N9 **验证**：`npm run build` 通过；`npx vitest --run` 全绿（当前 62 个文件、1443 个测试，新增测试后数字增加，但不能有失败或跳过）。

## 4. 验收标准

> 每条都要有对应的自动化测试，除非标「手测」。「请求」指对模型服务的 fetch 调用。

**分支树与差异继承**

1. 在节点 1 选 a 生成节点 2a，节点 2a 的差异把人物 X 的「身份」改为「叛徒」；在节点 2a 之下的节点 3a 的有效知识里，X 的身份是「叛徒」。
2. 回退到节点 1 选 b 生成节点 2b；节点 2b 及其后代的有效知识里，X 的身份仍是世界观原值，看不到 2a 的任何差异。
3. 节点 2a 新增的本线人物 Y，只在 2a 的后代中出现；在 2b 分支、在知识库条目列表、在现有写作链路的任何 prompt 里都不出现。
4. 世界观层条目在任何推演操作之后（推进、回退、编辑差异、结局）都未被修改，除非经「提升为世界观」提案确认。
5. 作用范围为「限定世界线」的条目只出现在指定推演 / 世界线的有效知识里，在其他推演中不出现。
6. 编辑节点 2a 的差异后，3a 的有效知识随之变化；2b 不受影响。

**锁定字段**

7. 某世界观设定的「运作规则」为锁定，AI 产出的差异试图覆盖它时，该差异被丢弃，节点上出现可见提示，有效知识里仍是原值。
8. 作者手动编辑差异时，不能针对锁定字段新建覆盖（入口不可用或保存被拒并说明原因）。
9. 自由输入「我突然学会了瞬移」且世界规则不允许时，生成的节点不包含对锁定规则的覆盖。
10. 提升为世界观不能用来绕过锁定（按 D6 的规则；测试验证该规则）。

**选项、回退、切换**

11. 在节点 1 选过 a 后回退到节点 1，a 显示为「已走过」且不可点击；b、c 可点。
12. 回退到节点 1 时显示的选项文本与第一次生成时逐字相同。
13. 回退到任意祖先节点期间，stub fetch 记录到的请求数为 0。
14. 切换到旧的 a 线任意节点期间请求数为 0；在 a 线叶子上继续推进，生成的新节点挂在 a 线叶子之下，b 线不变。
15. 自由输入与已走过选项相同时的行为符合 D2.1 的决定（测试覆盖精确匹配场景；若设计选了相似度或 AI 判定，再覆盖相应场景）。
16. 所有选项走过后的行为符合 D2.3 的决定。

**主线**

17. 按 D1 的定义，以下序列每一步之后主线标记都正确：走 a 线推进 3 步 → 回退到节点 1 走 b 推进 1 步 → 切回 a 线只查看 → 在 a 线推进 1 步。
18. UI 上当前主线有明确标识，当前节点不在主线上时也有标识（可被 `getByRole` / `getByText` 查询到）。

**生成与结局**

19. 一步生成产出：情节、挑战、2–4 个选项、差异、进展、结局标记；选项数不在 2–4 时视为校验失败并修复重试。
20. 输出 `finishReason === 'length'` 时报截断错误，不落节点；修复重试仍失败时不落节点，可重试。
21. 情节在生成过程中流式出现在界面上（UI 测试用分块 stub 验证）。
22. AI 判定坏结局后，该节点无选项、无自由输入框，显示回退提示；回退到祖先后可正常推进。
23. 「收尾」生成结局节点并标结局类型。

**提升与沉淀**

24. 「提升为世界观」生成一条提案；确认前世界观层不变，确认后条目新建或字段合并。
25. 「沉淀大纲」只生成提案（卷 / 章 + 细纲字段），确认前大纲树不变，确认后写入。
26. 对已沉淀的大纲节点「写这一章」时，「本次注入」清单包含推演原文与世界线状态；主角是新建 OC（限定条目）时，清单还包含推演专属设定，请求里有 OC 的设定字段；采用前正文不变。
27. 沉淀外传路径后，`SideStory` 记录了来源推演与分叉节点；生成外传第 1 章的 prompt 包含分叉点之前共用路径的摘要；外传导出不含共用前半段。
28. 主线切换后已沉淀内容的处理符合 D7.4 的决定，且作者已采用的正文没有被删除。

**写作规范**

29. 作用范围含「互动推演」的启用规范进入推演 prompt 的稳定前缀，并排在核心设定之前；不含该范围的规范不进入。

**持久化与兼容**

30. 推进若干步后卸载并重新挂载页面（或重开数据库），推演回到同一节点，树、差异、已走过状态完整。
31. 用 v6 结构建库并写入现有数据，升级到 v7 后现有数据全部可读，条目新属性取默认值。
32. v1、v2、v3 备份文件能恢复；缺推演数据视为空。
33. v4 备份往返（导出 → 覆盖恢复 / 合并导入）后推演数据逐字段相同。
34. 引用完整性被破坏的 v4 备份（例如节点指向不存在的父节点、外传指向不存在的分叉节点）被拒绝并说明原因。

**零回归**

35. 没有推演、条目新属性为默认值时，第 N4 条列出的各任务 prompt 与改动前快照逐字节一致。
36. `npm run build` 通过；`npx vitest --run` 全绿。

**UI 主要流程（renderWithProviders + stub fetch）**

37. 新建推演 → 填开局设定 → 第一步生成 → 点选项推进 → 回退 → 看到已走过 → 选另一个选项 → 切回旧线 → 到达坏结局 → 回退，全流程在一个测试里走通。
38. 自由输入路径走通一步。
39. 世界线导航（列表 / 面包屑）在测试中能列出当前路径与分支，并能跳到任意节点。
40. 手测：375px 窄屏与 1280px 宽屏各走一遍 37 的流程，导航、选项、差异查看都可用，触控目标不过小，桌面端正文限宽。

## 5. 决策点（留给技术设计，必须给出推荐与理由）

> 简报 §3 共 9 项。下面列出全部子问题；简报里给了「推荐」的，设计可以采纳也可以修正，但都要写理由。本文不替用户做决定。

**D1 「主线跟随最新」的定义**

- D1.1 「最新」是最近创建的叶子，还是最近推进（作者最后一次做决策）的路径？（简报推荐：最近推进所在的路径）
- D1.2 切换到旧的 a 线：只查看时主线是否变化？在其上推进后主线是否随之切换？（简报推荐：只查看不变，一推进就切）
- D1.3 主线如何在 UI 上标识。
- D1.4 主线变化时已沉淀大纲与章节的处理（与 D7.4 联动）。

**D2 「选过的选项不能再选」与自由输入**

- D2.1 自由输入与已走过选项本质相同怎么判定：轻量 AI 判定（额外成本）/ 文本相似度 / 只做精确匹配加提示。
- D2.2 可变性按条目还是按字段设置，以及各分类模板的默认值（简报推荐按字段：世界观设定的规则字段默认锁定，人物状态与关系默认可变）。_（属于 §2.2，放这里统一追踪）_
- D2.3 一个节点所有选项都走过后，是否允许「再生成一批新选项」；若允许，如何与「回退不发请求」「原始选项保存」共存。
- D2.4 走过的自由输入行动在回退后如何呈现（是否也显示为已走过）。

**D3 每一步的生成内容与 schema**

- D3.1 结构化 schema：情节、挑战、2–4 个选项（风险 / 倾向标签，不剧透）、差异、进展、结局标记的具体字段与限制（情节字数范围、选项文本长度等）。
- D3.2 情节流式与结构化解析如何同时成立（一次调用还是两次、流式显示哪一部分）。
- D3.3 自由输入不合理时的处理（简报推荐：按世界规则写出「尝试与后果」，不直接拒绝，同时不违反锁定规则）。
- D3.4 自由输入本身的校验（必填、长度上限、空白处理）。

**D4 导演层**

- D4.1 开局设定字段与校验（OC 引用或新建、起点、多结局目标、里程碑、基调、预计步数）。新建 OC 是否创建世界观人物条目、是否走提案。
- D4.2 每一步如何注入当前进度与下一个里程碑。
- D4.3 「收尾」按钮的生成方式。
- D4.4 防止「越走越散」与「为到结局强行转折」的具体 prompt 策略。
- D4.5 开局设定能否在推演开始后修改，改了对已有节点有什么影响。

**D5 上下文与成本**

- D5.1 稳定前缀与易变尾部的具体组成和顺序（锁定世界规则、OC 原始设定如何入前缀；有效世界线状态如何序列化）。
- D5.2 「最近若干步原文」取几步。
- D5.3 长路径早期步骤压缩：按路径滚动摘要，摘要按节点存放、沿路继承；何时生成、是否额外调用、失败如何处理。
- D5.4 有效知识注入量的控制（全量还是按出场预选），以及是否展示「本次注入」清单。

**D6 差异的确认流程**

- D6.1 是否采用：差异自动记在节点上（仅沙盒层）、随时可查看编辑、只有「提升为世界观」和「沉淀」走提案 / 预览确认（简报推荐采用）。
- D6.2 论证这为什么不违反 5.1，并写进产品文档 5.1 的例外说明。
- D6.3 提升为世界观时涉及锁定字段的处理规则。

**D7 沉淀为小说**

- D7.1 路径 → 大纲（卷 / 章）+ 细纲（梗概、关键事件、出场人物、关联条目）的映射：一步对应一章，还是多步合并为一章，由谁决定。
- D7.2 生成走提案的具体形态（一次性还是分卷）；细纲字段放在现有 `OutlineNode` 的哪些字段，还是新增字段。
- D7.3 整章生成时推演原文与世界线状态如何注入，放在前缀还是尾部，如何不破坏没有推演时的逐字节一致。
- D7.4 主线切换后已沉淀的大纲与章节：保留 / 标记过期 / 提示重建。
- D7.5 一本书多个推演、或书已有主线章节时，推演主线沉淀到哪里（追加、替换、禁止）。_（本文补充，见 A2）_
- D7.6 外传路径的大纲 / 细纲落在哪里，与「外传不挂大纲树」的现有设计如何调和。_（本文补充，见 A6）_

**D8 外传与分叉**

- D8.1 `SideStory` 如何关联推演与分叉节点（新增字段及其可空性）。
- D8.2 生成外传章节时共用路径摘要的来源与位置（易变尾部，保证与主线共享前缀）。
- D8.3 Dexie v7 迁移内容（新表、新索引、旧行补默认值），备份 v4 的结构与 v1–v3 兼容规则，`superRefine` 新增的引用完整性检查。

**D9 多 OC 与分支流程图**

- D9.1 本期不做多 OC，但数据模型要怎么留口（例如 OC 用数组或独立实体）。
- D9.2 本期移动端与桌面端导航用列表 / 面包屑的具体形态；不做图形化树。

**附加（简报 §4、§5 提到、需设计判断）**

- D10 入口位置：主导航第六项，还是写作页内（F1.1）。
- D11 task profile 参数（思维链、温度、模型档位）取舍（N5）。
- D12 「按规范检查」推演节点：低成本可以纳入第一期，否则第二期（§7）。
- D13 已有写作规范是否默认勾上新的「互动推演」作用范围（F12.2）。
