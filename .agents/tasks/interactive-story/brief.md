# 互动推演（世界线）· 需求简报

> 来源：与用户的讨论（2026-10-21）。本文是后续设计、规划、实现、审查的唯一需求来源。凡标「决策点」的，设计必须给出推荐并说明理由，不能静默略过。

## 0. 一句话

参考《底特律：变人》式的分支叙事：用户把一个 OC 放进已建好的世界观，AI 生成 OC 面对的挑战与可选决策；用户选择（或自由输入）后，AI 生成后果与下一个挑战，循环直到抵达用户预设的结局，或用户认为可以收尾的节点。可以随时回退到任意之前的挑战，走另一条世界线。

**与语 C／酒馆类应用的差异化（产品定位，必须体现在设计里）**：互动体验本身是目的，但每条世界线都能**沉淀为小说的大纲与细纲，再润色成正式章节**，并接入现有的写作链路（大纲树、章节编辑器、摘要链、外传、导出）。互动产生的是结构化的叙事资产，不是一次性的聊天记录。

## 1. 用户已确认的决策

1. **定位**：互动是目的；可以从一条世界线生成大纲与细纲，最终润色成小说。
2. **每一步篇幅**：像游戏，每步是几百字的情节，加一个挑战和 2–4 个选项。
3. **失败**：允许坏结局，包括 OC 死亡、任务失败。坏结局会结束这条世界线，但必须支持回退。
4. **分支与主线**：
   - 分支树是唯一的真实存储。主线和外传都只是树上的路径。外传只存分叉点之后的部分，同时记录它从哪个节点分叉。
   - **主线始终跟随最新的那条世界线**（「最新」的确切含义是决策点，见 §3）。
   - **在同一节点选过的选项不能再选**：在节点 1 选了 a，回退到节点 1 时 a 不可再选（显示为已走过）。但用户可以随时切换到之前选 a 的那条世界线，查看或继续它生成的后续节点。
   - 回退时，原来的线完整保留，成为外传线。
5. **新事实只记在所属世界线上**，不写回全局知识库。知识库本身要新增**世界线**结构，见 §2。
6. **决策方式**：可以从 AI 给的选项里选，也可以自由输入行动，两种都支持。

## 2. 知识库分层：世界观 → 世界线（用户要求具体规划，下面是推荐方案，设计可以修正，但要说明理由）

### 2.1 三层

| 层                               | 内容                                                                                                                                                                                                                                | 作用范围                                                   | 谁来改                       |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------- |
| **世界观（底层规则）**           | 现有的知识库条目：世界规则、人物原始设定、势力、地点等                                                                                                                                                                              | 所有世界线共享                                             | 作者，或经提案确认           |
| **世界线（变化 / 新增）**        | 在某个推演节点上，因为选择而产生的差异，包括：条目字段被覆盖（如某人物「身份」变为叛徒）、只在这条线存在的新条目（如新结识的人物）、条目状态变化（死亡、失踪、被毁）、OC 状态（伤势、能力、持有物、关系、已知秘密）、事件记录与标记 | 从该节点起，**沿树向下继承**到所有后代节点；兄弟分支看不到 | 每一步的 AI 产出，记在节点上 |
| **有效知识（计算出来，不存储）** | 节点 N 处的知识 = 世界观条目（通用的 + 作用范围包含 N 所在线的）+ 从根到 N 沿路逐个叠加的世界线差异                                                                                                                                 | 只读                                                       | —                            |

### 2.2 世界观条目上的新属性（推荐）

- **作用范围**：
  - `通用`：默认值，所有世界线都可见；
  - `限定世界线`：只在指定的世界线或推演里存在，例如作者预设「只有走入某个分支才会出现的隐藏人物」。
- **可变性**：
  - `底层（锁定）`：世界线不能覆盖。例如世界规则的「运作规则」「限制与代价」；AI 产出的差异若试图改它，必须拒绝或丢弃，并提示。
  - `可变`：世界线可以覆盖。例如人物的身份、关系、状态。
  - 设计要决定：可变性按条目设置，还是按字段设置（推荐按字段，并给分类模板定默认值。世界观设定类的规则字段默认锁定，人物的状态和关系字段默认可变）。
- **提升为通用**：某条世界线上的新增或变化，作者认为应该成为全书事实时，可以「提升为世界观」。提升必须走现有提案管道，由作者确认。

### 2.3 和现有功能的关系

- 现有的「仅作为世界观设定」导入、反向提取、写作规范、风格档案、核心设定等，继续作用于世界观层。
- 写作规范（作用范围）要新增「互动推演」项，推演的每一步都要遵守规范。「按规范检查」可以考虑支持检查推演节点（决策点）。
- 原作同人场景（参见写作规范里的「时间截面」）：本期不做「原作事件表」，但数据模型不能阻碍以后加。

## 3. 决策点（设计必须给出推荐）

1. **「主线跟随最新」的定义**：「最新」是最近创建的叶子，还是最近推进（用户最后一次做决策）的那条路径？切换到旧的 a 线并在上面继续推进时，主线要不要随之切过去？推荐：主线 = 最近一次推进所在的路径，切换后只要一推进，主线就跟过去；在 UI 上明确标出当前主线。还要给出「主线换了」时大纲和章节的处理方式（见 §5）。
2. **「选过的选项不能再选」与自由输入**：
   - 每个节点保存 AI 生成的原始选项（回退时不重新生成），走过的选项标为已走过。
   - 自由输入的行动，如果和已走过的选项本质相同，怎么判定？可选做法：轻量的 AI 判定（额外成本），文本相似度，或只做精确匹配加提示。设计给出推荐。
   - 一个节点所有选项都走过了，是否允许「再生成一批新选项」？
3. **每一步的生成内容与结构化 schema**，至少包含：
   - 情节正文（几百字）；
   - 挑战描述；
   - 2–4 个选项，可以带「风险提示」或「倾向」标签，但不能剧透结果；
   - 世界线差异；
   - 离结局或里程碑的进展；
   - 是否触发结局（好、坏、中性）。
   - 自由输入的行动不合理时（凭空获得能力、违反底层规则）怎么处理：推荐让 AI 按世界规则写出「尝试与后果」，而不是直接拒绝，同时不能违反锁定规则。
4. **导演层（让故事收得回来）**：
   - 开局设定：OC（引用一条人物条目，或新建）、起点（时间、地点、处境）、结局目标（可以有多个，例如真结局和若干坏结局）、可选的里程碑、基调和节奏（预计步数）。
   - 每一步注入当前进度与下一个里程碑。
   - 「收尾」按钮：根据当前状态写出结局。
   - 如何避免「越走越散」和「为了到达结局强行转折」，设计要给出具体的 prompt 策略。
5. **上下文与成本**：
   - 每一步注入：稳定前缀（作品信息、风格、写作规范、锁定的世界规则、OC 原始设定），以及易变尾部（有效世界线状态、最近若干步的原文、更早步骤的摘要、导演提示）。
   - 路径很长时，早期步骤怎么压缩（参考摘要链，按路径滚动摘要；摘要也要按节点存放、沿路继承）。
   - 严格遵守产品文档第 9 节的缓存策略。回退不重新生成。不预生成未选的分支。
6. **差异的确认流程**：产品原则 5.1 要求 AI 结构化产出必须经确认才落库。但每一步都弹提案会毁掉游戏节奏。推荐：
   - 世界线差异自动记在节点上，只在推演的沙盒层，不碰世界观层；
   - 在节点上随时可以查看和编辑；
   - 只有「提升为世界观」和「沉淀为大纲、章节」时才走提案或预览确认。
   - 设计必须论证这样做为什么不违反 5.1，并在产品文档里写明。
7. **沉淀为小说（差异化核心）**：
   - 从一条路径生成**大纲**（卷、章两层，写入现有大纲树）和**细纲**（每章梗概、关键事件、出场人物、关联条目）。生成结果走现有提案管道确认。
   - 再通过现有的「写这一章」整章生成，把章节润色成正式正文。推演原文和世界线状态作为额外上下文注入。正文仍是可编辑预览，确认后采用。
   - 主线路径沉淀到主线大纲和章节；外传路径沉淀为外传（使用现有 SideStory），并且外传要记住分叉点。生成上下文时，自动接上共用的前半段，但不重复导出前半段。
   - 主线切换后，已经沉淀的大纲和章节怎么办（保留、标记过期、提示重建）？设计给出推荐。
8. **外传与分叉**：现有 SideStory 是独立的章节序列。需要扩展：可以关联到某个推演和分叉节点，生成外传章节时的上下文要包含分叉点之前共用路径的摘要。数据模型变化需要 Dexie 升级（当前是 v6），备份快照也要升级，并兼容旧备份。
9. **多 OC、分支流程图**：本期不做。但数据模型要允许以后加多 OC。移动端的分支导航本期用列表或面包屑形式，不做图形化的树。

## 4. 第一期范围

- 新增「互动推演」入口。建议放在主导航或写作页，设计决定，并同步改产品文档第 7 节的信息架构。每本书可以有多个推演。
- 开局设定（§3.4）。
- 推演循环：每一步的情节、挑战、选项，或者自由输入；流式显示情节；结构化解析，失败时自动修复重试；截断检测（复用 finishReason === 'length'）。
- 世界线差异的记录、继承、查看和编辑；节点处的有效知识视图。
- 回退到任意节点，从那里分叉；走过的选项不能再选；切换到其他世界线的任意节点。
- 列表或面包屑形式的世界线导航，移动端和桌面端都要认真做。
- 结局判定（好、坏、中性），坏结局后提示回退；「收尾」。
- 世界观条目上的作用范围和可变性属性（§2.2），以及「提升为世界观」（走提案）。
- 从路径沉淀大纲和细纲（提案），并接入整章生成；主线进主线，外传进外传，外传记住分叉点。
- 写作规范新增「互动推演」作用范围。
- 断点续玩：刷新或关掉页面后，推演状态完整保留（IndexedDB）。

**范围外（第二期）**：图形化分支流程图、原作事件表、多 OC、跨推演的世界线合并、「按规范检查」推演节点（可选，设计判断成本，低成本可以纳入）。

## 5. 产品原则与工程约束

- 必读：`docs/产品文档.md`（特别是第 5、9 节）、`docs/设计方案.md`、`docs/世界观写作指南.md`。
- 中文注释，写明「为什么」。单套响应式 DOM，移动端和桌面端都是第一等公民。
- 新增 task profile（例如 `interactive-step`、`interactive-ending`、`path-to-outline`）。参数要说明：推演属于创作类，但输出是结构化的，开不开思维链、温度设多少，设计要给出取舍。
- 没有任何推演时，现有写作链路的 prompt 必须和改动前**逐字节一致**。参照写作规范功能做过的 noNormsBaseline 测试做法。
- 验证：`npm run build`，以及 `npx vitest --run`（当前 62 个文件、1443 个测试全部通过，必须保持全绿）。
- 测试至少覆盖：
  - 世界线差异沿树继承，兄弟分支互相隔离；
  - 锁定字段不能被覆盖；
  - 已走过的选项被禁用，切换到旧线后能继续推进；
  - 主线跟随规则；
  - 回退不发请求；
  - 坏结局后回退；
  - 沉淀大纲走提案；
  - 外传记录分叉点；
  - Dexie 升级与旧备份兼容；
  - 没有推演时 prompt 零变化；
  - 推演 UI 的主要流程（用 renderWithProviders 和 stub fetch）。
- 范围外文件：不需要改的现有功能不要动。
- 项目不是 git 仓库，直接在原目录改，不需要 worktree。
