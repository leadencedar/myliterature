# 长文自动分段翻译实现需求规格

## Summary

本任务要把「文墨」现有的导入翻译和章节编辑器单章翻译统一改为可恢复、可验证的自动章内分段翻译。目标是阻止模型输出上限、缺失 `finish_reason`、SSE 干净断流、损坏尾帧或模型漏译尾部造成的残缺译文被当作成功，并保证已经付费完成的分段不会因关闭面板、离开章节、刷新、二分重试、迟到响应或多标签页竞争而丢失。

长章节仍是一个产品章节，不因翻译切分而改变章节结构。系统在章节内部按 Markdown 和 Unicode 安全边界建立稳定计划，按顺序调用模型，每段通过轻量流式 envelope 和本地完整性校验后立即写入 IndexedDB。只有全部有效叶子段都成功，系统才拼出完整译文。导入链路随后原子替换导入草稿；章节编辑器则只进入现有的可编辑预览，作者明确采用前不得修改章节正文。

### 术语

- **源章**：一次导入草稿或章节编辑器启动翻译时的完整原文快照。
- **初始段**：首次按默认预算切出的源段。
- **有效叶子段**：没有被继续二分、参与最终拼接的段；被二分的父段不属于有效叶子段。
- **已验证段**：模型输出已通过本需求全部完整性校验，并且成功持久化为当前合法尝试结果的段。
- **受保护 token**：不能被翻译输出丢失或破坏的 Markdown 结构、围栏/行内代码、URL、模板占位符、显式数字编号等内容。
- **use-source**：导入时作者明确选择整章使用完整原文。它不是某个失败段的局部跳过。
- **活跃编辑器任务**：尚未采用或放弃的章节翻译任务，包括暂停、失败待处理、完整译文待预览和 stale 状态。
- **额外自动调用**：超出每个可翻译初始段一次基础调用的自动重试或二分子段调用。

### 已从源码与测试核实的现状

1. 当前技术栈实际为 React 19.3、TypeScript 7、Vite 8、Dexie 4、Zod 4、Vitest 5、Tailwind 4 和 Zustand 5；应用纯前端运行。`package.json` 没有可直接复用的分词或 Markdown 解析依赖。
2. 当前 Dexie 架构版本为 v7，备份格式为 v4。`RepositorySnapshot` 已包含进行中的 `importJobs`，但没有章节编辑器翻译任务实体。
3. 当前 `ImportScreen.translateOne` 把整份 `ImportDraft.content` 一次发送给 `runStream('translate-chapter')`。它只拒绝 `finishReason === 'length'` 和空译文；通过后一次性把整章译文写入 `content`、把整章原文写入 `sourceContent` 并标为 `done`。
4. 当前 `TranslateSheet` 同样把编辑器里的整章正文一次发送。它连 `finishReason === 'length'` 都不检查，运行状态和结果只在 React state 中；关闭面板、离开章节或刷新都会丢失进度。
5. 当前 `useLlm.runStream` 不接受或下发 `maxTokens`，虽然 `ChatRequest` 与 `OpenAiCompatibleClient` 已支持 `max_tokens`。本任务不能依靠调大该值证明输出完整。
6. 当前 SSE 解析器在流正常 EOF 时直接结束，不向业务层报告是否看到 `[DONE]`；损坏 JSON 帧会被静默忽略。因此 `finishReason: null`、正常 EOF 或后续无异常都不是完整性证明。
7. 当前 `parseTranslation` 允许没有 `---译名表---` 分隔符的输出，且没有源单元 ID、唯一结束标记、长度比例、受保护 token 或接缝重复校验。
8. 当前 `ImportDraft` 没有 `translationPlan`。`ImportJob` 由 `&novelId` 保证一部作品最多一个导入任务；现有 `patchImportDrafts` 只按章合并，尚无 `jobId/sourceHash/segmentId/attemptId/lease` 级保护。
9. 当前 `Chapter` 只有正文、原文留底和语种字段，没有翻译任务或分段进度。`updateChapter` 会重算字数，章节编辑器采用译文时把当时可见正文写入 `sourceContent`。
10. 当前世界观提交会清空 `ImportJob.drafts`，只保留由 `draft.content` 打包出的提取段。因此完整原文在世界观提取仍未结束时已不可恢复，这与本任务的新约束冲突。
11. 当前编辑器只有“采用译文”和“放弃”动作，没有翻译专用的“追加到正文末尾”动作。验收矩阵明确要求“采用”路径；本任务不据“采用/追加”措辞自行新增翻译追加按钮。
12. 当前编辑器只在最终采用整章译文时才合并译名；本任务要求成功段的译名 outbox 在下一段开始前按序同步，因此该时机将被新要求覆盖。
13. 已实际执行 `npm run build`，退出码为 0；已实际执行 `npx vitest --run`，结果为 75 个测试文件、1719 个测试全部通过。构建只有既有的大 chunk 警告。

### 冲突处理与范围判定

- 调查报告原先建议把章节编辑器完整分段后置；`decisions.md` 和本任务明确覆盖该建议。本期 **MUST** 同时完成导入与章节编辑器的完整分段、持久化和恢复，不得只补 `finishReason` 判断。
- 既有“导入目的地后置 + 外传”设计采用“超长提示 + 单次整章翻译”；本任务以自动章内分段取代该临时方案。不得继续把手工重新分章作为主要恢复手段。
- 既有导入阶段表要求世界观阶段清空 `drafts`；本任务要求世界观原文在翻译和提取全过程可恢复。后续设计必须调整内部承载方式，同时保持世界观零 `Chapter`。
- 导入计划仍放在 `ImportDraft.translationPlan` 内，不因该嵌套字段单独升级 Dexie。章节编辑器任务如何持久化是后续设计必须比较并锁定的架构决策，见 FR-7.12。

### 明确假设与尚待设计锁定的事项

1. “约 3000 Unicode 字符”和 4000 hard cap 是人类可见字符预算；无论最终采用 code point 还是 grapheme 计数，切点 **MUST NOT** 落在 grapheme 内部，且验收以不拆 grapheme、原文可逐字重建为准。精确计数口径由设计锁定。
2. 长度比例异常默认按验证失败处理。设计可以提供显式人工确认，但没有人工确认时 **MUST NOT** 自动成功。
3. “成功段实际采用”指该尝试成为当前段已持久化的合法 `done` 结果，而不是仅收到流式文本，也不是等待作者最终采用整章。其译名可进入作品级 outbox；失败、过期或未获胜尝试不得进入。已经幂等合并到作品级译名表的条目在放弃任务时不回滚。
4. 编辑器任务恢复保证生成的分段译文与状态不丢；作者在最终预览中尚未采用的手工编辑是否跨关闭保存，不属于本任务强制范围。
5. 编辑器 stale 任务一旦成立即保持 stale；即使正文后来碰巧恢复成同一文本，也必须由作者丢弃并重建，不能自动重新激活。
6. 同一作品不同章节可以各自保留未完成的编辑器翻译任务；本任务只规定同一章节最多一个活跃任务，不新增全书级互斥限制。
7. 世界观原文只需保留到该次导入提取完成或作者放弃任务；任务正常结束后可以随 `ImportJob` 删除，本期不建永久素材库。
8. 具体 lease 时长、续租间隔和网络重试退避毫秒数由设计锁定，但必须是有限值并满足本需求的并发与恢复行为。

## Functional Requirements

### FR-1 共享自动分段能力与启动规则

1. 导入翻译与章节编辑器单章翻译 **MUST** 使用同一套切分、envelope、校验、重试/二分、持久化和译名同步语义；可以有不同的任务容器和 UI 接线，但不得形成两套完整性规则。
2. 两条链路 **MUST NOT** 再把超过单段预算的长章节作为一次整章请求发送。短章节可以自然形成一个初始段并只调用一次。
3. 导入翻译仍 **MUST** 由作者明确点击开始，不得因进入翻译页、恢复任务或创建计划而自动产生模型费用。编辑器翻译同样只在作者启动或明确继续后调用。
4. 在任何首个模型请求前，系统 **MUST** 先持久化源章快照、SHA-256 source hash、稳定分段计划和任务身份。刷新后不得按新常量重新切已存在的计划。
5. 每章各段 **MUST** 按源文顺序调度，不主动并行。后段不得在前段译名 outbox 完成对账前启动。

### FR-2 无损切分规则

1. 每个普通可翻译初始段的目标大小 **MUST** 约为 3000 个 Unicode 字符，hard cap **MUST** 为 4000 个 Unicode 字符，并同时满足 `estimateTokens(sourceText) <= 1200`；任一限制先到即切。
2. 切分 **MUST** 按以下优先级寻找安全边界：Markdown 块或空行；单换行；句界；分号/冒号/逗号/邻近空格；最后才是 grapheme 边界。
3. 切分前后 **MUST** 保留全部原始偏移、换行和空白；不得先 `trim`、合并空行或标准化换行。全部有效源范围按顺序拼接后必须逐字符等于源章。
4. 切分 **MUST NOT** 拆开代理对、emoji ZWJ 序列、组合附加符或其他 grapheme cluster。
5. 三个及以上反引号或波浪号形成的 fenced code block **MUST** 作为 Markdown 原子块识别；未闭合围栏覆盖到文件末尾。代码围栏及内部内容 **MUST** verbatim 原样通过且不调用模型。
6. ATX 标题行与 Setext 标题两行 **MUST NOT** 在内部切开；列表项、引用行、表格行的行首结构标记 **MUST** 保持完整。
7. 超过 hard cap 的单个 verbatim 代码块 **MUST** 原样通过。超过 hard cap 且无法安全拆分的单个标题原子块 **MUST** 暂停并提示人工处理，不能按 UTF-16 下标静默硬切或超限发送。
8. 无标点、无空格的超长自然语言串 **MUST** 在 grapheme 边界切开。
9. 二分失败段时 **MUST** 复用同一安全边界优先级，在该失败段中点附近切；不得重算整章或改变其他段的 ID、范围与完成结果。
10. 被二分父段的两个子树范围并集 **MUST** 精确等于父段范围；父段变为非拼接状态，不能与子段重复计入进度或最终译文。

### FR-3 章内上下文与缓存稳定性

1. 每个可翻译段的请求 **MUST** 包含作品信息与文风、当前章标题和段位置、当前源文命中的最新作品级译名。
2. 除当前段外，请求 **MUST** 提供目标长度为 200–300 字的上一段原文尾与译文尾、目标长度为 120–200 字的下一段原文头；相邻内容短于目标长度时使用其完整可用文本，缺少相邻段时省略相应块。
3. 章内第一段 **MUST** 在有可用数据时沿用同一叙事线的上一章译文尾；主线和不同外传之间不得串用。没有可用上一章译文时应省略，而非伪造。
4. 参考内容 **MUST** 放在明确的“仅供衔接、不得输出”区块中，且不得获得当前请求允许输出的 source unit ID。
5. 系统提示的翻译规则和 envelope 规则 **MUST** 在同一配置下逐字节稳定；nonce、unit ID、相邻参考和当前正文等易变数据 **MUST** 位于用户提示的易变后缀。
6. 模型重复输出参考块时 **MUST** 视为未知 ID、重复接缝或其他验证失败；系统 **MUST NOT** 猜测并自动删掉疑似重复文字，因为原文可能有有意复沓。

### FR-4 轻量流式 envelope 与完整性校验

1. 每一次实际模型尝试 **MUST** 生成新的不可预测 nonce，并绑定当前 `jobId/sourceHash/segmentId/attemptId`。nonce 必须在当前源文和参考块中唯一。
2. 当前段内的 source units **MUST** 有稳定 ID；同一源段重试时 unit ID 保持不变，attempt nonce 改变。
3. 模型输出协议 **MUST** 至少包含：每个 unit 的开始控制行、该 unit 译文、unit 结束控制行、译名区、唯一整段完成控制行。控制行必须独占一行并包含本次 nonce。
4. parser **MUST** 只把与本次 nonce 精确匹配的控制行识别为协议，保存前必须剥离全部控制信息和完成标记。任何协议标记 **MUST NOT** 出现在持久化译文、预览或最终章节正文中。
5. 一个 translatable 段只有同时满足下列条件才可成为 `done`：
   - 响应译文和每个非空 translatable unit 的译文均非空；
   - `finishReason !== 'length'`；
   - 唯一完成标记恰好出现一次，且标记后只有空白；
   - 所有预期 unit ID 恰好出现一次，顺序与源文一致；没有缺失、重复、错序或未知 ID；
   - verbatim unit 与源文逐字符一致；
   - 受保护 token 的值、数量和必要顺序未丢失或损坏；
   - 长度比例检查通过，或作者在有该能力时明确确认；
   - 与前一已完成段的接缝没有异常重复。
6. `finishReason` 为 `stop`、`null` 或未知值只能作为诊断信息，**MUST NOT** 代替 envelope 完整性校验。SSE 是否看到 `[DONE]` 也不得代替唯一完成标记。
7. 对 `estimateTokens(source) >= 200` 的长自然语言段，译文估算 token 少于源文 30% 或高于源文 300% 时 **MUST NOT** 静默成功；默认进入验证失败。短文本不应用该比例作质量判断。
8. 相邻译段规范化空白后，如后一段开头与前一段结尾存在 40 个或以上连续重复字符，**MUST** 判为可疑接缝并阻止自动成功。
9. 所有有效叶子段都为已验证 `done`、所有 verbatim 内容已原样就绪、且不存在 running/failed/review-required 段时，系统才可按源范围顺序拼接完整译文。请求完成顺序不得决定拼接顺序。
10. 未验证、被截断、过期、失去 lease 或持久化失败的输出 **MUST NOT** 写入正式 `translatedText`，不得参与整章拼接、更新上一段译文尾或产出 glossary outbox。

### FR-5 重试、二分、暂停与成本上限

1. `finishReason === 'length'` 时 **MUST** 跳过同尺寸重试并立即只二分失败源段；若已达到二分或最小段限制，则暂停等待作者。
2. 完成标记、unit frame、受保护 token、长度或接缝等格式/内容校验失败时，系统 **MUST** 先对同一源段作一次带严格提醒的同尺寸重试；第二次仍失败才二分该段。
3. 网络错误、HTTP 429 和 HTTP 5xx **MUST** 对同一源段自动重试一次并采用有限短退避；再次失败后标记该段失败并暂停。
4. 鉴权错误、余额不足、配置错误、HTTP 400/422 等请求配置错误 **MUST NOT** 自动重试；系统应立即暂停并显示可操作原因。
5. 用户关闭/卸载造成的 abort **MUST** 使当前段回到可继续状态，不得标为 `done` 或 `failed`，也不得消耗一个已完成段。
6. 每个初始段自动二分深度 **MUST NOT** 超过 2 层；自动生成的可翻译叶子段 **MUST NOT** 小于 500 grapheme。
7. 在一次作者授权的自动运行批次内，单个初始段的整棵自动尝试树 **MUST NOT** 超过 7 次自动模型调用；每章额外自动调用 **MUST NOT** 超过 6 次。所有限制同时生效，以最先达到者为准。
8. 达到任一成本上限时系统 **MUST** 停止自动请求、持久化当前状态，并要求作者明确决定是否继续、重试、整章使用原文（导入）或放弃任务（编辑器）。明确人工继续可以授权新的调用，但累计实际次数不得被清零或隐藏。
9. 一次失败、重试或二分 **MUST NOT** 重新调用已完成段。第 2 段失败时，请求体中不得再次包含第 1 段作为待翻译正文；第 1 段只能作为有限参考尾部出现。
10. “暂停” **MUST** 在当前小段完成并落盘后停止，不启动下一段，并显示正在停在当前段结束处；关闭面板、离开章节或组件卸载则 **MUST** 立即 abort 当前段。
11. 存储失败时，系统 **MUST** 保留当前内存中可见结果但不得标 `done`，必须停止后续调用并提示存储空间/备份建议。只有结果成功持久化后才可继续。

### FR-6 译名 outbox、顺序与幂等

1. 只有通过全部完整性校验且成功赢得当前 attempt 的段，其译名才可随译文一起持久化。失败、截断、取消、过期和迟到尝试中的译名 **MUST** 丢弃。
2. 系统 **MUST** 先持久化段译文与该段译名 outbox，再把 outbox 合并到作品级 glossary，最后把该 outbox 标为已应用。
3. 未应用 outbox **MUST** 严格按源文顺序对账；后段先完成时可以保存其结果，但不得抢先取得作品级“先到先得”优先级。
4. 下一段请求开始前，所有更早已完成段的 outbox **MUST** 已幂等合并。合并失败时应显示“译文已保存、译名待同步”含义的状态并暂停，不得带旧词表继续。
5. 进程在“作品级 glossary 已合并、outbox 尚未标记”之间中断时，恢复后 **MUST** 安全重放而不产生重复或覆盖作者译名。
6. 作品级 glossary 继续遵守现有领域规则：原文名忽略大小写和首尾空白；模型译名先到先得；作者显式修改拥有最高优先级。
7. 每段开始前 **MUST** 读取包含已对账结果的最新 glossary，并只注入当前源段相关条目。

### FR-7 持久化、最小写入与并发不变量

1. `ImportDraft.translationPlan` **MUST** 是可空、带默认值的嵌套字段；缺失时解析结果为 `null`。它必须包含重建源章和恢复进度所需的 source hash、稳定段/单元、译文、译名 outbox、状态、调用计数和时间/尝试身份信息。
2. 编辑器任务 **MUST** 保存完整源文快照及其 hash、全部稳定 segments、成功译文、glossary outbox、任务/段状态和必要时间信息。仅保存 hash 而无法在采用时留底原文不合格。
3. 同一计划的有效叶子源范围 **MUST** 无重叠、无空洞，按序能逐字符重建源章；`split` 父段不得参与最终拼接。
4. `done` 段 **MUST** 对旧尝试不可变：过期响应不得改写、降级或清空它。两个标签完成不同段时两份结果都必须保留；竞争同一段时只有一个当前合法 attempt 可以获胜。
5. 翻译相关仓储操作 **MUST** 以 `job/draft/segment/attempt` 为最小更新单元，在同一事务内读取数据库最新行后合并。组件 **MUST NOT** 把内存中的整份 `drafts` 或整份 `segments` 覆盖回库。
6. 每次 claim、完成、失败、abort 释放、二分、outbox 对账、整章 finalize 和 use-source 变更 **MUST** 校验适用的 `jobId/sourceHash/segmentId/attemptId/lease`。任务已删除、已替换、source hash 不同、segment 已分裂或 attempt 不再持有 lease 时必须返回“未采用”且不写数据。
7. 二分 **MUST** 原子完成父段转 `split`、两个子段创建和计划 revision 更新；整章 finalize **MUST** 在事务中重读全部有效叶子并重新校验后再写最终状态。
8. lease **MUST** 有明确所有者和有限过期时间。未过期 lease 由另一标签持有时，本标签页不得重复调用；lease 过期后可以重新 claim，但原持有者的迟到响应必须因 attempt/lease 不匹配而被拒。
9. 关闭或卸载时 **MUST** 使当前 attempt 失效并尽力释放 lease；即使 abort 太迟或释放写入失败，迟到响应也不得写成成功，最终可由 lease 过期恢复。
10. 导入任务删除并创建新任务后，旧任务响应即使命中同一作品、同一 draft index 或相同文本，也 **MUST NOT** 写入新任务或污染 glossary。
11. 一个章节最多只能存在一个活跃编辑器翻译任务；该不变量 **MUST** 在存储层抵御多标签并发创建，不能只靠按钮禁用。删除章节或作品时不得留下悬空任务。
12. 后续设计 **MUST** 对以下编辑器持久化方案逐项比较并选择一个：独立 `ChapterTranslationJob` 表（首选基线）、把临时计划嵌入 `Chapter`、复用 `ImportJob`。比较至少覆盖一章一个活跃任务、不同章节任务共存、导入任务不冲突、最小事务写、stale、lease、级联删除、备份和恢复。若不选独立表，设计必须证明所有安全性质同等成立，不能只以改动少为理由。

#### FR-7A 状态机不变量

下列名称是需求层的概念状态，设计可以采用不同字段名，但允许的行为和终态约束不得改变。

| 对象           | 允许的状态/迁移                                                                                                                                   | 不变量                                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 可翻译叶子段   | `pending → running → done`；`running → pending`（abort 或合法回收）；`running → failed`；`running/failed → split`；`failed → running`（作者重试） | `running` 必须有当前 attempt 与 lease；只有完整性校验和持久化都成功才能进 `done`；`done` 不可降级或被另一 attempt 改写；`split` 是父段终态，只能由子段参与拼接。                                             |
| verbatim 段    | `pending → done`，不经过模型                                                                                                                      | `done` 文本必须逐字符等于源范围，不计模型调用。                                                                                                                                                              |
| 导入章翻译决策 | 无计划/`active`/`paused`/`failed` → 完整 `done`；任一未提交状态 → `use-source`；`use-source → active` 仅限选择目的地前                            | `done` 只由全部有效叶子成功后的原子 finalize 产生；`use-source` 始终解析为完整原文，不能代表局部跳过。                                                                                                       |
| 编辑器任务     | `active/paused/failed → completed-preview`；任一未结束状态 → `stale`；`completed-preview → applied`；任一活跃状态 → `abandoned`                   | `completed-preview` 之前正文不变；`applied` 必须通过 source hash 事务检查；`stale` 不可回到 active、completed-preview 或 applied，只能查看/复制、放弃或丢弃重建；`applied/abandoned` 后旧 attempt 全部失效。 |
| 过期 running   | lease 到期后可由新 attempt 重新 claim                                                                                                             | 新 claim 必须替换 attempt 身份；旧 attempt 即使返回完整输出也不得改变任何状态。                                                                                                                              |

任何恢复逻辑 **MUST** 把数据库中的状态映射回上述状态机，不得通过“页面重新打开”隐式把 `done` 变成 `pending`、把 `stale` 重新激活，或把 `running` 直接当成功。

### FR-8 导入链路语义

1. 新建翻译计划后，在部分翻译、失败、暂停和二分期间，`ImportDraft.content` **MUST** 始终是完整原文，`sourceContent` 不得提前写成部分内容，也不得把已译段与未译段拼成中外文混排正文。
2. 只有全部有效叶子成功后，仓储 **MUST** 在一个事务内设置：`sourceContent = 完整原文`、`content = 按源范围拼接的完整译文`、`translateStatus = done`、错误清空。事务失败时草稿仍保持完整原文和可恢复段进度。
3. 当前 v7 旧 draft-phase job 不做 Dexie 行迁移：没有 plan 的旧 `done` 草稿视为已完成且不得重译；旧 `pending/failed` 草稿在作者继续时根据当前完整 `content` 懒创建计划；缺 plan 且正文仍为外文的 `none` 草稿必须要求作者明确翻译或 use-source，不能把旧 `none` 默认为新式明确跳过。
4. 已进入旧版 main/worldview 提取阶段且已无原始 drafts 的遗留任务继续沿用既有安全恢复说明；不得伪造无法恢复的翻译计划或删除已写章节。
5. 作者在任一段失败或预算耗尽时可以选择整章 use-source。确认后该章最终只能使用完整原文，已经完成的中文段不得混入最终内容。
6. use-source 决定及已完成分段 **MUST** 持久化到任务。在选择目的地之前，作者可以撤销 use-source 并从首个未完成有效叶子继续，完成段不得重译。
7. 仓储层的主线、外传和世界观 destination commit **MUST** 重读并拒绝任何 unresolved 外文章节。每个外文章节必须是完整 `done`，或有作者明确记录的整章 use-source；UI 按钮状态不能是唯一防线。
8. destination commit 被拒时 **MUST** 原子回滚，不得写入部分章节、清空计划或推进任务阶段。
9. 主线和外传提交后，完整翻译章的 `Chapter.content` **MUST** 是完整拼接译文，`Chapter.sourceContent` **MUST** 是完整源章；语种和字数继续遵守既有语义，外传的 `sideStoryId` 与线内编号规则不变。
10. use-source 章提交主线或外传时，`Chapter.content` **MUST** 是完整原文，`sourceContent` **MUST** 保持未翻译章节的既有空值语义。
11. 世界观目的地在草稿、翻译、提交、提取、失败恢复和收尾全过程 **MUST NOT** 创建或修改任何 `Chapter`。提取只能读取完整译文或明确选择的完整原文。
12. 世界观源章完整原文 **MUST** 在翻译和提取尚未完成期间保留于可恢复的导入任务数据中；刷新、失败或暂停后仍能取回。提取完成并删除任务后无需永久保存。
13. 纯中文、无需翻译的导入路径 **MUST NOT** 创建 `translationPlan`、claim lease 或发送翻译请求；步骤、调用次数、目的地行为及提取 prompt 必须与改动前逐字节/行为一致。
14. `resumeStepOf` 或等价恢复逻辑 **MUST** 识别 plan 内未完成叶子、失败段、use-source、过期 running lease 和完整待提交状态；恢复不得仅查看旧章级 `translateStatus`。

### FR-9 章节编辑器语义

1. 作者启动单章翻译时，任务源章 **MUST** 是当时编辑器中可见的完整正文，包括尚在防抖保存窗口内的修改。创建任务不得修改 `Chapter.content/sourceContent/sourceLanguage`。
2. 关闭 `TranslateSheet`、关闭章节编辑器、切换章节或刷新后，任务和全部已完成段 **MUST** 可恢复；继续时从最早未完成有效叶子开始，不得重复调用完成段。
3. 全部有效叶子成功前 **MUST NOT** 进入可采用的完整译文预览。运行中可以展示当前段流式文本，但该文本不具备采用资格。
4. 全部有效叶子成功后 **MUST** 把完整拼接译文放入现有可编辑预览。关闭并重新打开时至少必须恢复由已持久化段生成的完整译文，且不再调用模型。
5. 作者明确点击“采用译文”前，章节正文、原文留底、语种、字数和章节状态 **MUST** 保持不变。仅查看、复制或编辑预览都不得写正文。
6. 采用时仓储 **MUST** 在事务中再次确认当前任务、完整状态和 `Chapter.content` 的 source hash，然后一次性写入作者编辑后的完整预览、把启动任务时的完整源章按既有语义写入 `sourceContent`、写入原文语种，并结束该任务。任何一步失败不得留下半应用状态。
7. 若本章已经译过，重新翻译仍遵守现有语义：任务基于当前可见正文，采用后该正文成为新的 `sourceContent`；本任务不改变既有撤销、字数和保存行为。
8. 任务存在期间，只要章节正文因本标签自动保存、其他标签页或其他写入发生变化，系统 **MUST** 把任务标为 sticky stale、停止后续自动翻译，并禁止采用旧译文覆盖或追加到新正文。
9. stale 任务 **MUST** 允许查看和复制已完成译文，并提供“丢弃后按当前正文重建”与“放弃任务”；重建必须先删除旧任务且受 job/attempt 身份保护。stale 任务不得继续翻译剩余旧源段。
10. “关闭面板”与“放弃任务” **MUST** 是不同动作。关闭只 abort 当前段并保留已付费进度；放弃必须二次确认，并明确说明所有已保存分段译文/进度会删除且无法恢复。
11. 放弃、采用或重建后，任何旧请求的迟到响应 **MUST NOT** 重建任务、覆盖正文或合并其译名。
12. 当前源码没有翻译“追加”按钮，因此本期强制验收“采用译文”。如果实现复用了带“追加”动作的既有预览组件，则追加也必须显式点击、只在完整且非 stale 时可用，并受同一 source hash 事务保护；本任务不要求新增该动作。

### FR-10 可观察 UI 与错误恢复

1. 导入页和章节编辑器翻译面板 **MUST** 同时显示：章级进度、当前章的有效叶子段完成数/总数、当前段、已完成源字符/源章总字符、预计基础调用数、因二分增加的调用数；动态二分后数字必须更新。
2. 每段详情至少 **MUST** 可观察其待处理、运行、完成、失败或被拆分后的当前状态，以及实际尝试次数和可操作错误；`split` 父段不计入当前总段数。
3. 两条链路 **MUST** 提供暂停、继续和重试失败段。导入额外提供整章使用原文及提交前撤销；编辑器额外提供放弃任务。
4. 另一标签页持有未过期 lease 时 **MUST** 明确显示“另一标签页正在处理”的含义，本页不得静默等待或重复请求；lease 释放/过期后允许重读继续。
5. 预算耗尽、stale、鉴权、余额、配置、网络、验证失败和存储失败 **MUST** 有可区分且可操作的界面状态。诊断可显示 finish reason、段号和失败种类，但不得显示 API Key。
6. 导入页 **MUST NOT** 再用“长章将作为单次翻译、请手工重新分章”作为正常方案说明；应说明系统会自动分段、完成段会保存、失败只处理当前源段及额外调用受限。
7. 所有新增控件 **MUST** 在同一套响应式 DOM 中工作，沿用现有 `Sheet`、按钮、确认框、`role="alert"/"note"` 和焦点语义，不得按屏幕宽度渲染两套功能树。

### FR-11 迁移、备份与文档

1. 仅给 `ImportDraft` 增加默认可空嵌套 plan **MUST NOT** 触发对旧 `ImportJob` 行的 Dexie 数据迁移；兼容由 schema 默认值与懒初始化承担。
2. 若设计选择独立 `ChapterTranslationJob` 表，Dexie **MUST** 从 v7 精确升级到 v8，迁移应为加表/索引及必要安全默认，不得修改既有章节正文；v7 数据升级后所有旧表仍可读。若选择其他方案，不得为本任务凭空增加 v8，且必须满足 FR-7.12 的同等安全证明。
3. 不论编辑器任务最终存放何处，备份格式 **MUST** 从 v4 升到 v5，并完整包含进行中的导入 translation plans、编辑器任务、成功段、outbox、状态和必要身份信息。
4. v5 备份导入前 **MUST** 校验引用完整性和状态不变量，至少包括编辑器任务指向存在且同属一部作品的章节、同章最多一个活跃任务、source snapshot/hash/段范围一致，以及导入计划可重建源章。失败时整份拒绝，什么都不写。
5. 当前应用 **MUST** 继续读取 v1–v4 备份并为新增字段补安全默认；v5 必须往返保留进行中付费进度。版本高于 5 的文件必须在解析未知正文前按文件头明确拒绝。
6. 覆盖恢复和合并导入都 **MUST NOT** 产生同章多个活跃任务或悬空任务；遇到无法无损决定保留哪一个的冲突必须在写入前拒绝，而不是静默丢弃已付费进度。
7. 本期 **MUST NOT** 为原作脉络、Facet 子设定或 OC 母版预建表、字段、索引或备份槽位。
8. 实现完成后 **MUST** 同步 `docs/产品文档.md`、`docs/使用说明.md`、`docs/设计方案.md`、`docs/开发计划.md`，准确说明导入与编辑器都自动分段、完整性协议、失败恢复、成本上限、原文保留、stale 与备份版本；开发计划中的测试数字必须写实际执行结果。

## Non-Functional Requirements

1. **NFR-1 技术栈锁定**：实现 **MUST** 保持 React 19 + TypeScript + Vite + Dexie + Zod 4 + Vitest + Tailwind 的纯前端架构，**MUST NOT** 新增依赖、后端服务或对运行中开发服务器的依赖。
2. **NFR-2 数据安全优先**：任何不确定输出必须失败关闭。宁可暂停并要求作者处理，也 **MUST NOT** 把未验证文本、旧响应或部分译文标为完成。
3. **NFR-3 原子性与可恢复性**：所有会改变任务身份、段树、整章最终内容、use-source 决定或应用编辑器译文的操作 **MUST** 具备事务原子性；刷新后观察到的状态必须是操作前或操作后之一。
4. **NFR-4 成本可控**：调度必须顺序执行、只重试失败源段、遵守自动调用上限，并向作者显示成本增长。不得为了“验证完整”默认再调用第二个模型做逐句审校或回译。
5. **NFR-5 缓存稳定**：稳定 prompt 前缀必须确定性排序且逐字节可复现；新增请求身份和邻接上下文只能放在易变后缀。无需翻译路径和未改动的现有 prompt 必须保持逐字节兼容。
6. **NFR-6 本地与隐私**：任务、源文、译文和诊断只按既有本地数据与用户配置的模型端点处理；备份继续不含 API Key，错误信息不得泄露密钥。
7. **NFR-7 响应式与可访问性**：移动端和桌面端必须共用单套 DOM；进度、错误、lease、stale 和确认状态须可由文本与语义属性感知，不能只依赖颜色。
8. **NFR-8 回归门槛**：`npm run build` 必须退出 0；`npx vitest --run` 必须保持当前 75 个文件/1719 个既有测试全部通过，并通过本需求新增测试。与翻译无关的互动推演行为不得改变。

## Acceptance Criteria

下列编号项组成最低验收矩阵。测试可以分布在纯函数、schema、仓储和 React 集成层，但每项断言必须自动化；涉及真实 IndexedDB 事务语义的项至少使用现有 fake-indexeddb 仓储集成测试，不能全部用组件 mock 代替。

| 编号      | 场景与可验收结果                                                                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **AC-01** | 对 20k+、无章节标题的英文输入，外层 `splitChapters` 仍得到一章，翻译计划自动得到多个稳定初始段；普通可翻译段满足目标/hard cap/token 约束，序列化恢复后 ID 与范围不变，全部源范围拼回逐字符等于输入。                                 |
| **AC-02** | 对超长自然语言单段，切分依次验证空行/行/句界/标点或空格/grapheme 回退；无任何标点空格时仍不拆 emoji、代理对、ZWJ 或组合字符。                                                                                                        |
| **AC-03** | fenced code、未闭合 fenced code、ATX/Setext 标题、列表、引用和表格结构均按规则处理；代码块逐字符出现在最终结果且模型调用中没有代码块源文。超长不可拆标题暂停而非超限调用。                                                           |
| **AC-04** | 合法 envelope 在流式分块跨控制行边界时仍能解析；所有 unit 按源序得到译文，控制行、nonce 和完成标记不会进入持久化文本。                                                                                                               |
| **AC-05** | 预期 unit ID 缺失、重复、错序或出现未知 ID 时全部拒绝，段状态不为 `done`，也没有正式译文/outbox。                                                                                                                                    |
| **AC-06** | 完成标记缺失、重复、被翻译/改写、出现在正文中造成重复，或标记后还有非空白内容时全部拒绝。SSE 无 `[DONE]` 但干净 EOF、尾帧损坏被忽略、`finishReason` 为 `stop/null` 时，也不能绕过该拒绝。                                            |
| **AC-07** | `finishReason='length'` 时不作同尺寸重试，立即只二分该失败段；已完成段的 ID、译文、次数和 outbox 均不变。                                                                                                                            |
| **AC-08** | 完成标记或 frame 格式错误且未命中 `length` 时，同尺寸严格重试恰好一次；再次失败只二分该源段。                                                                                                                                        |
| **AC-09** | 空响应、任一非空 unit 的空译文、受保护 Markdown/行内代码/URL/模板占位符/显式编号丢失或损坏时，段不得成功。                                                                                                                           |

## Out of Scope

1. **MUST NOT** 实现同人/改编的原作脉络层、原作事件表或为其预留存储结构。
2. **MUST NOT** 实现 Facet 子设定层、复杂能力按条件启用的结构化子设定，或为其预留表/字段。
3. **MUST NOT** 实现 OC 母版、多作品共享 OC 或相关迁移。
4. **MUST NOT** 修改与翻译无关的互动推演生成、世界线、回退、沉淀或提升逻辑。
5. 不新增世界观导入原文的永久素材库；提取任务结束后不提供历史素材管理、查看或删除 UI。
6. 不做多段并行翻译。并发保护只用于抵御多标签、迟到响应和恢复竞态。
7. 不做完整 JSON 字符串包裹的长译文协议、第二模型逐句审校、回译验证或默认语义对齐复检。
8. 不做按 provider/model 跨任务学习输出上限，不要求新增模型最大输出能力配置；`max_tokens` 即使后续作为辅助也不能替代本需求校验。
9. 不提供用户拖动分段边界、逐段手工编辑译文或段级混合采用。
10. 不新增通用翻译方向；目标仍固定为把外文稿译成简体中文。
11. 不新增翻译专用“追加到正文”按钮；若既有共享预览天然提供该动作，只需满足 FR-9.12 的安全约束。
12. 不重构与本任务无关的数据库表、导入提取、外传、摘要链、导出、写作规范、计划或设置功能。
