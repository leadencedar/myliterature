# 需求文档 · 写作规范

> 另见需求补充 `/Users/leadencedar/Production/Project/MyLiterature/.agents/tasks/writing-norms/requirements-addendum.md`：「按规范检查本章」本期必须实现（覆盖原 brief 第 7 条的默认）。下文已并入该补充；两者冲突时以补充文件为准。

## 1. 概述

用户原话：「这是整理出的写作规范，希望网站能够通过导入类似的写作规范约束作品的写作。」

示例是两份同人资料包配套文件（文档 02《背景脉络与同人使用说明》、文档 03《来源与核对边界》）。它们既不是世界观条目，也不是文风：它们是**作品级的创作约束与项目说明**，回答的是「这本书选择发生什么、哪些信息现在不可用、提取和续写时守什么规矩」。文档 02 原话：世界观条目告诉模型「这个世界能发生什么」，项目说明告诉它「这本同人选择发生什么」。

本期给每部作品加上「写作规范」：作者在知识库新建、粘贴或上传规范文档，原文直接保存；之后的 AI 生成与提取按每份规范勾选的作用范围，把它放进提示词的稳定前缀。

## 2. 用户故事

- **US1 建规范**：作为作者，我想把整理好的规范文档粘贴或上传（.txt / .md）到作品里，保存后原样留存，不被 AI 改写。
- **US2 管理**：我想在知识库里看到本作所有规范，能编辑、删除、启用或停用、调整先后顺序，手机和电脑上都能顺手操作。
- **US3 作用范围**：我想给每份规范选择它约束哪些 AI 任务（写正文 / 规划大纲与立项 / 章节摘要 / 提取设定），比如一份只管提取规则的规范不必进正文生成。
- **US4 看得见、可临时去掉**：整章生成前，我想在「本次注入」里看到哪几份规范进了提示词、各占多少 token，并能只在这一次取消某一份。
- **US5 控制成本**：规范很长时（例如以来源链接表为主的文档 03），我想看到 token 估算和提醒，并能让 AI 把它精简成可执行的约束条目。精简结果由我看过、改过、确认后才保存为新规范，原文保留。
- **US6 差异说明模板**：做同人或改编时，我想一键插入一份通用的「本作差异说明」模板，按格式填写开场时期、分叉点、不可用资源等。
- **US7 提取也守规矩**：导入旧稿做反向提取时，我想让模型遵守规范里的提取规则，比如阶段性称号不新增成人物、组织不因名字相近合并、保留「原作未明确」这类限定。
- **US8 备份带走**：备份文件里要有我的规范，旧备份照常能恢复。
- **US9 按规范检查本章**：写完一章后，我想让 AI 按我的规范审读，列出可能违反之处（哪条规范、正文哪一句、为什么、怎么改、严重程度），我能定位到原文、逐条忽略，或按建议走段落改写；AI 不会自己改我的正文。

## 3. 功能需求

### 3.1 数据

- FR1 每部作品可以有 0 到多份写作规范。每份有：标题、正文、启用开关、作用范围（多选）、排序。
- FR2 作者写的、粘贴的、上传的正文**原样保存**，不经过 AI、不进提案管道。上传文件只做与旧稿导入相同的编码探测、换行统一和 BOM 清理。
- FR3 删除作品时级联删除它的规范。

### 3.2 知识库页入口

- FR4 知识库页在「风格档案」之后新增「写作规范」区块：列出规范（标题、启用状态、作用范围、token 估算），提供新建、从文件新建、编辑、启用/停用、上移/下移。删除放在编辑面板里，需二次确认。
- FR5 编辑面板：标题、正文（可粘贴）、上传文件（追加到正文）、插入「本作差异说明」模板、作用范围多选、启用开关、实时 token 估算、超阈值与链接过多的提示、AI 精简入口。
- FR6 不在「导入旧稿 → 导入到」里加「作为写作规范」目的地。

### 3.3 注入

- FR7 启用、且作用范围包含当前任务的规范，按排序注入该任务的系统提示词稳定前缀；任务与作用范围的对应：

| 作用范围 | 覆盖的任务                                                        |
| -------- | ----------------------------------------------------------------- |
| 写正文   | 整章生成（chapter-draft）、段落续写/改写/扩写（paragraph-revise） |
| 规划     | 一句话立项（project-setup）、细化大纲（outline-expand）           |
| 章节摘要 | 章节摘要（chapter-summary）                                       |
| 提取设定 | 旧稿与世界观反向提取（extract-settings）                          |
| 检查     | 按规范检查本章（norm-check，新增）                                |

- FR8 翻译、文风取样、从稿件归纳文风、连通性测试不注入规范。
- FR9 新建规范默认启用，作用范围默认全选。
- FR10 整章生成面板的「本次注入」清单列出注入的每份规范及其 token 估算；面板里可以临时取消某份规范，只影响这一次生成，不改库里的启用状态。段落加工面板提供同样的临时取消。

### 3.4 成本控制

- FR11 编辑面板与列表显示每份规范的 token 估算（`estimateTokens`）。单份超过阈值、或启用中的「写正文」规范合计超过阈值时给出提示；正文里链接很多时提示「来源表通常不必进提示词」。
- FR12 AI 精简：对已保存的规范生成精简版，结果是可编辑预览；作者点「另存为新规范」后才写库：新规范插在原规范之后、沿用作用范围并启用，原规范自动停用但原文不变。放弃则什么都不写。

### 3.4b 按规范检查本章（需求补充）

- FR15 章节编辑器（主线与外传章节）提供「按规范检查」入口，窄屏与宽屏都可用。
- FR16 用作用范围含「检查」的启用规范 + 本章正文（另带核心设定、本章提到的条目、上一章摘要）调用模型，结构化输出每条：规范标题、规范原文片段、正文原句片段、问题说明、可选修改建议、严重程度（明确违反 / 可能违反 / 需作者判断）。
- FR17 只提示、不改正文。每条可定位到原文（能找到时）、可忽略、可「按建议改写」——后者打开现有段落加工，经可编辑预览由作者确认写入。
- FR18 没有可用于检查的规范、未配置模型、正文为空时入口禁用并说明原因。
- FR19 长章节分段检查并事先告知调用次数；任何一段输出被截断（finishReason 为 length）或失败，整次检查报错，不展示不完整结果。
- FR20 检查结果只保存在编辑器会话内；正文在检查后改过时提示结果可能过期。

### 3.5 备份

- FR13 备份快照包含写作规范；备份文件版本号升级；v1、v2 旧备份照常能恢复，恢复后没有规范。

### 3.6 文档

- FR14 更新 `docs/产品文档.md`（6.2 写作规范、6.3 按规范检查本章及「为什么只提示不自动改」、7 信息架构、9 注入顺序，含「世界观条目 vs 项目说明」的区别）、`docs/使用说明.md`、`docs/世界观写作指南.md`（新小节 + 第 8 节提示词补一句）。

## 4. 非功能需求

- NFR1 **无规范时零变化**：作品没有任何规范（或全部停用、或都不在当前任务的作用范围内）时，所有任务的系统提示与用户提示与改动前逐字节一致；「本次注入」清单的条目和 token 合计也不变。
- NFR2 **缓存前缀稳定**：规范块放在稳定前缀里（作品信息与风格档案之后、核心设定之前），渲染不含时间戳、token 数等易变内容；同样的输入两次构建逐字节一致；外传章节与主线章节共用同一份含规范的稳定前缀。
- NFR3 **原文直接落库**：保存路径不调用模型、不 trim 正文、不创建提案。
- NFR4 **AI 精简须确认**：精简结果在作者点击保存前不写任何数据；保存是单个事务（新建与停用原文同成同败）。
- NFR5 **升级安全**：Dexie 升到 v6 只新增表，不改动已有表的数据；从 v5 库打开后原有数据完整。
- NFR6 **备份兼容**：旧版本应用读到新备份时明确提示「来自更新版本」，不会静默丢掉规范。
- NFR7 **两端第一等公民**：单套 DOM + CSS 断点；排序用按钮不用拖拽；窄屏用底部抽屉，宽屏用右侧抽屉；触控目标不小于 44px；控件有可读的无障碍名称。
- NFR8 验证：`npm run build` 与 `npx vitest --run` 全绿；现有关于提示词的断言一条不改。

## 5. 验收标准

**数据与仓储**

1. 新建规范后，`listWritingNorms` 返回的 `content` 与输入逐字符相同（含首尾空白、Markdown 标记与空行）；`enabled` 为 true，作用范围为五项全选，`order` 排在已有规范之后。
2. 修改标题、正文、启用、作用范围都能保存；改不存在的规范报错「这份写作规范已不存在」；`id` / `novelId` / `createdAt` 不能通过修改被改动。
3. 调整顺序后列表按新顺序返回；传入的 id 集合与库里不一致时拒绝并不改动任何一行。
4. 删除规范后列表里没有它；删除作品后它的规范全部消失。
5. 一个只声明到 v5 的旧库，用新代码打开后版本为 6，作品、章节、外传、译名表数据不变，规范表为空且可写入。

**备份** 6. 新导出的备份 `version` 为 3，`data.writingNorms` 含全部规范；导出再导入后规范逐字段相同。7. v1、v2 备份可以覆盖恢复和合并导入，恢复后没有规范、其他数据照旧。8. version 为 4 的文件报「来自更新版本」。规范标题为空、正文为空或作用范围含未知值的备份被拒，错误信息给出路径。

**注入** 9. 一份启用、作用范围含「写正文」的规范出现在整章生成和段落加工的系统提示里，位置在作品信息与风格档案之后、核心设定之前；停用的、或作用范围不含「写正文」的不出现。10. 多份规范按排序注入，与传入数组的顺序无关；同一输入两次构建，`stablePrefix` 与 `volatileSuffix` 逐字节相同。11. 「本次注入」清单出现「写作规范 · {标题}」条目和 token 数；在面板里取消它之后，发出的请求系统提示里没有它，库里这份规范仍为启用。12. 没有规范、规范全部停用、或都不在作用范围内时，整章生成、段落加工、章节摘要、反向提取、细化大纲、一句话立项的系统提示，与改动前的基线输出逐字节相同（用基线采集的字面量断言）。13. 作用范围含「提取设定」时，导入旧稿逐章提取与世界观逐段提取的请求系统提示都带上规范，并带一句「规范本身不是待提取的正文」；不含时不带。14. 作用范围含「规划」时，一句话立项与细化大纲的系统提示带上规范；含「章节摘要」时章节摘要的系统提示带上规范。15. 翻译请求不带任何规范。16. 外传章节与主线章节生成时的 `stablePrefix` 相同（规范块在两者之间共享）。

**知识库页 UI** 17. 知识库页能新建规范：填标题、粘贴正文、保存，列表里出现它，库里的正文与粘贴内容逐字相同。18. 能从 `.md` 文件新建：选文件后编辑面板预填标题（文件名去扩展名）和正文，显示识别出的编码；保存后入库。`.docx` 被拒并提示另存为 .txt。超过单份上限的文件被拒。19. 能编辑、停用、上移/下移、删除（删除前有确认框，取消则不删）。20. 点「插入差异说明模板」后正文里出现通用模板，空标题时自动填「本作差异说明」；模板里没有任何特定作品的专有名词。21. 单份规范超过阈值时编辑面板显示提示；正文里链接超过 5 个时显示「来源表通常不必进提示词」提示。22. AI 精简：点「AI 精简」后结果出现在可编辑预览里，此时库里规范数量不变；点「另存为新规范」后，新规范排在原规范之后且启用，原规范停用、正文不变；点「放弃」后库里无变化。模型调用失败时显示错误，库里无变化。23. 新建、编辑面板在窄屏是底部抽屉、宽屏是右侧抽屉（沿用 `Sheet`）；页面上每个控件只渲染一份。

**按规范检查本章** 24. 有启用、作用范围含「检查」的规范时，检查请求的系统提示含该规范，用户提示含本章正文；停用或作用范围不含「检查」的规范不出现。25. 模型返回的条目逐条渲染（规范标题、规范原文、正文原句、说明、建议、严重程度）；点「定位」后正文选中对应原句；点「忽略」后该条不再显示。26. 「按建议改写」打开段落加工面板（操作为改写、额外要求预填建议）；作者确认前正文不变。27. 没有可用于检查的规范、或未配置模型时入口禁用，点击能看到原因，且不发请求。28. 响应 finishReason 为 length 时显示截断错误，不显示任何结果。长章分段时任一段失败整次失败。29. 整个检查流程前后，章节正文（库里与编辑器里）逐字相同。30. 外传章节同样可以检查。

**端到端** 31. 用一份根据文档 02 第 4 节要点自拟的通用夹具（不含任何原作事实）：建规范 → 整章生成请求带上它 → 导入旧稿提取请求带上它 → 取消勾选后整章生成请求不带它。

## 6. 范围外

- 结构化的「本作当前时期 / 分叉点 / 当前不可用资源」字段（本期只做自由文本 + 模板）。
- 检查结果持久化（按章保存、跨会话保留）；检查后自动修改正文。
- 「导入到 → 作为写作规范」的导入目的地。
- 规范的回收站、版本历史；多部作品共享同一份规范。
- 翻译、文风取样、文风归纳注入规范。
- 修改 `src/features/settings/DiagnosticsSection.tsx`、`src/app/store/diagnostics.ts`、`src/app/store/useActiveNovel.ts`。

## 7. 假设

- A1「整章生成、段落加工必须注入」理解为这两个任务必须接入规范注入；单份规范仍可由作者取消「写正文」作用范围（比如只管提取规则的规范）。默认全选，所以不做任何设置时它们一定会注入。
- A2 风格档案里已有的「额外写作要求」（`StyleProfile.extraInstruction`，≤ 2000 字，进【文风】段）保留不动。它管的是句式语感层面的短句约束；写作规范管作品级的长文约束，二者并存，不做迁移。
- A3 规范属于作者自己的内容，与「一句话立项」里作者写的那句话同理（`SetupSection.tsx` 注释：「一句话是用户自己写的，不属于 AI 产出，直接落库」），不受产品原则 5.1 的提案约束。
