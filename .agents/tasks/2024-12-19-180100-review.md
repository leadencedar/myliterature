# 导入类型选择：章节 vs 世界观设定（第二轮）

用户导入旧稿时可以选择将内容作为章节（分章、翻译、提取、生成摘要）或作为世界观设定（只提取知识库条目，不创建章节、不生成摘要、不归纳文风）。第一轮评审后修复了四个问题：在 useEffect 中添加孤儿临时章节清理逻辑、在 finalize() 中为 rollingSummary 提案生成添加 importType 判断、保留 withSummaries 和 importType 的双重条件检查作为防御性编程。

## 第一轮评审问题修复验证

### 临时章节清理的容错性（已修复）

在加载 ImportJob 的 useEffect 中添加了孤儿临时章节清理逻辑：

```typescript
// 清理孤儿临时章节：如果上次世界观导入异常中断,临时章节会留在数据库中
try {
  const allChapters = await repository.listChapters(novel.id);
  const orphanedTempChapters = allChapters.filter((chapter) => chapter.index === -1);
  for (const chapter of orphanedTempChapters) {
    await repository.deleteChapter(chapter.id);
  }
} catch {
  // 清理失败不应阻塞导入流程
}
```

**验证结果（confirmed）**：逻辑位于 ImportJob 加载后、设置 step 之前，每次进入导入流程都会清理。catch 块捕获异常不阻塞正常流程。

### rollingSummary 更新行为（已修复）

在 `finalize()` 中生成全书进展摘要提案前添加了 `importType` 判断：

```typescript
// 世界观模式不应更新全书进展摘要（设定文本不是故事的一部分）
if (
  current.importType !== 'worldview' &&
  current.rollingSummary.trim() &&
  current.rollingSummary.trim() !== novel.rollingSummary.trim()
) {
  proposals.push(
    buildReplaceProposal({
      // ... 全书进展摘要提案
    }),
  );
}
```

**验证结果（confirmed）**：世界观模式下即使提取过程中更新了 rollingSummary，也不会生成替换提案。

### withSummaries 和 importType 双重条件（保持现状）

`extractOne()` 中保留了双重条件检查：

```typescript
if (latest?.importType !== 'worldview' && latest?.withSummaries !== false) {
  await repository.createProposals([
    buildCreateProposal({
      // ... 摘要提案构建逻辑
    }),
  ]);
}
```

**设计决策（confirmed）**：第一个条件是模式检查（世界观模式强制跳过），第二个条件是功能开关（章节模式下用户可能关闭摘要生成）。双重检查为将来章节模式的摘要开关提供灵活性。
