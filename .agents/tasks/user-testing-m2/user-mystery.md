# 用户测试报告 · 悬疑/推理作者

## 1. 我是谁

悬疑/推理作者，豆瓣阅读连载；周更 2 章，单章 3000–5000 字。最在意伏笔公平、线索可回溯、时间线硬度。我先有案件事实表再排章，最怕系统替我决定埋什么、哪条算数。

## 2. 按新功能走一遍

- **细化大纲**：只当场景卡骨架，会用；卷上「写这一章」跳过。
- **写这一章**：会犹豫；过场可生成，盘问/搜证/揭底不用。
- **归档/查看**：会用，但逐条核；看不到伏笔流水不采用。
- **继续补写/下一章**：补写跳过；下一章仍自己排线索。

## 3. 问题清单

- **P0 归档只给伏笔余额，不给流水**：m2-02 摘要卡只有「3 项新增」，resolvedThreads 不显示、无从改回；误判一次，坑消失。期望「新埋/收束/现存」，收束项可勾回。
- **P1 未收束伏笔够全，线索不够**：summary 120 字、keyEvents 3–6 条、openThreads；物证/时间点不算伏笔也不进 300 字进展，默认只带 3 章，第 5 章的缺口第 9 章看不见；openThreads 是累计值，3 章摘要各带一份，已收束的还挂旧摘要，面板只列 token。期望加「线索/物证（首现章）」，伏笔只取最新一份。
- **P1 龙套建条目、与摘要捆绑**：m2-02「人物 · 船夫」「茶博士（新增）」都进「采用本批（4）」。推理里龙套可能是嫌疑人/证人，AI 写的身份动机会被当事实注入后续。期望默认不建；若建，标「一次性出场」不进注入，批量拆成摘要/设定。
- **P1 继续补写不告诉我缺哪场**：m2-08 只有「比目标少约 2342 字」，续写指令只有差额；哪些场景未落地、能否揭底全由模型定。期望先列未落地场景卡供勾选，并继承「只埋不揭」。

## 4. 最想要 / 不要做

最想要：①「案卷」：线索/物证/时间线可 pin，标「读者已知/计划回收章」，按案卷注入；② 归档可审计：新埋/收束/现存，可回原文，误判可恢复。
不要做：不要自动判伏笔已收束、自动合并同名/别名——这是诡计本身。

## 5. 对 M3 自动大纲

会让它做：导入旧稿后回溯「案件事实表/时间线/已埋线索（带出处）」作待确认提案；前沿 3–5 章只出场景卡与「本章不揭」清单。
绝不接受：自定凶手/手法/动机；把没上纸的线索当「已埋」；自动收束伏笔或选红鲱鱼；自动合并同名/别名；让「下一章梗概」进当前章生成（已注入）。五类里我最怕 AI 替我推理：别人写错难看，我这里毁全书可推性。

## 6. 一句总评

适合：注入清单、截断留痕、非阻塞归档，愿留；不适合：没有「案卷」，伏笔账本不透明，只敢写非关键场。
