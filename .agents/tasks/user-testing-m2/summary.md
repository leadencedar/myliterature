# 用户测试汇总：M1+M2（5 位差异化作者）

## 1 五类作者的共识

**真有用**：①场景卡细化让细纲"能直接开写"（男/女/悬疑 3 位会用；文学称"四问接近我的写法"）；②标记完成后台归档不弹窗、不抢焦点，5/5 认可"不打断收工"，是 M2 最大成功；③截断二次确认+编辑器留痕（女频：安心）；④目标来源/场景数可见、摘要自动接下一章。

**共同负担**：①待确认数字口径不一，"已生成"被读成已入库（男/女/文学）；②归档一键混合摘要/进展/龙套，无按批分组（男/文学/存量）；③继续补写按字数、不能选缺哪场（男/女/悬疑/存量）；④注入清单只给 token/人名，看不到人物字段、进展与未收束伏笔（女频/存量）。

## 2 分歧点

- **字数框架**：男频 6000/章（3–5 场）、存量 4000、女频 3000–4000、文学"默认不限、差额折叠"；统一默认 3000 只对部分成立。
- **场景卡结构化**：男频要场清单+爽点/钩子，悬疑要案卷/线索/时间线，女频要关系推进/谁知道什么，文学要可手改整段、反对硬指标→机制应"可读可改+可选附加行"，不做统一评分。
- **归档批次**：男频要全局按批/章分组；女频 4 条一键尚可；悬疑/文学要逐条核；存量要合并/替换默认不选。
- **自动大纲**：回溯范围（1:1 目录/关系线/案卷）未共识；共同底线=全提案、不写正文、不静默。

## 3 P0 / P1 / P2（按影响排序）

**P0**：①存量——"采用本批"默认全选且卡片折叠，新增/合并/替换同权，一键可能覆盖 40 万字旧库字段（user-veteran §3-3；ProposalReview.tsx:80 全选、ArchiveInboxSheet.tsx:37 默认折叠）。②悬疑——归档只给伏笔余额，无"新埋/收束/现存"流水，resolvedThreads 不可见、不可改回（user-mystery §3；archiveChapter 只合并 openThreads）。

**P1**：①状态行"N 条知识库更新待确认"只数条目，摘要/进展未计，与收件箱 4 项不符（男/女/文学；ChapterEditorScreen.tsx:746）。②注入清单只给 token/人名，人物字段、进展、未收束伏笔均不可见（女/存量；"人物·沈砚 N tokens"）。③继续补写仅"还差约 N 字"、不能选场（男/女/悬疑/存量；GenerateChapterSheet.tsx:52）。④龙套进批次且无身份/门槛（女/悬疑/存量；prompt 门槛 archiveChapter.ts:70，UI 未跟进）。⑤知识库全局收件箱不同批与大纲提案混列（男；KnowledgePage.tsx:118）。⑥截断留痕仅会话内，刷新即失（文学；incompleteDrafts 不落库，D7）。⑦导入作品无大纲只有"添加第一个节点"，细化无旧稿起点（存量 §3-1；WritingPage.tsx:290）。

**P2**：关联 chips 不像可点（女）；"名字提到"默认全选、取消仅本次（男）；进展提案"无变化"仍出卡无旧值（存量）；字数默认/差额话术（文学要"不限"）。

## 4 对 M3 自动大纲的联合建议

**做**：①导入回溯优先出 1:1 目录（节点=原章号、可预览改、带摘要/关联/伏笔，不改标题编号顺序）；②前沿只续 3–5 章，给"待确认方向/章节节点+3–5 场清单+引用设定与未收束伏笔"，作者只改钩子；③每章标钩子类型与"本章不揭"（悬疑）、关系推进/代价（女频）。

**不做**：写正文、落库、静默改状态；替作者定人物命运/情感走向/凶手手法；自动收束伏笔、合并同名别名、改旧设定与旧稿；按字数配额切章；把下一章梗概注入当前章生成。

## 5 一句话结论

M1+M2 对"已有粗纲、稳定日更、接受提案制"的男/女频连载作者最成立；严肃文学缺"声音锚点/可读可改的记忆"，悬疑缺"案卷式伏笔流水"，存量缺"1:1 回溯+合并只补不删"才敢交付旧稿。M3 先做 1:1 回溯骨架+前沿 3–5 章场景卡，暂缓多方向候选。
