# 女频言情/甜宠连载 · M1+M2 测试

## 1 我是谁
晋江女频甜宠日更，一章 3000–4000 字，章末留钩子；评论当天回。在意：主角口吻不漂、拉扯—心动—钩子节拍、收工别打断。

## 2 走一遍
- 细化：会用。场景卡能开写；单章字数要在提案里手改「约 2000 字」。
- 关联确认：会犹豫。双主角全选正好；chips 像标签、看不出可点，取消后果只有小字。
- 整章生成：会用。字数、场景数清楚；注入只有人名+token，看不到说话方式/关系网；截断+留痕安心。
- 标完成归档：会用。不弹窗、不抢焦点。
- 采用本批：会犹豫。4 条一键尚可；船夫/茶博士也进批次，折叠只写「5 项新增」。
- 补写/下一章：补写跳过（只从末尾续，说不出补哪拍）；下一章会用（摘要自动接上）。

## 3 问题
1. P1 人物字段不可见（生成本章/细化·本次注入）：只有「人物·沈砚 79 tokens」。期望展开见「说话方式、关系网」。
2. P1 龙套无可控门槛（归档收件箱；设置·归档提取条目）：船夫/茶博士也进「采用本批」，卡片无身份、无「这类别再建」。期望标出身份/再出场，并给「只建具名或会再出场角色」开关。
3. P1 补写不能指定节拍（未完成→继续补写）：指令含「还差约 N 字」易注水，高潮后续易泄。期望可填「补哪拍/停哪」。
4. P1 摘要「已生成」实为待确认（编辑器状态行；写作页说明写「确认后才会写入大纲」）：只报 2 条知识库更新，摘要/进展也待确认；不确认就写下一章，摘要链缺一章。期望计数含摘要，说明改「归档摘要与设定也在此确认」。
5. P2 关联面板五行小字；选中/取消像标签不像勾选，期望两行+勾。

## 4 最想要/不做
想要人物「声音卡」：生成时看到主角说话方式与当前关系，可加「这章推进到 X」；归档优先更新已有关系网（旧怨→同船暂盟），龙套不建条目。不做自动循环补写到目标字数。

## 5 M3 自动大纲
让它：导入 60 章旧稿回溯成节点，每章一句「关系变化/谁知道什么」，关系网变化做成分批确认的关系线提案；写到头时前沿续 3–5 章，每章写关系推进、代价、回收伏笔、钩子，标注会改哪些条目。绝不接受：①不确认就写/覆盖大纲与人物关系；②替我做情感走向；③凑章数硬拉男二与误会。

## 6 总评
适合：场景卡、收工不打断、摘要链贴连载；但我靠口吻与关系张力吃饭，看不到声音/关系被用上，不补就像生成器。
