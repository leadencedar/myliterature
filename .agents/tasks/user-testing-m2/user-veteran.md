# 存量旧稿/同人作者 · M1+M2 测试

1. 我是谁
40 万字，旧稿已导入，起点/同人双开，周更 2–3 章，单章 3500–4500 字，设定边写边补。最怕改错已有设定、带偏文风、重排覆盖旧稿。

2. 按新功能走一遍
细化：犹豫。导入的全书进展、伏笔和人物提及项能用；但旧稿无大纲要先手建卷，且清单只列设定，前两块看不见。写章：会用，清单/目标来源/场景数清楚，3000 默认不合我的 4000，会改。归档：会用，不弹窗只出状态行；3–5 章一批比逐章减负，险在一键合并。采用：犹豫，关联默认全选、每场重复同一对人物；新增/合并/替换同屏，一键怕改旧设定。补写/下一章：跳过，旧章已定稿，新章自己写，截断才补。

3. 问题清单
1 P0「采用本批（N）」默认全选、卡片折叠；展开可见原值，但新增/合并/替换同权，一键可能覆盖旧字段，对 40 万字旧库我不敢点。期望合并/替换默认不选，按钮标「含 N 条改动」。
2 P1 导入作品无大纲，M1 只能手工新建空节点再细化，结果与已写 40 万字没有结构对应；期望 M3「1:1 回溯目录」放在空大纲区。
3 P1「本次注入」只列核心/相关设定，不列实际也带的全书进展与未收束伏笔；0 条设定时整块消失，规则没 pin 也不提示，规范只给份数。期望清单补齐+空态。
4 P1 导入给「船夫/茶博士」建档，归档同名合并，多个船夫并成一人；期望职务名不建档或标「疑似同名」。
5 P2「全书进展摘要 替换」显示「1 项新增/无变化」且无旧值；期望并列旧值，无变化不出提案。

4. 最想要 2 条 / 不要做 1 条
想要：①1:1 回溯目录，节点=章、可预览改，逐章带摘要/关联/伏笔；②合并逐字段并列旧新值，默认只补不删。不做：重写/重排/合并已写章节，自动改库或状态。

5. 对 M3 自动大纲
生成：按原章号标题 1:1 建节点，标已写前沿，每章带条目/伏笔；前沿只出 3–5 章节点，不写正文。绝不接受：改标题/编号/顺序、并章或外传，重写摘要、覆盖设定、同名合并、静默落库、替写正文或改状态。

6. 一句总评
适合当「提案型助手」：M1 的设定清单敢用，M2 一键合并最不敢用；合并默认只补不删、回溯大纲 1:1 预览，我才敢交 40 万字。
