# M1+M2 用户测试团 · 共同测试说明

## 目的

找 5 类不同写作习惯的作者，各按自己的真实工作流「走一遍」文墨 M1（细化大纲/关联设定/整章生成/截断）与 M2（标记完成后台归档/批次确认/继续补写），回答三个问题：

1. 对你的写法来说，哪一步真的省事？哪一步会卡住、需要学、或让你不信任？
2. 哪些信息/默认值/确认量让你觉得是负担？
3. 对 M3「自动生成大纲（导入作品回溯 + 前沿续写 3–5 章）」的期待与边界。

## 材料（只读）

- `docs/使用说明.md` 5–6 节（写作/归档/摘要）
- `docs/产品文档.md` 6.3（大纲/生成/归档/继续补写）
- `.agents/tasks/outline-context-scene/ux/walkthrough.md`（M1 走查）+ `.agents/tasks/m2-chapter-archive/ux/literary-review-m2.md`（M2 顾问复核）
- 截图：`.agents/tasks/outline-context-scene/ux/shots/`（M1 `after-*`；M2 `m2-*`）
- 可读 `src/features/writing/` 与 `src/features/outline/` 中与文案/交互有关的代码（不必读实现细节）

**限制**：不要运行 `ux/run-demo.mjs`（会覆盖他人截图），不要改任何 feature/测试/文档；只写自己的报告文件。模型是 mock，**只评信息与流程，不评演示文笔**。

## 报告格式（≤700 字，中文）

1. **我是谁**：类型/平台/更新节奏/单章字数/最在意的三件事（3–4 句）。
2. **按新功能走一遍**：细化大纲 → 写这一章 → 标记完成归档 → 查看/采用 → 继续补写/下一章；每步一句话：会用/会犹豫/会跳过。
3. **问题清单**：≤5 条，标 P0（阻止使用）/P1（明显摩擦）/P2（打磨），写具体文案/位置/期望。
4. **最想要 2 条 / 不要做 1 条**。
5. **对 M3 自动大纲**：你会让它生成什么、绝不接受它做什么。
6. 一句总评：这套工具适不适合你这类作者，为什么。

## 产出

`.agents/tasks/user-testing-m2/user-<你的名字>.md`；完成后 send_message 给 lead 与 product-flow（product-flow 会汇总成用户测试报告）。
